### Decomposition decision

One task. The record is one file with one writer (`arch-scope4` CONTRACT "sole writer"); its
items are facts of one measurement session in one clone, so splitting would create a linear chain
on one file. The benchmark capture (Should) stays in the same task as the carrier fixes it there;
it stays deferrable because "not captured, and why" is a complete outcome for it: the Must items
never wait on a benchmark result.

### Local decisions (owned by this plan)

- **D-1 Clone.** `git clone --local --no-checkout <project root> <tmp>/repo`, then
  `git -C <tmp>/repo checkout --detach 96c9ad69aee983ce2b929dd681b6ba43bf920535`, with `<tmp>`
  a fresh directory under `/tmp`, outside `.worktrees/` (E2). Never push, fetch into, or create a
  branch in the project repository from the clone; delete the clone after measuring. No
  `make install` or binary replacement (E3).
- **D-2 Environment.** Every measurement command runs as
  `env -i HOME="$HOME" PATH="$PATH" TMPDIR=/tmp GOFLAGS=-count=1 <command>` (E4, G1.4,
  `arch-scope4` Protocol). The record shows `$HOME`/`$PATH` as those literal names, never their
  values (G1.4).
- **D-3 Sync-clean check.** In the clone: `make -C <tmp>/repo sync-embedded`, then
  `git -C <tmp>/repo status --short`. Recorded: both commands, the exit code, and the (empty)
  status output. A non-empty status is recorded as is and reported in the checkpoint; this task
  never commits a synced copy (`arch-e0`).
- **D-4 `make test` timing.** In the clone, after D-3: one warm-up `make -C <tmp>/repo test`
  (must exit 0; proves green), then one timed run of the same command, wall time taken from UTC
  start/end stamps (`date -u +%Y-%m-%dT%H:%M:%SZ`) or `/usr/bin/time -p`. One run took 360 s
  (P5), two together exceed the 600 s foreground cap: run them in the background and wait per
  `AGENT_TOOLS.md`. Recorded: protocol (D-1, D-2, warm-up then timed), both exit codes, timed
  wall seconds, start/end UTC, host (`uname -srm`, `nproc`, `uptime` load averages before the
  timed run), `go version`. A red warm-up is recorded and reported in the checkpoint; it is not
  retried into green.
- **D-5 Benchmarks.** For each package of the Q11 set (P7: `./internal/db/`,
  `./internal/commands/`, `./internal/agent/`), in the clone after D-4:
  `timeout 300 go test -run '^$' -bench . -benchmem <pkg>` under D-2. Recorded per benchmark
  function (eleven, P7): its result lines (ns/op, B/op, allocs/op and custom metrics; one line
  per sub-benchmark, P6), or "not captured" with the reason (failure output excerpt, or timeout).
  No retries, sleeps or added waits.
- **D-6 E0 resolution.** Recorded: D23 cited by heading (`dec-d23`), its ruling that the
  integration branch is `global-refactoring`, and the configured branch observed with
  `omni-ee -C <project root> get config --json` (`IntegrationBranch` value) with the UTC time
  of observation.
- **D-7 S1 counts.** A per-area table (A1–A9: offending files, offending functions) citing the
  Scope 1 start snapshot by path — `internal/testguard/archguard/s1_snapshot_test.go`
  (`startSnapshot`) and the per-area data files `area_a1_test.go` … `area_a9_test.go` — at the
  integration commit where Scope 1 merged, and naming that commit. Entries are cited, not
  copied (`arch-scope4`). The counts must equal the `arch-areas` column (totals 33 files,
  93 functions); a mismatch is recorded and reported in the checkpoint, not reconciled here.
- **D-8 Record layout.** `specs/architecture/consolidation-run/baseline.md`, sections in this
  order: Starting commit; E0 resolution; Sync-clean check; S1 counts; `make test` wall time
  (with Protocol, Host, Result); Benchmarks; Measurement provenance (clone path pattern, UTC
  window, and the statement that measurements ran at the starting commit before the record was
  written after Scope 1 merged). The Protocol subsection is written so a gate (G5) can repeat
  it verbatim. Paths of this repository appear only as repo-relative paths; the CLI name is
  quoted as invoked (historical artifact, G1.3).
