### Harness Reuse and AC1 Fallback

Reuse `oracle.RunMain`, `oracle.BuildCLI(t, "./cmd/liza")`, and `oracle.ChildEnv` for platform
environment construction. The delivered `Run` creates and immediately executes in an empty
project; it cannot receive the committed project fixture. Therefore this package prepares the
project and uses `os/exec` with the binary returned by `BuildCLI`. Each CLI case has independent
project/home/tmp directories, `cmd.Dir` set to its project and separate stdout/stderr buffers.
Use `exec.ExitError.ExitCode`; distinguish launch failures from ordinary nonzero CLI exits.
Share the one cached build across cases. No process-global `Chdir` or `Setenv` in parallel cases.

CLI environment: temp HOME/TMPDIR, minimal PATH containing no provider CLI, plus only PR's
`LIZA_AGENT_GENERATION=g1`. The portable base uses `ChildEnv`'s explicitly declared Windows
platform variables (D-14 of `harness-plan`), with no additional host inheritance. A fresh empty
directory is sufficient as CLI PATH here: no tested case needs an external executable. Build
and proof-tool children instead use the harness Go-toolchain policy with its cache locations
and tool PATH. Never dump environment values in failures. Assert allowed names and booleans.
Default-brand paths, command literals and generation variable are intentional default-brand
assertions under G1.3; there is no new presentation surface requiring a branded runtime change.

The delivered normalizer replaces all date-times, UUIDs and long hex strings, including fixed
fixture values. It has no selective switch. AC1 therefore allocates a small stdlib-only
comparator in `golden_test.go`, preserving the harness tree/kind and `ORACLE_WRITE` protocol.
Do not shield fixture values with invented replacements or edit the harness. It must:

- Normalize only registered disposable path prefixes, longest first, including resolved/symlink
  and slash/native forms and path-tail separators; never arbitrary fixture path values.
- Normalize AR's `**Analyzed:**` stamp only, leaving anomaly timestamps and every other fixed
  value intact. Do not sort human rows, arrays, state lines or report sections.
- For `human/usage-value.txt` only, normalize the non-nil address tokens in the stderr report's
  `PerCompletedTask`, `Provenance` and `SuppressedCalls` positions to stable, field-specific
  markers. P10 below verifies these process-dependent addresses; explicit dates alone do not
  make this format deterministic. Identify positions within the fixture's report structure,
  not by globally replacing hexadecimal strings. Preserve `<nil>` as distinct from a pointer,
  the surrounding fields and delimiters, and every token outside those positions. An unexpected
  report shape must fail naming this golden rather than broaden the match. Apply this step
  before human layout normalization, identically in live comparison and baseline generation;
  do not apply it to stdout, other usage formats or other surfaces. Production rendering and
  the harness remain untouched.
- Canonicalize JSON with `UseNumber`, sorted object keys, indentation and trailing newline;
  preserve codes, fields, numbers and array order. Human form strips ANSI/layout whitespace,
  retaining row/token order and the separate channel labels. State is a before/after pair
  preserving fixed timestamp text and identifiers. Record the CLI exit status in every golden,
  including the PR state pair and the AR report-file observation.
- Compare live observations to existing bytes; missing/mismatching files fail naming the
  relative golden path. Live mode never writes. `ORACLE_WRITE=1` writes only during entry-point
  regeneration in scratch. Generate and compare with the identical selective transformation.

`TestOracleCLIComparison` exercises fixed date-times (including offsets), UUIDs, long hex IDs,
numbers and array/row order surviving; only known paths, the report header and the allocated
usage-value pointer slots varying; repeated normalization idempotent. For usage-value, two
synthetic observations differing only in those three addresses must compare equal. Changing a
slot from a pointer to `<nil>`, a fixture date/number/identifier (including `0x`-prefixed hex
text outside a pointer slot), report field/token order, exit status, or stdout/stderr placement
must remain unequal. An unexpected report shape must fail explicitly. The same hex text in a
different surface must remain unchanged. These are AC-values assertions in command 0, within
the already allocated comparator test; they add no golden. Layout-only human changes compare
equal while changed content and channel placement do not. Use synthetic data in comparator
failure checks, never host values.
Comparator unit tests use their own temporary directory, never add synthetic goldens to the
package inventory. The inventory assertion runs only in live mode: entry-point generation
deletes scratch goldens before tests start, so it must not demand their presence before drivers
write them. The import boundary assertion still runs in both modes.

### Generation and Sensitivity Proof

After committing the drivers and fixed inputs, create absent goldens with the inherited entry
point (`harness-plan` D-13):

`env -i HOME="$HOME" PATH="$PATH" TMPDIR=/tmp go run ./internal/testhelpers/oracle/cmd/regen -mode write-new -pkg ./internal/oracle/a1/cli/...`

Verify its baseline is `96c9ad69aee983ce2b929dd681b6ba43bf920535` from the provider-owned ledger;
never write or amend that ledger. No direct write-mode run at HEAD is permitted. Commit the
generated goldens. The subsequent `check` command uses the same filter and must reproduce all
21. A missing/extra golden fails the exact inventory test. New golden paths are permanent.

`TestOracleCLITamper` skips unless `ORACLE_CLI_TAMPER=1`. Under that opt-in it uses one
disposable local clone of the committed candidate with history (no remote access), never this
repository's runtime state. It first proves unaltered live comparison and filtered entry-point
check both pass. For every one of the 21 files, independently change asserted content in that
clone, then require both live `go test` and real filtered `regen -mode check` to fail naming that
relative path. Restore the exact bytes before moving to the next file, including on failure;
clean up the clone. Corrupt a JSON value without breaking its syntax, a human token and the state
pair content; do not rely on layout-only edits. Require an actual comparison failure, not a
build/setup failure. No tamper child inherits the opt-in variable or ORACLE_WRITE; regeneration
alone supplies ORACLE_WRITE to its scratch tests. This prevents recursion.

The clone proof uses the CLI and entry point as delivered, not a fake regenerator. Caching its
test/regen executables is permissible but must not substitute a different production tree or
reuse stale observed output. Ordinary `make test` runs the normal oracle once, with tamper skipped;
the expensive 21-case sensitivity proof runs only in canonical command 2.
