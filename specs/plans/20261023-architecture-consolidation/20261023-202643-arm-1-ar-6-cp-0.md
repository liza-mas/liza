## Intent and decomposition

One Must coding task delivers the single package defined by `a6-decisions` D1.
The 24 inventory rows expand to 30 named cases. Requirements remain at `a6-scope`
and `a6-inventory`; this plan allocates files, exact case identifiers and proof.

Based on the resolved carrier, the pinned inventory read under operator decision D25,
the delivered harness sources, the starting-commit refusal sources and the probes below.
Software-architecture-review and testing were applied within the leaf-package boundary.
The ADR index and architectural-issues Update Policy/Open Issues Summary, merge-authority
and worktree-indexing entries were consulted; no new production architecture is decided.

The fixed-cost bundle shares a TestMain, one CLI build, a disposable-repository builder and
a determinism layer. A setup-only predecessor would serialize this same deliverable, and
no consumer needs a partial inventory. Keep family drivers in separate files for review;
estimated handwritten size is 1,000–1,600 lines plus generated goldens. The most consequential
review seam is W7's persisted failure delta versus the unchanged refusal fixtures.

freezing an interface. `BuildCLI`, `RunMain`, `ChildEnv`, `Normaliser`, `Check` and
`CheckState` exist. `ChildEnv` actually returns `([]string, error)`; handle that error.

executable inherited wait on its producer; A6 owns no provider correction.

### Driver construction and checks

1. Build committed fixture inputs into a fresh temporary Git project for each output mode,
   using repo-local identity and named commit/path token substitutions. Common inputs
   include a valid pipeline and state; family inputs define only their differences.
   Fixed historical/future timestamps follow `a6-scope`. No runtime `init`.
   W1 creates a committed post-worktree command and a fixture root Stacklit index;
   W3 omits that index. Keep other index gates disabled, no configured indexer languages,
   and no installed index script. Assert W1's command effect and copied index.
2. Use the harness-built CLI, a bounded `exec.CommandContext`, and `ChildEnv` with
   disposable HOME/TMPDIR, PATH, TZ and Git policy per `a6-scope`. Set only the identity
   and gates that each case needs. Every Git setup command gets this explicit environment
   too. Capture stdout, stderr and exit status separately. Do not print environment values.
   I1/I2 re-exec the test binary under that policy, dispatching to the integration adapter;
   the helper emits only its result and terminates before parent comparison.
3. The lock adapter holds the real runner file lock until the matching invocation finishes,
   then releases it in cleanup. Fixture records supply the simulated runner/batch; no
   detached runner, polling or sleeps. D7's success command is a deterministic passing
   local command, run synchronously by the operation. For merge and reconcile cases,
   assert no effective deferred command, installed index script, or runner directory/log.
4. R1 supplies a reusable synthetic input via `provision --record --file`, the sole
   permitted command-based input setup. Use a local command that prints the fixture token
   and exits 7; assert masked output and propagated exit 7. Never read real credential
   files or host secrets. R2 keeps a task without declared inputs.
5. Compare json wrappers and human transcripts as prescribed by `a6-scope`; each mutating
   human run uses a fresh equivalent fixture and its normalized final state must equal
   the json run's state golden. Retain content, error codes, row/token order and all
   state fields. Remove only stdlib-log-formatted lines and the explicitly allowed Git
   text; do not discard arbitrary stderr or error strings.

Apply the common Unix gate at every driver entry, before building the CLI or fixture.
Windows skips name the gate; Unix zone loading failure names `Etc/GMT-2`.
Helper processes receive TZ before Go initializes local time.

The determinism layer replaces instants with tokens such as `<TIME:+02:00>` and
`<TIME:Z>`, preserving offset class before harness normalization. Maintain per-fixture
SHA identity mapping shared across its output/before/after captures; register known commits
by name, assign other full SHAs in first-observation order. Tokenize only Git-produced
message portions, durations and PIDs; delegate paths and remaining supported identifiers to
the harness. Reset mappings for fresh equivalent runs so human/json state can compare.
Focused tests demonstrate different zones and distinct SHAs remain distinguishable after
the harness pass. These are support tests, not additional golden surface cases.
