## Mutation Guard Design (Task 3)

Mechanism (smallest proving one, stdlib only, K5): for each configuration GOOS ∈ {linux, darwin,
windows}, GOARCH=amd64, CGO_ENABLED=0, run `go list -e -export -deps -json` over `./cmd/...` and
`./internal/...`, type-check every module production package outside `internal/ops`,
`internal/db` and the existing `excludedDirs` with `go/types` from its `GoFiles`, importing
dependencies through `go/importer` "gc" export data from that listing. Rules, applied to
`types.Info` (so aliases, renamed receivers, embedding and handle chains such as
`db.For(p).Patient().Modify` resolve by object identity):

| Rule | Rejects outside `internal/ops` and `internal/db` |
|---|---|
| M1 | Any use (call, method value, method expression, promoted method) of a `*db.Blackboard` method the classification table marks mutating: `Modify`, `Write`, `UpdateTask`, `UpdateAgent`, `ArchiveTerminalTask` |
| M2 | A call or reference to an interface method whose name and signature are identical to a mutating `Blackboard` method (interface indirection) |
| C1 | Any use of an `ops` or `db` function or method having a func-typed parameter that itself takes `*models.State`, `*models.Task` or `*models.Agent` (today `ModifyWithAgentAuthority`, `Modify`, `UpdateTask`, `UpdateAgent`); a literal, a named function variable and a variable holding the API are all uses |
| K1 | An exported `*db.Blackboard` method (union over configurations) missing from the classification table, or a table entry naming no method |
| B1 | A production file (`productionFiles`, build constraints ignored) under a checked package that no configuration type-checked |
| S1 | Self-check: `db.Blackboard` or the known callback APIs unresolved (the guard never passes vacuously) |
