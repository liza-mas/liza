Allocate Scope 2 (`arch-scope2`, priority Must) to one coding task: the K4 guard file in the
architecture-guard package, the layer entry of every production package and the five baseline
allowlist entries in their area files.

### Decomposition decision

One task. Guard code, its unit tests and the layer/allowlist data form one deliverable in one

  production package for K4 (not mapped, R8 does not apply) nor a classified import target.
- **D-4 Import graph.** Production packages = the directories (module-relative slash paths) of the
  files `parseProduction` returns, minus the exempt set; a directory with only `_test.go` files
  is therefore no package. For each such file, every import whose path is `<module>/<rel>` adds
  the package-level edge `pkg(file) → rel`, recording the importing files; build constraints are
  ignored because every non-test file is parsed (`arch-foundation`). Standard-library and
  third-party imports are ignored; blank, dot and aliased imports count. The live test parses
  through `liveTree` (one parse per test binary, shared with S1).
- **D-5 `checkK4(graph, areas) []k4Violation`**, pure; all violations returned, sorted by area
  file, rule ID, then package/edge. Per edge P → Q with both mapped and Q not exempt, at most one
  rule matches (the rule sets are disjoint by importer):
  - R1 layer(P) ∈ {domain, infrastructure, leaf}, layer(Q) ∈ {application, runtime, presentation, prompts};
  - R2 application → {runtime, presentation, prompts}; R3 prompts → {application, runtime, presentation};
  - R4 runtime → presentation;
  - R5 layer(P) = presentation, P ≠ `cmd/liza`, Q is `internal/agent` or below it;
  - R6 P = `internal/jsonout`, layer(Q) = application;
  - R7 P is `internal/agent` or below it, Q = `internal/db`.

  "`agent`" in R5/R7 reads as the `arch-layers` runtime row "`agent` and `agent/**`"; no
  `internal/agent/**` sub-package exists at the starting commit (P2), so the reading changes no
  baseline result. An edge matching a rule is a violation unless one allowlist entry names exactly
  its importer and imported package. Integrity checks (rule ID in brackets):
  - unmapped production package [R8];
  - package mapped twice, in one area or across areas [R8-dup];
  - layer entry naming no production package, including an exempt one [R8-stale];
  - layer entry with a value outside D-2 [R8-layer];
  - allowlist entry whose edge no longer exists or no longer matches a rule [ALLOW-stale];
  - allowlist entry with an empty importer, imported, owner or rationale, or a second entry for
    the same edge [ALLOW-entry].

  An edge whose importer or imported package is unmapped is not classified (the package's R8
  violation is reported instead).
- **D-6 Messages** carry the rule ID, the package or edge (`P → Q` with the first importing file),
  the layers involved, and the area file to change: for an entry, the `areaFile` of the area
  holding it; for a forbidden edge, the area file holding P's layer entry (where an
  owner-supplied allowlist entry would go unless SI-5 names another owner). For an unmapped
  package no file is derivable (`arch-areas`: the creating task's area), so the message says to
  add a layer entry in the creating area's file. Only repo-relative paths, never the absolute
  root or environment values (G1.4). `TestK4ImportDirectionGuard` fails once listing every

- **D-7 Data.** Layer entries, sorted by package, per `arch-areas` placement and the `arch-layers`
