## Shared Implementation and Proof Rules

Use a1-scope for semantic requirements rather than treating these local file
allocations as new contracts. Keep orchestrator declarations at their keyed
locations while making them small; every resulting unit satisfies S1. A split
file belongs to its original package/area and needs no new layer or allowlist
entry. Only remove the task's listed ratchet entries, without changing ceilings,
snapshot, S2, layer data, guard code, Makefile or any oracle file.

Each child owns its named production split, directly associated white-box tests,
its guard-data removals, listed invariant references and its acceptance manifest.
Mechanical test file/import/path adjustments are expected and allowed;
behavioral expectation changes are not expected and are forbidden. Move tests
only with their code, preserving each assertion. Existing tests can remain in
their current same-package file when movement adds no clarity. New helper tests
are justified only by a concrete preservation gap. No blanket coverage project.

The tests and manifests use the committed oracle convention; live mode only,
with no ORACLE_WRITE, regeneration, golden update, real provider execution,
installed-binary replacement or live runtime-state access. The source's scoped
race proof takes precedence over the older worktree lesson's full race suite.
Run pre-commit on all touched files before the canonical batch. Submission
requires the actual changed Go/test paths so applicable Go hooks execute; a
manifest-only hook invocation does not establish code formatting.

All commands run from the child's worktree. The first canonical command,
`make lint`, performs embedded preparation as part of its existing target.
The remaining ordered commands are recorded in each Acceptance Contract.
The E1 set is retained undeferred: a1-scope explicitly makes these per-task
acceptance gates, and compiling/running outside callers is part of the
no-exported-API/frozen-composition proof, not just an optional regression sweep.
No manifest maps to a deferred command.

For each child, commit its manifest with exactly the IDs in its declaration.
Use command 2 / `internal/testguard/archguard/s1_guard_test.go:TestS1SizeGuard`
for AC-size, command 1 and an exact package assertion for AC1, command 3 and
the relevant existing oracle test for AC-frozen, and command 4 / `Makefile`
test target for AC-proof; the receipt must also show all other declared commands
passing. A manifest selects one executable mapping for each ID; it does not
copy tests or goldens into the plan directory.

The declared review exceptions cover judgments tests cannot establish alone:
complete exported declaration/signature/tag identity; cohesion of extraction;
assertion preservation across moved white-box files; monotonic ratchet removals
and final emptiness; correct enforcement references; absence of new locks/shims,
out-of-scope edits and C-site changes. Their pinned references name the review
criteria, not an assertion that implementation already passed. The independent
plan reviewer authorizes these exceptions; the coding reviewer must examine the
actual diff before accepting them. AC5 applies additionally to Task 5.
