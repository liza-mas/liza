## Correction

Based on: the amendment reason recorded on this task, the current
arm-1-ar-11-cp-4 output manifest (`omni-ee get arm-1-ar-11-cp-4 --json`, 10
slots, equal to the committed output JSON), the original plan at merge
`63244644f`, ADR-0197 §2 and `internal/models/plan_amendment.go`
(`ValidateAmendmentOutput`), and the probes below.

Orchestrator check b found that Tasks 2, 3, 4, 5, 7 and 8 and the Task 9 value
adoption allocate only generic or colocated tests. They name no full `*_test.go`
path that submission admission recognizes. This correction adds an **Owned test
files** paragraph to each of those sections in the original plan. Task 9 gets an
**Owned value-sensitive test files** table, and the plan's Dependencies and
Shared-File Ownership table gets two test-file rows. Tasks 1, 6 and 10 are unchanged:
Tasks 1 and 6 already name their test files, and Task 10 remains
documentation-only.

The edits leave every Acceptance Contract JSON block, obligation set, canonical
validation array, dependency, `inherit_inputs` value and Owned scope line
byte-identical. They add no behavior, acceptance mapping or test infrastructure.
They only make explicit the characterization each section already required.

### Output-scope boundary

The reason asks for the paths "in its plan section and output scope". This
correction writes them in the plan sections and leaves every output `scope` string
unchanged. In this empty-mode amendment, `amend-plan --apply` freezes each existing
slot's scope: ADR-0197 §2 says so, and `models.ValidateAmendmentOutput` enforces it
with a `reflect.DeepEqual` over everything except dependency, inherited-input,
validation, prerequisite and runtime-input fields. A changed scope makes apply
refuse ("changes existing slot identity or permission"). The frozen scopes already
assign these tests to the children: "their tests" (Task 2), "local tests" (Task 3),
"tests" (Tasks 4, 7, 8), "hook files and tests" (Task 5), "their colocated tests"
(Task 9). Each plan section now gives the exact files. Each section's Owned scope
line stays equal to its output scope. Changing the scope strings themselves would
need `replan` with consumer retirement, which this correction does not authorize.
