## Intent and Allocation

Based on: the resolved a1-scope and its direct references, the legacy goal,
the merged concern-split plan, current worktree source, and the Reality Probes.
This allocates the approved architecture; it introduces no architecture decision.
Success means four reviewable allocations cover the assigned vocabulary and
named-value contract. Validate the plan with payload preflight, reference and
acceptance parity checks, pre-commit, a clean commit and independent plan review.
Doc Impact: this plan and its output JSON. Test Impact: no planner code changes;
the coding children own their focused preservation tests and manifests.

All outputs are **Must**, inherited from a1-scope/K7. Task 1 is the pipeline
control vocabulary boundary; Task 2 is persisted model vocabulary; Task 3 is
the residual A1 adoption sweep; Task 4 is the independently reviewable ADR.
The first two changes each span consumers because X2 requires an atomic
signature-and-caller conversion. Splitting them by package would leave a
non-compiling intermediate result. Combining them would mix config-validation
regressions with history/RCA persistence regressions in a very large diff.
Task 3 has a distinct attribution risk: timing/threshold substitutions should
be reviewable separately from changes to Go type identity. Finer chains per
V-set would add fixed cost without a separately needed deliverable.

No new package, dependency, shim or configuration is allocated. No new shared
interface is designed or frozen: the complete substitutions and consumers are
already prescribed by a1-scope. Provider Ask Inventory is N/A for this
functional-spec-entry run (no epic stage); the AC4 inventory below reconciles
the current consumers. ADR-0045 identities and the open status-partition issue
remain outside scope. The current architectural-issues Update Policy, summary,
control-flow-vocabulary and status-partition sections were consulted; registry
closure remains with the area-boundary owner.

## Change and Proof Rules

The following are local execution directions under the referenced contracts.

- Use the concern-owned files delivered by arm-1-ar-10-cp-0. Current locations
  below are planning evidence, not permission to put split concerns back in
  `task.go` or `resolver.go`. Re-find symbols at coding HEAD.
- Introduce defined string types, not aliases. Keep existing exported constant
  names where they already exist. A new typed constant at an unchanged non-A1
  string API uses `string(constant)`; do not propagate a type through unrelated
  consumer APIs. Slices/maps need element conversion where Go type identity
  prevents direct assignment.
- Each task performs its complete A1 use-site sweep for its own sets and its
  complete X2 caller conversion in the same commit. Task 3 catches residual
  uses, not compile errors intentionally left by Tasks 1 or 2.
- AC3 review traces both producers and consumers of history Extra, anomaly
  Details, JSON payload maps and prompt/template data. Convert at the insertion
  boundary before a later string assertion. Changing the assertion to accept
  another runtime type would change the consumer contract.
- Scope includes mechanical test and test-double conversions. Behavioral
  expectation changes are not expected or authorized. New narrow
  characterization assertions are permitted where the typed boundary exposes
  a preservation risk. Keep all old assertions meaningful.
- Oracle drivers stay under arch-harness: if an adapter needs its first
  call-site edit, preserve its pre-edit body verbatim in the oraclestart twin
  and edit only the live adapter. Existing twins, fixtures, golden paths,
  golden bytes and PROVENANCE remain unchanged. No unrelated driver edits.
- Run pre-commit on every actually touched file before proof commands; passing
  only a manifest path does not exercise Go hooks. Canonical validation starts
  with make lint, which synchronizes embedded assets and checks the three-OS
  vet and size/import guards. No agent installs or replaces the running binary.
- All commands run from the child's worktree with the explicit sanitized
  environment below. Real Git fixtures are disposable; native provider tests
  stay disabled. No live runtime state is a fixture.
- For Tasks 1–3, validation indices 3 and 4 are shared regression-only suites:
  record them once and defer admission execution under the acceptance guide.
  The coder still performs E1 local proof; integration batches deferred
  commands and closure remains held on their result. No manifest maps to a
  deferred index. Task 4's code regression commands are similarly deferred;
  its non-executable document proof is independently reviewed.
- Each child commits the exact manifest named in its Acceptance Contract.
  V-set and AC1 mappings name focused owner validation tests at index 1;
  AC-frozen names live oracle assertions at index 2; AC-guards names the
  existing archguard tests exercised by index 0. Approved proof exceptions
  are reviewed against their pinned reference and map with
  `approved_reference_id` only.
