## Intent and Allocation

Five Must coding outputs build the one A9 oracle package of `a9-scope`. Task 1 delivers the
shared kit (scenario runner, stub provider, A9 normaliser, fixture recipe, package doc with the
published inventory) proven on the supervisor-lifecycle rows. Tasks 2–5 add the remaining row
groups as new files only and run in parallel after Task 1. The split is by independent surface
group (provider-output signals, reviewer, orchestrator, launch), each with its own fixtures and
goldens; one task carrying ~55 scenarios plus the kit would be too large to review (precedent:
A3 lifecycle oracle split conventions + first rows from later rows). Row semantics, kinds, stub
and normaliser contracts stay at `a9-scope`; this plan allocates rows and fixes the local
choices below. This planning task changes only this file and its output JSON.

(`normalise.go`, `cli.go`, `env.go`, `golden.go`, `kind.go`, `fixed-shas.md`, `cmd/regen`);
the delivered correction tests; A3 control and A8 plan precedents; probes below.

## Plan Decisions

These refine `a9-scope` where it leaves a concrete choice; none changes a row, kind, assertion
or golden provenance rule.

- **D-1 Runner.** Drivers build the CLI with `oracle.BuildCLI(t, "./cmd/liza")` (needs
  `oracle.RunMain` in `TestMain`) and run it with `os/exec` in the prepared scenario repository,
  `cmd.Env` = `oracle.ChildEnv(EnvBase{Home: scenario home, Path: scenario bin, Tmp: scenario
  tmp}, extras...)`. Extras: `TZ=Etc/GMT-2` (fixed, non-UTC, no DST, `a9-design`),
  `LIZA_SKIP_AUTO_UPDATE=1`, `LIZA_PROVIDER_CATALOG_URL=http://catalog.invalid/`,
  `GIT_CONFIG_NOSYSTEM=1` and fixed `GIT_AUTHOR_*`/`GIT_COMMITTER_*` name, email and date (P9
  precedent). `oracle.Run` is not used: it allocates its own empty project and runs one
  invocation, while A9 needs a prepared repository, concurrent test-issued commands (`liza stop`,
  `liza delete agent`, `liza config set`) and one shared `HOME` per scenario (P3).
- **D-2 PATH.** The scenario `PATH` is exactly one scenario `bin` directory: stub executables
  plus symlinks to host tools resolved by `exec.LookPath` from the parent `PATH` (at least
  `git`; the minimal set the supervisor needs, listed in the package doc). No host directory is
  ever on a child `PATH`, so no real provider CLI or `acpx` is reachable (E2; I-25).
- **D-3 Stub mechanism (AC1).** The stub is the test binary itself: per needed executable name,
  the kit writes a `/bin/sh` wrapper into `bin` that sets the stub-mode variable and the
  scenario record directory inside the wrapper, then `exec`s `os.Executable()`. `TestMain`
  dispatches stub mode before `oracle.RunMain`. Scenario scripts are committed JSON
  (`testdata/fixtures/<scenario>/stub.json`): executables, version-probe argv and reply per
  executable (R6), per-call-index actions from `a9-scope` "Stub provider" (wait for file with
  failure deadline, print lines, run `liza` commands by the CLI's absolute path, modify or
  commit worktree files, exit code) and snapshot policy (first non-probe call, or per call).
  Data-driven versions let Tasks 2–5 add tools without kit edits.
- **D-4 Timestamp classes.** Precision class is `s` (no fraction) or `f` (fraction of any
  length): RFC3339Nano trims trailing zeros, so digit count varies per run (P7). Zone class is
  `Z`, offset `O` or none `N`. Token spelling `<Tn:cz>` / `<Tn+Ks:cz>` (e.g. `<T1:fZ>`,
  `<T1+1800s:fZ>`), numbered by first appearance per golden document. `f`-class values follow
  `a9-scope` verbatim (equal instants share a token; whole-second offset from an earlier token
  is derived). `s`-class values (signal files, alert lines: RFC3339 seconds, P7) are written by
  wall clock, so equality or a whole-second offset between two of them is timing, not
  construction: a value present verbatim in the scenario's committed fixture keeps an
  equality-preserving token; any other `s` value gets a fresh token per occurrence, derived only
  when it equals an earlier token's instant (truncated to seconds) plus a nonzero multiple of
  60 s (signal expiry +30 min, R4). Deviation from the literal carrier rule for `s` values only,
  to keep goldens deterministic; C1 lease derivations are all `f` (R3, R23).
- **D-5 Identifiers and names.** Volatile identifiers (`a9-scope` list) are found by a key list
  (e.g. `generation`, `transition_id`, `request_id`, digest keys, `record_id`,
  `supervisor_run_id`, `pid`) plus unregistered 40/64-hex, UUID and hash-suffix patterns; equal
  values share `<Vn>` per document; the exact list lives in the package doc. Registered SHAs
  are never touched. File-name stamps and dated names become `<STAMP>`/`<DATE>` without index
  (wall-clock, listing-only); listings are sorted after tokenisation. Paths: the harness
  normaliser instance gets `Dir(project, <PROJECT>)`, `Dir(home, <HOME>)` and `Dir(scenario
  root, <TMP>)`. Order: A9 normaliser, then that harness instance (`sha-correction`).
- **D-6 Fixed SHAs.** Before any `CheckState`/`Check`, register with `KeepSHA` every commit SHA
  of the scenario repository (`git rev-list --all` after the run, plus recipe SHAs) whose
  author and committer dates are the fixed recipe dates and whose message carries no timestamp
  or volatile identifier; any other SHA is a volatile identifier (D-5). The recipe file records
  expected SHAs and materialisation fails on a mismatch.
- **D-7 Golden layout** (`<scenario>` = row prefix and case, e.g. `i01-success`):
  `state/<scenario>/state.yaml` (before → after), `state/<scenario>/launch.yaml` (before →
  at-launch: `state.yaml` plus copied liveness records under `## <name>` headers; per-call
  variants `launch-<k>.yaml`; a test-taken observation snapshot for runs without a provider
  call), `state/<scenario>/runtime.txt` (before → after bundle of the other A9 `.liza/` files:
  `agent-prompts/` and `agent-outputs/` name listings, signal files, `alerts.log`, liveness
  records, usage records), `human/<scenario>/agent.txt`, and `json/<scenario>/invocations.json`
  for I-23 only. Paths are never renamed after commit.
- **D-8 Human content.** `human` goldens hold the exit code and every stdout/stderr line that is
  not a structured log record (`time=… level=…`): log lines are free (`goal-frozen`), CLI and
  error text are not. A row whose path is visible only in logs (I-05 refused fence) is recorded
  through state, runtime files, exit code and non-log output.
- **D-9 Prompt boundary.** Prompt content is A8's surface. The stub replaces an argument or
  stdin equal to the newest saved prompt file with `<PROMPT>`; other stdin is recorded verbatim
  only when it does not contain the prompt, otherwise as `contains_prompt: true` without bytes or
  length. Prompt files appear only as names and that equality (I-26).
- **D-10 Platform and isolation.** Every test skips on Windows with the AC4 reason. Scenarios run
  `t.Parallel()` except adapter tests that `t.Setenv`. Waits are bounded by a failure deadline
  and report the row, golden path and stage (setup, run, collect, compare) without environment
  values (G1.4).
