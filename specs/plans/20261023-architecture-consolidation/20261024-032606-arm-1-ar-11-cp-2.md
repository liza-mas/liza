## Validation and Review Protocol

Each task's exact commands appear in its Acceptance Contract. Execute from the
child worktree. Command 0 synchronizes embedded assets through `make lint` before
standalone Go commands. Run touched-file pre-commit first. Commands 3 and 4 are
long shared regression-only suites: their admission indices are deferred, no
obligation maps to them, and integration batches them. The coder still runs both
locally before submission to meet E1; deferral avoids duplicate admission cost,
not the per-task proof obligation. Commands 0–2 remain undeferred.

The coder commits its declared acceptance manifest. Executable mappings:
`AC-size` → `internal/testguard/archguard/s1_guard_test.go`,
`TestS1SizeGuard`, command 0; `AC-behavior` → the child's package test
assertions below, command 1; `AC-oracle` → the child's identified A2 oracle
test, command 2, which also runs all other live suites including A3/A6.
Five static/process obligations use only the reviewed reference exceptions
declared in each contract; the manifest uses `approved_reference_id` for them.
No test output or manifest can self-approve an exception.

Review with a move-aware diff: same declarations/signatures and bodies, adjusted
imports only, no changed string/raw-string payload, ordering or synchronization.
Mechanical source-path test updates are allowed where required and preserve the
asserted invariant; behavioral assertion changes are not expected. The S1 guard
proves size but not cohesion, which remains independent review.
All oracle files, goldens and provenance remain untouched; regeneration is
review-only under `arch-harness`. The non-default-brand A2 render oracle runs
in command 2. Legacy brand literals move unchanged in their compatibility category.
