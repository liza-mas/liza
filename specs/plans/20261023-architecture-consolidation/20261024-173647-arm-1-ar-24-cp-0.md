Encoding constraints (`scope` Record and presentation separation; the coder picks the concrete
encoding, the tests below fix the outcomes):
- **E1 Location.** Every unavailable record is one regular file directly under the project signal
  directory (`paths.New(root).LizaDir()`, branded) whose name starts with `provider-unavailable-`, so
  the frozen `support-docs/SUPPORT.md` guidance (`ls .liza/provider-unavailable-*`, delete the flag
  file) and the spawn-blocked alert stay true. No path component comes from configured key text;
  tool/display text is encoded so a name like `../x` or `a/b` stays one path element inside that
  directory (no traversal, no new refusal).
- **E2 Legacy.** A file with no originating-tool information (every pre-C3 file, e.g. the A9
  `i21-unavailable-codex-run` fixture `provider-unavailable-codex-acp`) displays its filename
  suffix as today and matches by `Key(suffix)`. An unreadable or unparseable record is evaluated the
  same way (today's presence semantics; never ignored). No migration or rewrite of existing files.
- **E3 Display.** A new record's display provider is the classifier label today's writer used
  (`pu.Provider`, e.g. `codex` for a `codex-acp` raise). No canonical key appears in display, alert
  or error provider values.
- **E4 Byte stability.** A raise whose originating tool equals its display provider (`claude`,
  `codex`) writes the same file name and content as today, so A9 `i20-*` raise goldens stay
  unchanged.
- **E5 Collapse.** Under a config where the raising tools share both display provider and effective
  key (default `codex`/`codex-acp`), successive raises address one record (resume reports one row,
  as today). Raises whose effective keys differ never overwrite each other (`scope`: no conflation
  by alias filename normalization).
- **E6 Order.** Enumeration is lexical by physical name (today's `filepath.Glob` order), so legacy
  fixtures list identical rows in identical order.
- **E7 Handles.** Clear removes exactly an enumerated file; a missing file on clear is success as
  today; clearing all enumerated records leaves no unavailable record that still matches any tool.
- **E8 Policy truth.** Keys are derived at evaluation; no derived key is stored as policy truth and
  `agents[].provider` is untouched.

- **PD-1 Key source.** Callers capture the catalog-derived base once per evaluation through C2's

  goldens stay unedited and green.
