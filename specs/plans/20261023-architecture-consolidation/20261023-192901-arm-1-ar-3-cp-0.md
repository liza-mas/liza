## Goal

Allocate `a3-scope1` (priority Must) to coding tasks: the black-box lifecycle oracle package
`internal/oracle/a3/lifecycle/`, one `TestOracle…` test per CONTRACT row L1–L15, its fixtures and
its goldens created from the starting commit by the entry point.

## Context

Based on: the resolved carrier `a3-scope1` and its direct references; carrier sections Reality
Probes, Surface Inventory, Components, Interfaces and Output (read at `ac5eac0ad`); the merged
harness plan (`plan-harness`, D-1 to D-14: API of the PROSPECTIVE harness and entry point); the
`cmd/liza` help of every L-row command; `internal/models/{task,agent,blocked_recovery,runtime_inputs}.go`,
`internal/runtimeinputs/key.go`, `internal/ops/runtime_input_record.go`; and the probes below.

### Decomposition decision

Two tasks, a linear chain in one package. One task would carry the A3 convention layer
(environment, identity, clock, identifier, stream, runtime-file and state-golden code with its
unit tests), ten fixture states, fifteen drivers and about 75 golden files: an estimated 2,300
hand-written lines plus generated goldens, too large to review as one diff, with every
convention decision (TC5/TC6 masking above all) reviewed only together with fifteen rows.
The seam is the convention layer: Task 1 builds and proves it on the doer rows L1–L7, which
already exercise every golden facet (worktree and branch creation, receipts and token equalities,
refusals with no delta, json and human modes, live-PID tokens); Task 2 adds rows L8–L15 as new
files only, so it never edits an oracle file another task merged (`goal-tests`, `arch-files`
"additive per test"). A three-way split (L8–L11 ∥ L12–L15) was rejected: each extra task pays the
full E1 validation (≈ 13 min, Reality Probes) for about 400 lines.

- **D-4 Environment** (TC3, TC4; R6). Built per run with `os/exec` (the harness runner fixes `PATH`
  to the host's, `plan-harness` D-6/D-14, so drivers run the binary themselves as `a3-scope1`'s
  Interfaces allow); the binary comes from the harness `BuildCLI(t, "./cmd/liza")`. Exact names:
  `HOME`, `PATH` (a per-run directory holding only a `git` symlink to `exec.LookPath("git")` of the
  test process), `TMPDIR`, `TZ=Etc/GMT-2`, `LIZA_SKIP_AUTO_UPDATE=1`,
  `LIZA_PROVIDER_CATALOG_URL=http://catalog.invalid/`, `GIT_CONFIG_NOSYSTEM=1`,
  `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, `GIT_COMMITTER_NAME`,
  `GIT_COMMITTER_EMAIL`, `GIT_COMMITTER_DATE` (fixed values, dates `2020-01-01T00:00:00Z`); plus
  `LIZA_AGENT_ID` and `LIZA_AGENT_GENERATION=gen-1` for agent callers only. `HOME`, `TMPDIR` and
  the project root are fresh per run and `HOME` starts empty. The fixture Git commands use the
  same environment. Live PID = `os.Getpid()`; dead PID literal `99999999` (above Linux's maximum
  `pid_max`, 4194304, R6). The runner refuses a case whose arguments contain `--force` while any
  agent it targets carries the live PID (OC4); no case passes `--cli`.
- **D-5 Clock masking** (TC5; R5, R7). Per case, `start` = wall clock read immediately before the
  case's first CLI invocation, truncated down to the whole second (human output prints second
  precision, so a 1800 s lease printed as `…:39Z` after a `…:39.6` start would otherwise read
  29 min). Every RFC 3339 instant (quoted or not, `T` separator, optional fraction, `Z` or numeric
  offset) within seven days of `start` becomes `<now+Nm ZONE>` (`<now-Nm ZONE>` if earlier), `N`
  the offset truncated to whole minutes, `ZONE` the instant's own zone token (`Z`, `+02:00`). Any
  other instant becomes `<at YYYYMMDDThhmmss[.frac] ZONE>`, digits verbatim. Both forms carry no
  RFC 3339 date-time, so the harness timestamp normaliser (`plan-harness` D-3, which maps every
  date-time incl. its zone to `<TIME>`) leaves them intact and TC5's zone and value assertions
  survive (D-7).
- **D-6 Identifier masking** (TC6; R4, R7, R16). Order: paths, then instants, then identifiers,
  then PIDs.
  - Paths: the run's project root, `HOME` and `TMPDIR` (longest first) → `<PROJECT>`, `<HOME>`,
    `<TMP>`; worktree paths in Git effects are project-relative.
  - Fixture commits: the SHA of each named fixture commit → `<commit:base>`, `<commit:state>`
    (the `state` commit's SHA varies with the PID it records, R4).
  - Volatile values, declared in `mask_test.go`: the values of `transition_id`,
    `completed_transition_id`, `instance_id` and `key_id` (16-hex, R16) found anywhere in the
    case's outputs and states, plus every occurrence of those values elsewhere (receipt
    `expected_transition`, `runtime_inputs` map keys, human output) → `<id-N>`, numbered by first
    appearance in the golden being composed (json: sorted-key traversal; text: line order). A
    value is declared volatile only when two runs of the same case at a start-equal tree differ
    (R4: `expected_transition`, `generation_digest`, `payload_digest`, `base_commit` are stable;
    the four above are not). Validation command 0 runs the package twice (`-count=2`): an
    undeclared volatile value fails it, and the coder extends the declared set from that evidence.
  - Stable 40- and 64-hex values → `<hex:XXXXXXXX.XXXXXXXX…>` (verbatim digits in groups of eight),
    so the harness identifier normaliser cannot fold them into `<ID>` (D-7).
  - Live PID → `<live-pid>`, whole-word matches only, applied after the instant and hex passes;
    in parsed JSON, a number equal to the live PID becomes the string `<live-pid>`.
  JSON stdout is masked on the parsed document (strings and numbers); human output and state
  text are masked line by line.
- **D-7 Harness fixed point.** `conventions_test.go` asserts, for a sample of every D-5/D-6 token
  form, that the harness's exported normaliser returns it unchanged. If the harness regexes catch
  a form, the coder changes the form (still digits-verbatim and zone-carrying) until the test
  passes; this is the only place the token spelling may differ from D-5/D-6.
- **D-8 Goldens** (TC7, TC8, CONTRACT State golden; R8, R9). Paths
  `testdata/golden/<kind>/<command>/<case>.<ext>` with `<command>` ∈ `claim-task`,
  `release-claim`, `handoff`, `write-checkpoint`, `check-commit-allowed`, `mark-blocked`,
  `lifecycle-receipts`, `assess-blocked`, `assess-hypothesis-exhausted`, `unblock-task`,
  `release-blocked-chain`, `recover-task`, `recover-agent`, `provision`, `validate-repair` and
  `<case>` ∈ `success`, `refusal-<reason>` (L5: `allowed-executing`, `allowed-blocked`,
  `denied-review`; L7: `replay`, `stale`). Golden paths are never renamed (`arch-harness`).
  - Streams: lines matching the standard library `log` prefix
    (`^\d{4}/\d{2}/\d{2} \d{2}:\d{2}:\d{2} `) are removed from stdout and stderr before masking.
  - `json` (`--json` runs): `{"runs":[{"exit_code":N,"stdout":<parsed document>,"stderr":[lines]}]}`,
    one entry per CLI invocation of the case in order (L7 `replay` has two). Unparseable stdout
    fails naming the case. Passed to the harness `Check(t, JSON, …)`.
  - `human`: per invocation `exit N`, `stdout:` and its lines, `stderr:` and its lines; harness
    `Check(t, Human, …)`.
  - `state` (json mode of mutating cases): harness `CheckState(t, name, before, after)`; `before` =
    the masked rendered fixture `state.yaml`; `after` = the masked final `state.yaml`, then
    `# git` and the sorted effect lines (`ref + <name> <sha>`, `ref - <name> <sha>`,
    `ref ~ <name> <old> -> <new>`, `worktree + <path> <branch>`, `worktree - <path> <branch>`,
    from `git for-each-ref` and `git worktree list --porcelain` before and after), then
    `# lifecycle outcomes` and sorted `<operation> <outcome> <count>` lines for every non-zero
    count in `.liza/lifecycle-metrics/*.json` (lock and owner files skipped), then `# exit N` of
    the last invocation. Nothing else under `.liza/` is read (`*.lock`, `*.lock.owner.json`,
    `log.yaml`, `alerts.log*` excluded, TC8). A refusal records whatever delta the starting
    commit produces.
  - The human-mode run of a mutating case composes the same `after` text and asserts it equals
    the json-mode `after` (failure names the case and the first differing line number only).
- **D-9 Callers and invocations** (CONTRACT table; R4–R16). Agent callers run with `LIZA_AGENT_ID`
  set to the caller and no `--agent-id` flag; operator callers have neither. Refusals per row are
  the CONTRACT's, reached as probed: L1 claim of `executing.yaml` (`not claimable by coder`); L2
  `release-claim task-1 --role doer` on `executing.yaml` (lease valid, use `--force`); L3 handoff by
  `coder-2` (`STALE_CALLER`, `a3-probes` P16); L4 checkpoint on `blocked.yaml` (`not in an
  executing state`); L6 `mark-blocked` on `blocked.yaml`, L8 `assess-blocked` and L10
  `unblock-task` on `executing.yaml` (`ALREADY_TRANSITIONED`, P16); L9 one `failed_by` entry;
  L11 `blocked.yaml` (`0 of 2`); L12/L13 live assignee (`still running`); L14 `--input nope`.
  Fixed arguments: L3 summary `oracle summary`, next `oracle next`; L4 `--intent oracle-intent
  --validation-plan oracle-plan --files-to-modify a.go`; L6/L7 `--reason oracle-reason --questions
  oracle-question`; L8 `--note oracle-note`; L10, L11 `--reason oracle-reason`. L7 `replay`: two
  identical `mark-blocked … --request-id req-1 --expected-transition <pre>` on one repository,
  `<pre>` the constant pre-state transition id of `executing.yaml` (R10; a constant, so a changed
  derivation surfaces as a golden difference); L7 `stale`: one request `--request-id req-2` with
  an all-zero expected transition. L14 writes the envelope `TOK=oracle-value` to `<TMPDIR>/tok.env`
  before the run and passes that absolute path; each mode has its own fresh `HOME`, in which the
  CLI creates its key (R16). L15 runs `validate --repair --json` on `executing-dead.yaml`.
- **D-10 Case runner contract (Task 1 → Task 2).** `case_test.go` exposes to drivers in the package:
  a case value naming fixture, caller, arguments, modes (json, human or both), mutating flag,
  ordered setup files written under the run's `TMPDIR` (name and bytes), and invocations (one, or
  several for L7); a run function applying D-2 to D-8. Task 1 implements every field, including
  setup files that only L14 uses, so Task 2 adds driver files without editing Task 1's files.
