### Decomposition decision

Two tasks, a linear chain. One task would carry the harness library, five golden kinds, the CLI
helper, the sample package, the ledger, the change-point engine, Git materialisation, the entry
point, its disposable-repository scenario suite and the ADR: an estimated 3,000+ lines across two
concerns (shared normalisation/comparison used by every oracle suite; Git-history provenance used
only by the entry point), too large to review as one diff. The seam is the golden file: Task 1
fixes how a golden is written and compared; Task 2 only reads and regenerates golden files and
imports from Task 1's library only the child-environment policy `ChildEnv` (D-14), so harness and
entry-point subprocesses share one policy. The ADR documents both and lands with Task 2,
when every convention it records is implemented (DOC row).

- **D-2 Kinds and golden paths.** `type Kind string`, constants `Prompt`, `Artifact`, `JSON`,
  `Human`, `State` with values `prompt`, `artifact`, `json`, `human`, `state`. Golden path =
  `testdata/golden/<kind>/<name>` relative to the calling package directory; `name` is a clean
  relative slash path without `..` (else the call fails the test).
- **D-3 Normalisers** (H3), exported so drivers and later determinism-only edits reuse them;
  `Normaliser` carries the disposable directories of the run (temp, home, project) as
  replacements:
  - timestamps: RFC 3339 / ISO 8601 date-times with `T` or space separator, optional fractional
    seconds, and `Z` or a numeric local offset (`+02:00`, `-0500`) → `<TIME>`;
  - temporary paths: each registered directory, longest first, and the system temporary
    directory prefix → `<TMP>`, `<HOME>`, `<PROJECT>`; slash and OS separators both matched;
  - volatile identifiers: 40- and 64-hex runs and canonical UUIDs → `<ID>`; driver-registered
    literal values → caller-chosen tokens;
  - ordering: `SortLines` for outputs whose line order is not asserted, used only where a driver
    asks for it; JSON object keys are always sorted (D-4).
- **D-4 Golden form per kind** (H3, H4; carrier "Golden form"): `prompt`, `artifact` = raw bytes,
  no normaliser; `json` = decode with `UseNumber`, string values passed through the normaliser,
  re-encode with sorted keys, two-space indent, trailing newline (codes are string values that
  survive unchanged); `human` = ANSI escape sequences removed, each line's whitespace-separated
  tokens joined by one space, empty lines dropped, line and token order kept; `state` = one file
  `# before\n<normalised state.yaml>\n# after\n<normalised state.yaml>\n`, each side
  text-normalised line by line (timestamps, paths, identifiers; no YAML parser, K5).
- **D-5 Golden I/O.** `Check(t, kind, name, got)` normalises `got` per kind and compares bytes
  with the golden. Live mode (default): a missing golden fails naming its path; a mismatch fails
  naming path, kind and the first differing line number with both lines truncated to 200 bytes;
  live mode never writes. Write mode, enabled by environment variable `ORACLE_WRITE=1`: writes
  the normalised bytes (creating directories, overwriting) and never fails on content.
  `CheckState(t, name, before, after)` is the `state` form.
- **D-6 CLI helper.** `RunMain(m *testing.M)` for each oracle package's `TestMain` owns the
  per-binary temporary root (`os.MkdirTemp`, removed after `m.Run`). `BuildCLI(t, mainPkg)` builds
  `mainPkg` (e.g. `./cmd/liza`, a path: G1.3 structural) once per test binary (`sync.Once`) from
  the module root found by walking up from the package directory to `go.mod`, as a Go-toolchain
  child of D-14 (home = parent home, tmp = the per-binary root; `GOFLAGS=-buildvcs=false`, Q15).
  `Run(t, bin, args, opts)` runs it in a fresh disposable project directory with exactly
  `ChildEnv(home = disposable home, path = host PATH, tmp = disposable tmp)` plus driver-supplied
  pairs (D-14), never inheriting the host environment (E4, G1.4); returns stdout, stderr, exit
  code. Failure messages carry variable names, paths relative to the disposable
  root, and exit codes, never environment values.
- **D-7 Sample goldens** (surfaces present at start, P1, P5; harness proof only, outside any
  area's inventory): binary-driven `TestOracleSampleHelp` = `<cli> --help` → `human`
  `help.txt`; adapter-driven `TestOracleSampleErrorEnvelope` = adapter `errorEnvelope()` calling
  `jsonout.WriteResult(&buf, nil, nil, err)` with a fixed untyped error whose message
  `ClassifyError` maps to a code other than its fallback → `json` `error-envelope.json`. The
  adapter is untagged (not split by this task, H1 adapter rule). Goldens are produced by write
  mode on a tree whose `cmd` and `internal` production files equal the starting commit, checked
  before generation with `git diff --quiet 96c9ad69aee983ce2b929dd681b6ba43bf920535 HEAD -- cmd internal ':(exclude)internal/testguard' ':(exclude)internal/testhelpers' ':(exclude)internal/oracle'`
  (E5); Task 2's entry point then reproduces them from the starting commit.
- **D-8 Ledger** (`internal/oracle/PROVENANCE`, parsed by Task 2): one record per line, fields
  separated by one space, no comments or blank lines. Exactly one `start <40-hex>`, first;
  `fix <40-hex>`; `changed <golden-path> <reason>` with `<golden-path>` a repo-relative path
  matching `internal/oracle/**/testdata/golden/<kind>/…` and `<reason>` ∈ `C1`…`C6`,
  `determinism`, `fix`. Any other shape (a fourth field, a SHA as reason, unknown kind) is a
  ledger error naming the line number: a `changed` record cannot carry a SHA.
- **D-9 History and change points** (carrier "Change points", Q14). Chained golden = one named by
  a `changed` record with a C reason in the ledger at HEAD. Candidates =
  `git log --reverse --format=%H -- <G>` from HEAD (default history simplification, so a
  `--no-ff` merge TREESAME to its task parent is not listed). `c1` = first candidate whose diff to
  its first parent adds a `changed G C<n>` line to `PROVENANCE`; `c1…ck` = `c1` and every later
  candidate. Each must be a non-merge commit adding exactly one `changed G …` line (else
  unexplained: merge changing a golden, change without record, two records). Separately, every
  commit listed by `git log --format=%H -- internal/oracle/PROVENANCE` whose diff adds a
  `changed G …` line must change `G`'s blob against its first parent (else unexplained: record
  without change). Records added for a non-chained golden are checked by this rule only.
- **D-10 Materialisation.** One temporary root `os.MkdirTemp("", "oracle-regen-*")`; per needed
  tree `git worktree add --detach <root>/<n> <commit>`; `git worktree remove --force` for every
  created worktree and removal of the root in a deferred cleanup that also runs on SIGINT/SIGTERM
  (`signal.NotifyContext`) and on any failure. No `git branch`, `tag`, `update-ref`, `stash`,
  `checkout` in the repository's own worktree; no path under `.worktrees/` or `.liza/`. Trees:
  - baseline(oracle-tree source O ∈ {working tree, `c1^`}): worktree at `start`; for each `fix`
    record of the ledger at O in ledger order, `git diff --binary <fix>^1 <fix> -- . ':(exclude)internal/oracle'`
    applied with `git apply` in the worktree; then `internal/oracle/` and
    `internal/testhelpers/oracle/` removed and replaced from O (working tree: file copy of the
    current files; commit: `git -C <tree> checkout <O> -- internal/oracle internal/testhelpers/oracle`,
    which writes only that worktree's index); built with `-tags oraclestart`;
  - change point `ci`: worktree at `ci`, untagged.
  Trees are keyed and created once per (kind, commit).
- **D-11 Regeneration** (default implementation of the `regenerator` seam, D-13): in the tree,
  delete every `internal/oracle/**/testdata/golden/**` file, run
  `go run ./internal/brandrender/cmd/sync-embedded --repo-root .` (Makefile line 120, Q8, Q15:
  embedded copies are untracked), then `go test -count=1 [-tags oraclestart] <packages>`, both as
  Go-toolchain children of D-14 (home = the entry point's own home, path = its `PATH`, tmp = the
  temporary root), the `go test` child adding `ORACLE_WRITE=1`; collect the written golden files
  as path → bytes. Every Git child of D-10 and D-12 runs with the same `ChildEnv` base, through one
  command constructor in `cmd/regen`. Any non-zero exit fails that tree's regeneration, reported with
  stage (`worktree`, `fix-apply`, `overlay`, `sync`, `go-test`), tree commit and the failing
  test names from `go test` output; output excerpts are bounded and contain no environment value
  (the child environment is the explicit one). G1.1 does not apply: this is repository tooling,
  not runtime behaviour run in user projects.
- **D-12 Comparison and report** (carrier "Comparison rule"). Golden set = working-tree files
  under `internal/oracle/**/testdata/golden/**` within the filter. Non-chained G: baseline(working
  tree) value equals working-tree bytes. Chained G: (1) baseline(`c1^`) value equals
  `git show c1^:G` (absent at `c1^` → unexplained); (2) each `ci` regenerated equals
  `git show ci:G`; (3) working-tree bytes equal `git show ck:G`. Missing = regenerated by
  baseline(working tree) but absent from the working tree; extra = present but not regenerated
  there. Output lines, sorted by path: `ok <path> H1`; `ok <path> chain pre <c1^ sha> <reason> <c1 sha> … <reason> <ck sha>`;
  `unexplained <path>: <rule> [<sha>]`; `missing <path>`; `extra <path>`; setup failures as
  `error <stage> <commit>: <detail>`. Exit 0 iff every golden is `ok` and nothing is missing,
  extra or errored; 1 for unexplained/missing/extra; 2 for ledger or setup errors.
- **D-13 Entry point.** `go run ./internal/testhelpers/oracle/cmd/regen [-repo DIR] [-mode check|write-new] [-pkg PATTERN]...`;
  `-repo` defaults to the repository containing the working directory (`git rev-parse
  --show-toplevel`); `-pkg` patterns (default `./internal/oracle/...`) bound the packages run
  and the golden set. `write-new`: regenerate baseline(working tree) only, copy each missing
  golden into the working tree, never overwrite an existing file, print `wrote <path>` lines,
  exit 0 (or 2 on setup error). `main` calls `run(ctx, args, stdout, stderr, regenerator) int`;
  tests inject a fake `regenerator` (func over tree directory, commit, baseline flag and
  packages returning path → bytes), so history, materialisation and comparison are tested with
  real Git on disposable repositories without a Go build per tree.
- **D-14 Child environment policy** (E4, G1.4; review R2). One exported function in the harness,
  `ChildEnv(base EnvBase, extra ...string) []string` with `EnvBase{Home, Path, Tmp string; Go bool}`, delegating
  to an unexported `childEnv(goos, …)` so every platform's set is unit-tested on any host. It is
  the only source of `exec.Cmd.Env` for the CLI build and run (D-6) and for every entry-point
  child (D-10, D-11). Exact names:
  - all platforms: `HOME`=Home, `PATH`=Path, `TMPDIR`=Tmp;
  - `windows` adds `USERPROFILE`=Home and `TMP`=`TEMP`=Tmp, because `os.UserHomeDir` reads
    `USERPROFILE` and `os.TempDir` reads `TMP`, `TEMP` there (P11), so the disposable directories
    take effect; and `SYSTEMROOT` = the parent's value, set explicitly: `os/exec` appends the host
    `SYSTEMROOT` to any `Env` lacking that name (`addCriticalEnv`, "required (or at least almost
    always required)", P11), so omitting it would not suppress it, and naming it makes the set
    exact. An empty value is not used: it would deprive Windows children of the system directory
    `os/exec` treats as required. The value is a fixed OS location, passed but never printed;
  - Go-toolchain children (`Go` set: D-6 build, D-11 sync and `go test`) add `GOCACHE` and `GOMODCACHE`
    (the parent's `go env` values, resolved once per process) and `GOFLAGS=-buildvcs=false`:
    the caches then resolve without inheriting `LocalAppData`/`XDG_CACHE_HOME` and independently
    of Home (P12);
  - `extra` pairs are appended; one redefining a policy name is an error naming it.
  No other host variable reaches a child. Assertions compare names only (case-insensitively on
  Windows, where names are case-insensitive); failure messages name variables, never values.
