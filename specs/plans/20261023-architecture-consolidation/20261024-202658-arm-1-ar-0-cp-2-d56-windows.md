### b. Mechanism

`withoutExcluded` normalises one side of a path comparison. When the child's reported working
directory differs in spelling from `EvalSymlinks(dir)`, `filepath.Rel(base, line)` returns a
relative path that climbs out of `base` and back in (for example `../link/internal/oracle/sample`,
RP-3), which never equals `./internal/oracle/sample`. The C package is kept, the relative path still
names the same package for `go test`, and the C1-flipped driver runs over starting production:
`sample_test.go:32: envelope lacks the C1 message`. On macOS the reported form is physical
(`/private/var/…`) and `base` is resolved to it, so they agree; on Linux both are physical. On
Windows the child reports the spelling it was given (`RUNNER~1`), while `base` is normalised to the
long name.

### c. Reproduction

- **Native (unreproducible here):** `TestRegenReproducesChangedSampleAssertion` on a Windows runner
  whose temporary directory has an 8.3 component (CI job 120972050452).
- **Local, real `go list` (RP-3):** a module under `/tmp/d56probe/mod`, a symlink `link` to it,
  `go list -f {{.Dir}} ./internal/oracle/...` run with `Dir=link`; with the child reporting the
  given spelling (`PWD=link`, the Unix analogue of `GetCurrentDirectory`), the current filter keeps
  `./../link/internal/oracle/sample` with `excluded=[./internal/oracle/sample]`; resolving both
  sides keeps only `./internal/oracle/other`.
- **Child regression (Task 1 test 1):** the same state through the filter the child extracts —
  materialised path given as a symlink, listed directories in the given spelling — red before the
  fix on every platform, green after.

### d. Verification scope

Verified: source path above; the failure text and `TEMP`/`TMP` values in the job log; the
mechanism with real `go list` on Linux; the real test passing on Linux (RP-4). Not verified
locally (Windows platform behaviour): that `GetCurrentDirectory` keeps the 8.3 spelling the parent
passed and that `FindFirstFile` expands it, so `base` and the listed lines differ by `RUNNER~1`
versus the long name or by case. The established cause does not depend on which spelling differs:
elimination shows the sample package was kept by `withoutExcluded`, which only happens when the
two sides differ in spelling. The `path/overlay` hypothesis in the note is refuted for the overlay
(evidence above) and confirmed only as a path-spelling comparison in exclusion.

### e. Sufficiency

Resolving each listed directory with the same `filepath.EvalSymlinks` used for `base` makes both
sides canonical by one function: symlinks (Unix, macOS), 8.3 names and case (Windows) cannot
differ any more, so a selected C package always maps to its `./<dir>` and is excluded. Residual: a
spelling `EvalSymlinks` does not canonicalise. Task 1 rule 3 turns it into an error (a listed
directory outside the materialised tree exits 2 as `error go-list working`) instead of a silent
inclusion. Native Windows proof is only the D52 boundary run at the corrected SHA.
