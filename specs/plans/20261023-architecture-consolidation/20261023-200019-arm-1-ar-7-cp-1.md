### Decomposition decision

One coding task. Every row's driver shares the package's `TestMain`, environment builder, runner,
normaliser and mask table, manifest builder, and fixture-repository materialiser. Init and
activation rows also share the Git snapshots. Splitting by row would give a linear chain over the
same files that no other task consumes, so under the fixed-cost rule it is one deliverable. The
`write-new` tool writes the goldens and the entry point's check verifies them, so the hand-written
diff a reviewer reads is drivers, one adapter and small fixtures (estimate 900–1 300 lines).

### Interpretations (DERIVED; each disclosed for review)

- **I-1 Setup runs pass `--yes`.** "default" is `setup --yes`, and every other setup run adds its
  flag to that. `--force` without `--yes` prompts and fails on empty stdin (Q3), so the success path
  needs `--yes`. The architect's setup probes (R2, R11) also ran `setup --yes`.
- **I-2 Init preconditions.** MAS init refuses without a global config (Q2), so every init run
  first runs `setup --yes` in the same fresh home. That setup is a fixture step and is not
  recorded. Activation rows already state "after a default setup" (R10).
- **I-3 Re-init refusal omits `--yes`.** With `--yes`, re-init deletes without asking (Q11), so the
  prompt can only be declined without it. The refusal run is a first `init "<goal>" --yes` (fixture
  step), then `init "<goal>"` with stdin `n\n`. This matches R11, which also ran without `--yes`.
  Every other init run keeps `--yes` as the CONTRACT states.
- **I-4 Cursor stderr follows codex.** `--cursor` performs codex activation (its stdout links
  `~/.codex/AGENTS.md`, help: "dependent Claude/Codex project setup"). Its stderr carries the same
  host-dependent AppArmor warning as `--codex` (Q14). AC5's exception for codex activation therefore
  covers both runs. Recording cursor's stderr would make that golden differ between hosts (H3).
- **I-5 `setup --provider kimi` is recorded as observed.** At the starting commit it exits 1 with
  `provider kimi does not define setup skill symlinks` (Q4). The CONTRACT lists it as a run, so its
  golden set records that output, exit code and home tree. No row is added or dropped.

- **P-2 Golden names.** `testdata/golden/<kind>/<surface>/<case>.<ext>`, with `<surface>` one of
  `setup`, `init`, `activation`, `migrate`, `tui`. Extensions: `human/…/<case>.txt`;
  `state/…/<case>.state` (`state.yaml` before/after) and `<case>.git-effects`;
  `artifact/…/<case>.home` (home manifest), `<case>.project` (project manifest) and
  `<case>.activations` (Git-directory artifact). Cases:
  - setup: `default`, `force`, `agent-tools`, `claude`, `codex`, `copilot`, `cursor`, `gemini`,
    `mistral`, `opencode`, `pi`, `provider-kimi`, `refusal-existing-home`;
  - init: `default`, `config-flags`, `default-cli-<p>` for `claude`, `codex`, `cursor`, `opencode`,
    `copilot`, `gemini`, `mistral`, `pi`, `refusal-spec-uncommitted`, `refusal-reinit-declined`;
  - activation: `claude`, `codex`, `cursor`, `opencode`, `copilot`, `gemini`, `mistral`, `pi`,
    `provider-kimi`;
  - migrate: `legacy`, `clean`, `refusal-unparseable`;
  - tui: `auto-resume` (`state` only).
  No golden carries a `.json`, `.yaml` or `.toml` extension, so the repository's `check-json`,
  `check-yaml` and `check-toml` hooks never parse one (Q17).
- **P-3 Environment** (AC3, G1.4). Each run gets a fresh `t.TempDir()` root holding `home`,
  `project`, `tmp` and `bin`. `bin` holds a symlink `git` → `exec.LookPath("git")` and a stub
  `pre-commit` (`#!/bin/sh\nexit 0\n`, mode 0755) that the test writes. The environment is
  `oracle.ChildEnv(oracle.EnvBase{Home: home, Path: bin, Tmp: tmp}, extra...)`. `extra` is exactly
  `LIZA_PROVIDER_CATALOG_URL=http://catalog.invalid/`, `LIZA_SKIP_AUTO_UPDATE=1`,
  `GIT_CONFIG_NOSYSTEM=1` and fixed literals for `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`,
  `GIT_AUTHOR_DATE`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL` and `GIT_COMMITTER_DATE` (dates far
  in the past, AC4). No row names any other variable. Every Git child of the drivers (P-7, P-8)
  uses the same environment. Drivers run processes with `os/exec` themselves, because the harness
  `Run` fixes `PATH` to the host's and makes a new project for every call
  (`arch-provider-asks`). Failure messages name variables and root-relative paths, never values.
- **P-4 Runner.** `runCLI(t, env, dir, stdin, args...) (stdout, stderr []byte, exit int)` runs the
  binary from `oracle.BuildCLI(t, "./cmd/liza")`, with `dir` the run's `project` or `tmp`, never
  this repository (E4). Init and activation run with `dir = project` (AC3, carrier: "init runs with
  the project root as working directory"). Migrate also runs with `dir = project` and no argument,
  so it reads its default `.liza/state.yaml`. The exit code comes from `*exec.ExitError`.
- **P-5 Record shape** (AC5, exit-code rule): one `human` golden per invocation holding the lines
  `exit <n>`, `--- stdout`, stdout, `--- stderr`, stderr, passed to `Check(Human, …)` of the run's
  normaliser. For codex and cursor activation (I-4), the stderr section is the single line
  `--- stderr omitted (AC5)`. Fixture-step invocations (I-2, I-3, the setup before `--force`) are
  not recorded, but each must exit 0. The driver fails naming the step and its exit code otherwise.
- **P-6 Normaliser and masks** (AC4, H3). Each run builds its normaliser with
  `n := oracle.NewNormaliser()`. It registers the run root's directories with `n.Dir`, using
  `oracle.TokenHome` for `home`, `oracle.TokenProject` for `project`, `oracle.TokenTmp` for `tmp`
  and `<ROOT>` for the root itself (the longest match wins, D-3). It then applies the package mask
  table, declared once in `main_test.go`: `goal-<digits>` → `goal-<ID>`, and every now-relative
  value the coder observes (none is expected in these outputs). Timestamps and hex ids stay with the
  harness normaliser. Masks apply before `Check`/`CheckState` in live and write mode alike, so
  goldens hold the masked form. The table is the only place masks are declared, so a later fix is a
  determinism-only edit. A value that differs between two `write-new` runs gets a mask before
  submission.
- **P-7 Fixtures** (AC4, carrier "committed fixture files include `specs/vision.md` and
  `.pre-commit-config.yaml`"). `materialiseRepo(t, env, project, commitSpec bool)` copies
  `testdata/fixtures/repo/**` into `project`. It runs `git init -q -b main` and stages the files by
  name, including `specs/vision.md` only when `commitSpec` is true. It commits with subject
  `fixture` and returns the named-commit map `{<sha>: "fixture"}` (stable under the fixed dates,
  Q7). The spec-uncommitted refusal calls it with `commitSpec=false`, which leaves
  `specs/vision.md` untracked. State fixtures are copied to `<project>/.liza/state.yaml`, never kept
  under a `.liza/` path in this repository (E4):
  - `legacy.yaml` holds one trigger for each normalisation `commands/migrate.go` applies:
    - an agent with role `code_reviewer` (`roles.NormalizeRoleName`);
    - a task with legacy `attempted: [<x>]` and no `attempt` (`Task.MigrateAttemptedField`);
    - a task with `lease_expires` and no `assigned_to`;
    - a `retry_loop` anomaly whose details hold `agent_id`, `role`, `rounds` and
      `impact: <models.PendingMergeStallImpact>`, without `count` or `error_pattern`
      (`MigrateLegacyPendingMergeStall`);
    - an anomaly whose `details.message` is transcript-shaped (`statehygiene.ScrubStateForMigration`).
    Timestamps are far in the past or future, and every PID exceeds 4194304.
  - `clean.yaml` is a valid state with `auto_resume` unset (false). The `clean` migrate run and the
    TUI row both use it.
  - `unparseable.txt` holds `version: [` and is copied to `.liza/state.yaml`.
- **P-8 Git effects** (`state` kind; carrier "Git effects"). `gitSnapshot(t, env, project, names)`
  returns sorted text lines:
  - `ref <refname> <name>` for each `git for-each-ref` entry, where `<name>` is the commit's
    fixture name, or `unnamed <subject>` for any other commit;
  - `exclude <line>` for each non-comment, non-empty line of `.git/info/exclude`;
  - `hook <name> <perm>` for each `.git/hooks` entry without the `.sample` suffix;
  - `config <key>=<value>` for each `git config --local --list` line.
  The snapshot is taken before and after the recorded invocation and passed to
  `n.CheckState(name, before, after)`. Values pass through the run's normaliser.
- **P-9 Manifests and Git-directory artifact** (`artifact` kind, so bytes are compared raw and the
  driver normalises them before `Check`).
  - `manifest(root)` lists every entry under `root`, sorted by slash path. Each line is
    `<path> <type> <perm-octal> <target-or-hash>`: a symlink's target after `n.Text`, or a regular
    file's SHA-256 over its content with only the registered directories replaced. The project root
    skips `.git/**`. AC6 files (`*.lock`, `*.lock.owner.json`, `log.yaml`, `alerts.log`,
    `~/.liza/cache/**`) are excluded.
  - `.liza/state.yaml` is the one file whose content varies between runs (Q7). It is hashed after
    the full normaliser and masks, the same transform as its `state` golden.
  - The golden is a delta between snapshots taken before and after the recorded invocation: lines
    `+ <entry>`, `~ <entry>` (same path, different type, mode or hash) and `- <path>`. A fresh, empty
    root yields only `+` lines.
  - The Git-directory artifact is the content of `.git/liza-provider-activations.json` after
    `n.Text`, or the single line `<absent>` when the file does not exist. It is recorded for every
    init and activation run.
  - The `state.yaml` before and after sides use the same `<absent>` line for a missing file.
- **P-10 Permission determinism.** Installed modes follow the process umask (Q8). `TestMain`
  therefore sets umask 022 before any run, so the goldens agree between the entry point, `make test`
  and CI hosts.
- **P-11 TUI adapter** (`adapter_tui_test.go`, untagged; imports `internal/tui` and
  `github.com/charmbracelet/bubbletea`). `toggleAutoResume(projectRoot string) error` does the
  following (Q16):
  1. calls `tui.New(projectRoot)`;
  2. sends `tea.KeyMsg{Type: tea.KeyRunes, Runes: []rune{'y'}}` through `Update`;
  3. requires a non-nil command and executes it;
  4. requires the result to be `tui.CmdResultMsg` with `Success` true;
  5. sends `'q'` through `Update`, which closes the watcher.
  It returns an error naming the failed step. The driver materialises a project whose state is
  `clean.yaml` (with `git init -q -b main`, as probed), snapshots `state.yaml`, calls the adapter and
  records `state/tui/auto-resume.state`. The adapter compiles against the starting tree because the
  production trees are equal (Q1). If HEAD's `cmd/` or `internal/` differs from `96c9ad69a` in
  `internal/tui` when the coder starts, the coder applies the `arch-harness` adapter rule for an
  oracle added after refactors began. The adapter then ships as an `oraclestart` twin plus a
  `!oraclestart` original.
- **P-12 Generation workflow** (AC8, E5). The coder writes drivers and fixtures, then creates the
  goldens only with
  `go run ./internal/testhelpers/oracle/cmd/regen -mode write-new -pkg ./internal/oracle/a7/install/...`.
  Running `ORACLE_WRITE=1` in the worktree and editing a golden by hand are both forbidden. After
  generation, the coder deletes the goldens, regenerates them and diffs the result, then runs
  `pre-commit run --files` on them. The goldens must be byte-identical after both steps (Q17: the
  `end-of-file-fixer` and `trailing-whitespace` hooks apply repo-wide). A difference is fixed by a
  P-6 mask or a P-2 name, never by editing the golden.
