  Task 2: `dependencies_test.go`, `planning_test.go`; Task 3: `sprint_test.go`,

  `adapter_checkpoint_test.go` (Task 3).
- Tagged proof: `regen_proof_test.go` with `//go:build oracleproof` (Task 1).
- Inputs: `testdata/fixtures/pipeline.yaml` (byte copy of
  `git show 96c9ad69aee983ce2b929dd681b6ba43bf920535:internal/embedded/pipeline.yaml`,
  D4), `testdata/fixtures/project/**` (committed docs), `testdata/fixtures/state/<name>.yaml`,

- Goldens: `testdata/golden/<kind>/<command-dir>/<case>.<ext>`; ext `.json` (json),

- Acceptance manifests: `testdata/acceptance-a4-<n>.json` (n = task number).

Later tasks add files only; they never edit Task 1 files. A gap found later is closed in
the later task's own files (shared-file audit below).

### Invocation (AC-invocation)

- CLI: `oracle.BuildCLI(t, "./cmd/liza")`; `TestMain` calls `oracle.RunMain(m)` after the
  helper dispatch.
- Env per run: `oracle.ChildEnv(EnvBase{Home: <fresh empty dir>, Path: os.Getenv("PATH"),
  Tmp: <fresh dir>}, "TZ=Etc/GMT-2", "GIT_CONFIG_NOSYSTEM=1", identity...)`. Identity per
  D6: operator cases add none; others add `LIZA_AGENT_ID=orchestrator-1`,
  `LIZA_AGENT_GENERATION=gen-1`; G3 adds only `LIZA_AGENT_ID=architect-1`,
  `LIZA_AGENT_GENERATION=gen-a1`; O1 uses the orchestrator pair. Default-brand names are
  tests asserting default-brand behaviour (G1.3, `a4-crosscutting`).
- `cmd.Dir` = fixture root; stdin empty (`bytes.NewReader(nil)`); stdout and stderr
  captured separately; exit code from `exec.ExitError`; 2-minute context timeout.
- Diagnostics name variables, never values (G1.4). `TestA4Environment` asserts the exact
  name set per identity class and that `HOME` starts empty.
- Helper process (D5, T2/S2): `TestMain` checks `os.Args[1] == "a4-helper"` before
  `RunMain`; `os.Args[2]` names an op in the driver-held registry
  `helperOps map[string]func(root string) (string, error)`, populated by adapter files'
  `init()`; `os.Args[3]` is the fixture root. The parent re-executes `os.Executable()`
  with the same env as a CLI run (no identity), waits for it, and asserts exit 0 and the
  one-line summary the op returns. No `time.Sleep` anywhere (AC2).

### Golden forms (AC-golden-forms)

- json mode (`--json` added): document `{"exit_code": N, "stdout": <parsed stdout>}`
  after the A4 layer, then `oracle.Normaliser.Check(t, oracle.JSON, ...)`. Non-JSON
  stdout fails naming the case.
- human mode: transcript `exit_code: N` / `--- stdout` / stdout / `--- stderr` / stderr,
  with stdlib log lines (`^\d{4}/\d{2}/\d{2} \d{2}:\d{2}:\d{2}(\.\d+)? `) removed, then
  the A4 layer, then `Check(t, oracle.Human, ...)`.
- state: before = fixture `state.yaml` as written at setup; after = `state.yaml` after
  the run followed by `# written files` and, per created or changed file under the
  fixture root (walk excluding `.git` dirs and `.git` files, `.liza/state.yaml`,
  `log.yaml`, `*.log`, `*.lock`, `*.lock.owner.json`; compare against the pre-run
  snapshot by content), sorted by tokenised path: `## <path>` then the content normalised
  by form (`.json` via the harness JSON form, `.yaml` line-wise as state, `.md`/other via
  the harness human form). Both sides pass the A4 layer, then `CheckState`.
- Mutating cases build a fresh fixture per mode. Where a row has json and human, the
  state golden comes from the json run and the human run's normalised after side must
  equal it (assertion, no second golden). Human-only rows (T1, T3, T4, G7) take the state
  golden from the human run. T2/S2 have only the state golden.

### Determinism layer (AC-determinism; stdlib only; applied before the harness)

One normaliser instance per golden document; first-appearance numbering scans the
document in order (state: before, after, files).
- Instants: RFC 3339 and Go/`time` layouts (`T` or space separator, optional fraction,
  `Z`, `±hh:mm`, `±hhmm` or ` UTC`/` +0000 UTC`) → `<INSTANT Z>` or `<INSTANT +02:00>`
  (the literal offset kept). Instants inside JSON strings and file contents included.
- 40-hex: fixture commits by name `<SHA base>`, `<SHA state>`, recipe labels
  (`<SHA plan>`, `<SHA merge-cp-1>`, `<SHA amend>`, `<SHA merge-amend>`); others
  `<SHA n>`.
- 64-hex: `<DIGEST n>`; archive object paths `objects/<2hex>/<64hex>.json` and
  `lifecycle-metrics/<64hex>.json` tokenise both segments (`objects/<DIGEST n:2>/<DIGEST n>.json`).
- Durations: values after `Elapsed:`, `Remaining:`, `Overdue by:` and Go duration
  strings → `<DURATION>`.
- Archive result byte counts: json `bytes` of `archive-terminal-tasks` and the human
  `(N bytes)` of that command → `<BYTES>`. Other byte counts (note size) stay.
- Fixture root (native, slash and symlink-resolved forms, also inside escaped JSON and
  archive object `value_yaml`) → `<FIXTURE>`; run `HOME`/`TMPDIR` via `Normaliser.Dir`
  with the harness tokens.
- Tokens are fixed points of the harness normaliser (`TestA4HarnessFixedPoint`: harness
  `Text` over a tokenised sample is a no-op).

### Fixtures (AC-fixtures; D4, AC3)

Builder (driver, stdlib + `git` on `PATH`): fresh `root/{project,home,tmp}`; `git init -b
main`; repo-local `user.name Oracle`, `user.email oracle@example.invalid`; setup git
commands use the run env plus `GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE=2020-01-01T00:00:00Z`
(setup only). Base commit: `testdata/fixtures/project/**` (at least `specs/vision.md`,
`specs/plans/p.md` with `## Task 1: One`, `specs/architecture/a.md` with
`## Scope 1: One`) and `.liza/pipeline.yaml`; `integration` branch at base. Optional
Go-level git recipe (`branch`, `commit <label> <path>=<fixture file>`, `merge --no-ff
<label>`, return to `main`) runs before the state commit. State: `{{COMMIT:<label>}}`
tokens (quoted YAML scalars so fixtures pass `check-yaml`) filled with recorded SHAs;
unfilled `{{` fails; state committed on `main`. Each `worktree: .worktrees/<id>` in the
rendered state gets `git worktree add -b task/<id> .worktrees/<id> <base>`. Optional
archive objects copied into `.liza/archive/objects/`. The builder calls no CLI command.
Fixture YAML: literal timestamps (history 2020, leases/deadlines 2099), one
`orchestrator-1` row (role orchestrator, IDLE, `generation: gen-1`, no lease, no pid).
Validity: `TestA4FixturesValidate` builds every `testdata/fixtures/state/*.yaml` and runs
`validate --json` under the run env as a separate test (never in a case's setup): exit 0,
`"valid":true`, `state.yaml` byte-unchanged — or, only where `<name>.violations` exists,
exit 1 with `error.message` equal to that file's content (see Source Conflict). Under the
entry point this runs the starting commit's `validate`.
Authoring aid (never in tests): a child may run the starting-commit CLI in a scratch repo
to obtain the exact YAML a command writes (D2 `inherited`, S8 `archived`, D4), then commit
it with instants replaced by literals.

## Source Conflict: D4 success fixture

⚠️ SOURCE CONFLICT
- `a4-scope1` Fixtures says the committed `.liza` inputs are "valid at the starting commit".
- `a4-inventory` D4 requires `repair-superseded-dependencies` success.
- Evidence (P11, P12): the operation succeeds only on a SUPERSEDED task whose
  `depends_on` names a downstream role-pair task; the starting commit's `validate`
  reports every such edge (`internal/statevalidate/validate_deps.go`
  `validateDependencyDirection`, applied to all tasks): `task p1 has downstream dependency
  t3: role_pair coding-pair is downstream of code-planning-pair`. No valid state yields
  D4 success; the command exists to repair that state.

Options: (1) the D4 success fixture is the one fixture that carries exactly that single
violation, asserted by `superseded-downstream.violations`; every other fixture must be
valid; (2) drop D4 success (loses an inventory case); (3) block for a ruling.
Chosen: (1) — it keeps the inventory case and the intent of the validity rule (no fixture
carries unexplained invalidity), adds no capability, and is reviewable as one file.
Owner: Task 2. If the plan reviewer rejects (1), Task 2's D4 success case is withheld and
the conflict is escalated (mark-blocked with a human action); nothing else changes.
