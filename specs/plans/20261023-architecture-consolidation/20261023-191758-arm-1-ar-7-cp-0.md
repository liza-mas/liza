### Decomposition decision

One coding task. Every row's driver shares the package's `TestMain`, the A7 environment builder,
the record composer and the mask table (one Go package: no per-row duplicate is possible), and most
rows share the fixture project. Splitting by row gives a linear chain over the same files that no
other task consumes, so the fixed-cost rule makes it one deliverable. Goldens are tool-written
(`write-new`) and verified by the entry point's check, so the reviewable hand-written diff is the
drivers, adapters and fixtures (estimate 1 000–1 500 lines).

- **P-2 Golden names.** `testdata/golden/<kind>/<surface>/<case>` with `<surface>` ∈ `status`,
  `get`, `get-tasks`, `version`, `help`, `completion`, `watch`, `stop-guard`,
  `envelope-classification`, `envelope-cli`, `usage`; `<case>` a lowercase slug of the invocation's
  arguments (`json`, `format-yaml`, `detailed-json`, `tasks-all`, `refusal-unknown-id-json`, …) with
  `.json` for `json`, `.txt` for `human`, the shell name for `artifact`. Help: the command path
  joined by `-` (`root` for root `--help`, `help-command` for `help`). Kind per invocation as the
  CONTRACT table states; YAML output is `human` (`arch-provider-asks`).
- **P-3 Environment** (AC3, G1.4). Per test: `t.TempDir()`-rooted `home`, `project`, `tmp`, and a
  `bin` directory holding one symlink `git` → `exec.LookPath("git")` of the test process. Env =
  `oracle.ChildEnv(oracle.EnvBase{Home: home, Path: bin, Tmp: tmp}, extra...)` with `extra` exactly
  `LIZA_PROVIDER_CATALOG_URL=http://catalog.invalid/`, `LIZA_SKIP_AUTO_UPDATE=1`,
  `GIT_CONFIG_NOSYSTEM=1`, `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`,
  `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, `GIT_COMMITTER_DATE` (fixed literals), plus per-row
  variables only where the CONTRACT names them (stop guard: `LIZA_AGENT_ID`). Drivers run the binary
  through `os/exec` themselves because the harness `Run` fixes `PATH` to the host's and its own
  project directory (`arch-provider-asks`: "drivers run the binary with `os/exec` when the harness
  runner lacks a needed control"). Failure messages name variables and paths relative to the
  temporary root, never values.
- **P-4 Runner.** `runCLI(t, env, dir, stdin, args...) (stdout, stderr []byte, exit int)` on the
  binary from `oracle.BuildCLI(t, "./cmd/liza")`; `dir` is the materialised project or a fresh
  temporary directory, never this repository (E4); exit code from `*exec.ExitError`.
- **P-5 Record shape** (one golden per invocation; stdout, stderr, exit code per AC5 and the
  CONTRACT's exit-code rule):
  - `human`: lines `exit <n>`, `--- stdout`, stdout, `--- stderr`, stderr; passed to
    `oracle.Check(t, oracle.Human, name, …)`;
  - `json`: object `{"exit": <n>, "stdout": <stdout decoded as JSON, or the raw string when it is
    empty or not JSON>, "stderr": "<stderr>"}`, passed to `oracle.Check(t, oracle.JSON, name, …)`
    (stop guard's empty output is recorded as `""`);
  - `artifact` (completion scripts): stdout raw; the driver additionally requires exit 0 and empty
    stderr, failing with the observed exit code otherwise, because an artifact golden holds bytes
    only;
  - adapter rows (watch, classification) have no process: `human` lines / `json` bytes as rendered.
- **P-6 A7 masks** (AC4), one declared table in `main_test.go`, applied before `oracle.Check` in
  live and write mode alike (so goldens hold the masked form, H3): JSON values under the keys
  `age`, `time_in_status`, `elapsed`, `lease_expires` and every other key whose value the coder
  observes to be now-relative → `<REL>`; human lines: the value after each now-relative label
  (same set, as rendered) → `<REL>`; `goal-<digits>` → `goal-<ID>`. Timestamps, temporary paths and
  hex ids stay with the harness normaliser (D-3). A value that differs between two runs one minute
  apart is masked; the table is the only place masks are declared, so a later fix is a
  determinism-only edit.
- **P-7 Fixture project** (AC4, CONTRACT "Fixture project"). Committed under
  `testdata/fixtures/project/`: `.liza/state.yaml` meeting the CONTRACT's representativeness list,
  `.liza/pipeline.yaml` equal to the starting commit's default pipeline bytes
  (`git show 96c9ad69a:<default pipeline path>`), every other `.liza/` file `status` and `get` read,
  and every spec file the state references. Timestamps far past or far future; PIDs above Linux
  `pid_max` (4194304). `materialiseFixture(t, env) string` copies it into a fresh temporary project,
  runs `git init -b main`, excludes `/.liza/` in `.git/info/exclude`, commits the rest, and creates
  the integration branch named by the state's config, every Git child with the P-3 environment.
  `TestFixtureStateValidates` runs `validate` (no flags, so spec files are checked) on it and
  requires exit 0; run by the entry point on the baseline tree, it proves acceptance by the starting
  commit's `validate`.
- **P-8 Generation workflow** (AC8, E5). The coder writes drivers and fixtures, then creates goldens
  only with `go run ./internal/testhelpers/oracle/cmd/regen -mode write-new -pkg ./internal/oracle/a7/present/...`;
  never `ORACLE_WRITE=1` in the worktree and never a hand edit. A golden that is not stable across
  two `write-new` runs (delete, rerun, diff) gets a P-6 mask before submission.
