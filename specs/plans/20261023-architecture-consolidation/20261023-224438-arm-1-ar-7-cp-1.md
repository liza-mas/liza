## Allocation and Evidence

Based on the resolved Scope 2 and direct references, D29, the merged harness plan and
ADR-0219, and the delivered-source probes below. Priority: **Must** (`a7-install`).
N3/N4 and H7 retain **Should** priority; they do not add an optional prerequisite.
Doc Impact: this plan and its matching output JSON only. Test Impact: no planner test
changes; Task 1 owns all new oracle tests, inputs, goldens and its acceptance manifest.

One coding unit owns the package deliverable. Splitting fixture construction, snapshots,
test families and golden generation would produce a serial chain over the same package
helpers with no independently consumed intermediate result. The five families remain
separate test files for review. The single intent is preserving Scope 2's installation
surfaces before A7 refactoring. No architecture decision or production change is made.

Data flow: committed inputs → disposable projects → CLI/TUI operation → harness comparisons.
Artifacts: fixture files → temporary installed trees/state → streams, manifests, state pairs.
The stable harness owns comparison and provenance; this package owns inputs and observations.
The one adapter isolates the TUI call site; the binary drivers do not import production code.
Failures propagate as named-case test failures, without environment-value diagnostics.
All runs have separate disposable directories; no live repository state participates.

The two relevant pre-existing issues (`architectural-issues.md` sections “Decompose init.go
(1,268 LOC)” and “Duplicate Initialization Implementations”) are downstream refactor concerns;
this package freezes the CLI reference path without editing either implementation.
No new shared interface is frozen: Task 1 consumes the delivered SI-3 contract. Its required
build, comparison, state-pair and regeneration operations are present (P2–P5). Its prepared
workspace and restricted PATH need a local stdlib subprocess driver, since `oracle.Run`
creates its own directories and uses the host PATH. `oracle.ChildEnv` accepts an explicit
`EnvBase.Path`; no provider correction or harness edit is needed.

### Snapshot and determinism implementation

Apply AC1–AC8, the installed-tree manifest, Git effects and Git-directory artifact definitions
by reference. Manifest enumeration uses `Lstat`/`Readlink` without traversing symlink targets;
sort root-relative paths, record type and permission bits, and normalize temporary roots in
link targets and file content **before** SHA-256. Homes/projects that pre-exist the measured
invocation use added/changed/removed deltas. Preserve empty directories and absent ownership
maps as observations. Restrict `.git` observations to the named effects and ownership artifact.

**D29 implementation:** retain the runtime `.liza/state.yaml` manifest entry, including its
presence/type/permissions. Its content slot is a stable `state-golden` marker, not a hash.
Its content is asserted exclusively by the corresponding normalized before/after state golden.
Every other included regular file retains its SHA-256. This is the operator's D29 override
of the unqualified manifest digest rule, not a new exemption invented by this plan.

Use path-only substitution for installed file hashes and Git-directory artifact contents.
Do not feed whole artifact manifests through `Normaliser.Text`: it masks 40/64-hex strings
and would erase digests (P2). `oracle.Artifact` compares the prepared bytes unchanged.
Use harness `Dir`, `Literal`, `Check` and `CheckState` for human/state observations, registering
only the AC4 goal IDs and field/label-selected relative-time values. Do not sort human rows,
mask stable field values, or normalize installed artifact timestamps/identifiers. Keep the
AC6 exclusions exact. State before/after pairs must distinguish absent from present state.

Use explicit AC3 environments through `oracle.ChildEnv` with a prepared `EnvBase.Path` and
stdlib `exec.CommandContext` for multi-step cases. `oracle.Run` cannot prepare the needed Git
repository or restricted PATH (P2); this local driver is within the standard-library boundary.
Every failure names a case/path/variable name, never a host environment value. All case data
are committed synthetic fixtures; the package neither reads credentials nor uses live state.
