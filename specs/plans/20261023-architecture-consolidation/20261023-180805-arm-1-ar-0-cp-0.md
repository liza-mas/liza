which lands the architecture-guard package, the S1 size guard with its start snapshot and per-area
data, the lint wiring and the guard ADR, after confirming the E0 and sync-clean holds.

One task. Scope 1 names one unit ("the unit merged as the run's first coding task"); package
helpers, data, guard, lint target and ADR form one deliverable in one owned package, and a split
would create a linear chain whose first link would also have to be "first" (`arch-sequence`).
The ADR is architecture record for this unit, not user-facing documentation, so it stays in the
task (DOC row of the matrix).

- **D-2 Data shape** (the seam Scope 2 consumes, `arch-scope2` "Uses Scope 1's … area data shape"):
  `type AreaID string`; `type Key struct{ File, Func string }` (`Func == ""` is a file key);
  `type RatchetEntry struct{ Key Key; Ceiling int }`;
  `type S2Category string` with constants `S2Table`, `S2Registration`, `S2Generated`,
  `S2HumanRuling`; `type S2Entry struct{ Key Key; Category S2Category; Ruling, Rationale string }`
  (`Ruling` names the human ruling, required iff `S2HumanRuling`);
  `type Layer string` (values are Scope 2's: no constants here);
  `type LayerEntry struct{ Package string; Layer Layer }` (module-relative slash path, e.g.
  `internal/ops`); `type AllowEntry struct{ Importer, Imported, Owner, Rationale string }`;
  `type Area struct{ ID AreaID; Layers []LayerEntry; Allowlist []AllowEntry; Ratchet []RatchetEntry; S2 []S2Entry }`.
- **D-3 Keys.** `File` is the repo-relative slash path on every OS (`filepath.ToSlash`). `Func` is
  the name, or `Recv.Name` for a method with pointer, parentheses and type parameters stripped
  (`func (s *Store[K]) Get` → `Store.Get`). The first declaration of a name in a file has no
  ordinal; the n-th repeat (n ≥ 2) gets `#n` (`init#2`), so adding a later duplicate never
  re-keys an earlier one. String form in messages: `file` or `file:Func`.
- **D-4 Measurement** per S1 (`goal-success`): a `FuncDecl` with a body measures
  `line(Body.Rbrace) − line(Pos()) + 1`; a file measures its physical lines (newline count, plus
  one when the last byte is not a newline). Offender = strictly above the threshold. Enumeration:
  every `.go` file under `cmd/` and `internal/`, skipping `_test.go`, `internal/testhelpers/`,
  `internal/testguard/`, `internal/prompts/promptbench/` and any `testdata` directory; build
  constraints are ignored (all files parsed).
- **D-5 `checkS1(measured, snapshot, areas) []violation`**, pure, all violations returned, sorted:
  duplicate key (same key twice in one list, in both lists, or in two areas); ratchet key absent
  from the snapshot; ceiling above its snapshot value; ratchet or S2 key not over threshold
  (stale: remove it); measured above ceiling (overrun); S2 entry with an unknown category, empty
  rationale, or `S2HumanRuling` without `Ruling`; offender in no list (unlisted). A renamed or
  moved offender therefore yields stale (old key) plus unlisted (new key), or "not in snapshot"
  if the new key is ratchet-listed. `TestS1SizeGuard` reports every violation in one run.
- **D-6 Messages** carry key, measured lines, the limit applied (threshold, ceiling or snapshot
  value) and the area file: the entry's `areaFile` for violations of a listed entry. For an
  unlisted offender no data file is derivable (`arch-areas`: a new production file belongs to the
  area of the task creating it), so the message names key, measured value and threshold and says
  to reduce it or add an S2 entry in the owning area's file. Only repo-relative paths, never the
  absolute root or any environment value (G1.4).
- **D-7 Lint target.** New phony target `lint-archguard: go test -count=1 ./internal/testguard/archguard/`,
  invoked from `lint-nosync` (`@$(MAKE) lint-archguard`) and added to the `.PHONY` list, so CI's
  lint lane (`ci-core.yml:156`, `make lint-nosync`) and `make lint` run it; `make test` runs it
  through `./...`.
- **D-8 Snapshot generation.** The coder confirms `git diff --quiet 96c9ad69aee983ce2b929dd681b6ba43bf920535 HEAD -- cmd internal`
  exits 0 (P3) and derives `startSnapshot` from the package's own measurement of the working tree;
  if it does not exit 0, the coder measures a `git archive 96c9ad69a…` export instead (parsing
  needs no sync or build). Ratchet data = snapshot, each entry in its area per `arch-areas`; the
  per-area counts must equal P4.

## Tasks

### Task 1: Size guard and run holds

Priority Must (`arch-scope1`). Depends on: none (first coding task; every other coding task of the
run waits on it by phase inheritance, carrier ASM-001).

**Holds (before submission, recorded in the checkpoint).** (1) P1 and P2 re-run at the rebased
HEAD; (2) `make lint` (validation command 1) leaves `git status --short` empty. On failure,
`omni-ee mark-blocked … --human-action` naming the options of `arch-e0` (E0) or asking the
maintainer to commit the synced copy (sync-clean).

**Changes.** D-1 to D-8; `Makefile` per D-7; ADR `specs/architecture/ADR/0218-<slug>.md` (next
free number at the coder's base) with its README index row, covering the four subjects listed in
`arch-scope1` ADR paragraph, including review of ratchet-data diffs as the remaining shrink check
(`arch-scope1` S1 invariants). Repository paths such as `cmd/liza` appear only as paths (G1.3 structural
category).

**Tests** (TDD, all in the package):
- `s1_measure_test.go`: function lines from declaration to closing brace on fixture source;
  bodiless declaration ignored; receiver key for pointer, generic and value receivers; ordinal on
  a repeated name; physical lines with and without a trailing newline; enumeration over a
  `t.TempDir()` tree applies each exclusion and skips `testdata`.
- `s1_check_test.go`, table-driven over `checkS1`: unlisted offender; ceiling overrun; stale
  ratchet entry; renamed offender (stale + unlisted, and "not in snapshot" when the new key is
  listed); ceiling above snapshot; duplicate across areas and across lists; stale S2 entry;
  malformed S2 entry; several violations reported together; messages name the area file and
  contain no absolute path.
- `areas_list_test.go`: `areas` holds `A1`…`A9` once each, in order; `TestStartSnapshotShape`:
  33 file keys and 93 function keys; `TestModulePath`: non-empty path read from `go.mod`.
- `s1_guard_test.go`: live `TestS1SizeGuard` passes at HEAD.

**Out:** K4 rules and layer/allowlist data (Scope 2), oracle harness, baseline record, production
Go, any file outside the scope.

Executable mappings expected in the manifest: `AC-hold-sync-clean` and `AC-lint-target` →
`Makefile`, command 1; `AC-package-helpers`, `AC-s1-measurement` → `s1_measure_test.go` and
