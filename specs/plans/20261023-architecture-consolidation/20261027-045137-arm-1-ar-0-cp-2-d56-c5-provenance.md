## Corrected Mechanism

Builds on `d56-plan` M1–M9; strings and rules not named here are unchanged.

- **A1 Attributed record.** New ledger form `changed <path> <reason> <commit>`: `<path>` a golden
  path (`goldenPath`), `<reason>` C1–C6 only, `<commit>` 40-hex (`commitSHA`). Any other 4-field shape is
  `ledger line N: invalid record`. The 3-field form is unchanged.
- **A2 Binding.** In `scanRecords`, an attributed record added by ledger commit Y binds to commit X
  `<commit>`: it is keyed to X, never to Y, and is valid only when X is a strict ancestor of Y,
  X has exactly one parent, and X changes `<path>` against that parent. Otherwise the path gets
  `unexplained <path>: attributed record invalid <X>`. A valid record then counts exactly as a
  same-commit record of X in `packageChain`: X can be the first C point, its pre-C commit is X's
  parent, and the existing `change has multiple records <X>` rule rejects an attributed record for a
  golden X already recorded. Y changes no package path, so it is no point and appears in no report.
- **A3 Excluded set in check mode.** `compare` excludes from the H1 working baseline only packages
  whose chain resolved (`h.packages`); a selected package with a C record but no resolved chain runs
  under H1, so its paths with issues keep their `unexplained` lines and its other goldens report
  `ok … H1` or a true H1 failure, never `extra` by omission. `write-new` keeps excluding every package
  with a C record (M8 unchanged).
- **A4 Ledger line.** One appended line, in its own commit after A1–A3 land:
  `changed internal/oracle/a6/testdata/golden/state/WtMerge/success.yaml C5 7e4e9f37d5f791cd0adab602736a12a0c94dc5ba`.
- **A5 ADR-0219 clarification.** §4: the attributed form is reserved for an omission already merged,
  under a recorded human ruling naming commit and path; first and only authorized use: this correction
  (ruling `2026-10-27T04:41:26Z`); review verifies the ruling; every other change keeps the same-commit
  record. §5: A2 binding and its rejection string. §7: A3. Consequences: residuals (i)–(ii). Status
  notes the clarification. `d24`/`d53`/`d56` text stays.

Preserved (`C5P-preserve`): the UTC golden and C5 driver/assertions; rejection of unexplained missing
and extra files, unrecorded changes, record-only commits (`record without change`), merges, and
unreproduced links; ledger-equals-HEAD and append-only checks; `ChildEnv`, cleanup, flags, exit codes;
D53 storage names; behaviour with no C record.
