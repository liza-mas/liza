## Intent and Allocation

One Must output: a complete A8 oracle package. The fixtures, adapter, driver and goldens form one
deliverable in one owned package. Splitting fixture groups would serialize writers of the common
driver without delivering an independently usable surface. The negative proof belongs to this
deliverable's acceptance, not a separate feature. This plan changes only this file and its adjacent
output JSON; Task 1 owns all implementation files below.

Based on: inherited source spans; D25/D26 and the pinned A8 inventory read in full; the merged
harness plan; current source and command probes below. No new production architecture decision.
The adapter boundary is inherited and absorbs the concrete variation between starting and moved
production APIs. Existing prompts-to-ops coupling is recorded in the issue registry and preserved
by this oracle, not fixed here. No new shared interface is frozen: the A8 architecture's provider
asks are answered by `harness-contract` and `harness-api`; this run has no epic Provider Ask Inventory.

   before state references are resolved. Follow `a8-scope`'s state write/read and public render
   path. Apply `a8-determinism` in full, including EvalSymlinks, fixed state dates, explicit Git
   identity/dates/config, default brand, sequential cases, POSIX skip, gates and T15 initial task.
   Use the harness's path-only replacement operation for the single case root; do not apply its
   general timestamp/identifier/order normalisers to prompt bytes. Fail before comparison on any
   missing marker or wrong W trigger. Include case ID and golden path in failures.
2. Commit the fixtures and driver before golden generation. Use the provider's regeneration
   entry point from the task root under the clean environment, with `-mode write-new -pkg
   ./internal/oracle/a8/...`. It must generate at `96c9ad69aee983ce2b929dd681b6ba43bf920535`
   per `foundation`. Do not set `ORACLE_WRITE` for live checks and do not add ledger records.
   Commit the new goldens; existing goldens are never overwritten to make a test pass.
3. Validate all 30 live renders and starting-tree regeneration with commands 0–2 below. For
   determinism, compare renders materialized in two distinct roots after the single root
   replacement, with no other byte substitutions. Validate missing-golden failure in disposable
   data through the shared harness behavior rather than reimplementing its comparator.
4. Implement the acceptance-mandated one-byte experiment in `TestOraclePromptAlteredGolden`.
   It skips unless `A8_ORACLE_MUTATION_CHECK=1`, and skips on Windows for the inherited reason.
   Clone the committed candidate into a disposable temporary repository with its history,
   preserving the baseline object; never alter the caller's checkout. Change exactly one byte
   of T01's golden there, without changing length, fixtures or production. Run the live
   `TestOraclePrompt` in the clone, then the real regen entry point filtered to A8. Assert both
   return nonzero and identify that golden; a setup/compile error alone is not proof. Use
   explicit child environments from the harness, omit the opt-in variable and `ORACLE_WRITE`,
   and restrict the live child with `-run '^TestOraclePrompt$'`. Thus regeneration's ordinary
   suite skips the mutation helper and cannot recurse. Cleanup on pass and failure. The same
   candidate's untouched positive checks in commands 0 and 2 must pass. This is the only
   intentional golden alteration, confined to the disposable clone.
5. Commit the acceptance manifest and run touched-file pre-commit before the canonical commands.
   Observe the complete boundary in the diff; no tracked change outside A8. Record package
   elapsed time for H7 without adding a timing threshold or new benchmark. Finish with a clean
   worktree and the canonical receipt; full regression commands 5–6 are integration-deferred.
