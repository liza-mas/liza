## Corrected Mechanism

Why package scope: `go test` runs a package, and in a package whose driver a C commit edited,
the working drivers mix C-flipped and unchanged assertions. Only the package's whole oracle tree
from before its first C change can reproduce its pre-C state over starting production (`d56`
R2); every later state is then reproduced at its own commit (`d24`). Per-test selection, driver
reversal or tagged twins would be new mechanisms and are excluded.

Definitions. The *package* of a path under `internal/oracle/` is the prefix before its first
`/testdata/`, else its directory; nested packages (`a2/cli`, `a3/control`) are distinct.
`internal/oracle/PROVENANCE` belongs to no package. *Package paths* of P are its goldens and its
other tracked files (drivers, adapters, fixtures).

- **M1 Records (R1).** `changed <path> <reason>` names a golden, as today, or a non-golden
  package path (clean, under a package below `internal/oracle/`, not under `testdata/golden/`,
  not `PROVENANCE`). Every record must name a path its commit changes (the existing
  record-without-change scan covers both kinds). A driver-only C change records the driver path;
  a C commit that also changes a golden of P may rely on that golden's record (C2's plan does).
- **M2 C package.** A selected package is a C package when HEAD's ledger holds a C1–C6 record
  for one of its paths. Its first C point X is the earliest commit in its path history adding
  such a record; its pre-C commit is X's first parent. Package selection keeps `selected()`
  semantics (exact vs `/...`), applied to the record's package.
- **M3 H1 run.** The working baseline (start + fixes + working overlay, `oraclestart`) runs only
  the selected packages that are not C packages; the regenerator receives the selected patterns
  and the excluded package directories, lists packages with `go list` under the Go `ChildEnv`
  in the materialised tree, and skips `go test` when none remain. Non-C goldens compare as today.
- **M4 Pre-C state (R2).** For each C package, the baseline of its pre-C commit (start + that
  commit's fix records + its oracle and harness trees, tagged; ADR-0219 §7 unchanged) runs that
  package; packages sharing a pre-C commit share one run. The package's goldens committed at the
  pre-C commit must equal the reproduction (same path set, same bytes); otherwise
  `pre-change reproduction differs <sha>`, and a golden first appearing after it is
  `pre-change blob absent <sha>` (unchanged rule). A failing run is the runtime form of the
  `d56` disproof: exit 2 naming the commit, never bypassed.
- **M5 Points (R2).** Every commit after the pre-C commit that changes a package path is a
  point. It must be non-merge (`merge changes golden <sha>` / `merge changes oracle files <sha>`),
  add at least one record for a package path it changes (`change without record <sha>`), and add
  exactly one record for each package golden it adds, modifies or deletes (`change without
  record` / `change has multiple records`). Each distinct point commit runs once, untagged, over
  the C packages it is a point of, and must succeed; the package's goldens committed there must
  equal the reproduction: `change point reproduction differs <sha>` for a differing or
  unreproduced golden, `deletion not reproduced <sha>` for a golden deleted there but still
  produced.
- **M6 HEAD (R3).** Per C package: a working golden equal to HEAD's is `ok`; differing is
  `working tree differs from last change point <sha>`; present at HEAD and absent in the working
  tree is `missing`; present only in the working tree is `extra`; a non-golden package path with
  an uncommitted or untracked change is `unexplained <path>: working tree differs from HEAD`.
  A golden absent at HEAD and in the working tree is accepted only when the last point that
  changed it deleted it, reproduced, under a C1–C6 record; otherwise `missing`. `extra` keeps
  its meaning.
- **M7 Report.** Per C-package golden:
  `ok <golden> chain pre <pre> [<reason> <sha>]…[ deleted]` (links are the points that changed
  it, with its record's reason); per C package: `ok <package> package pre <pre> [<reasons> <sha>]…`
  listing every point with the reasons of the package records it adds (comma-joined). Non-C
  goldens keep `ok <golden> H1`. Existing rule strings stay.
- **M8 write-new.** Creates absent goldens from the M3 run only; never writes into a C package.
- **M9 Unchanged.** Flags, exit codes 0/1/2, ledger-equals-HEAD and append-only checks,
  `ChildEnv` for every child (`go list` included), temporary detached worktrees removed on
  success, failure and cancellation, no ref or live-state change, stdlib-only imports, D53 stored
  golden names, and all behaviour while no selected package has a C record.

Ceilings (fail loud, never a false accept): a golden added after a package's first C point is
`pre-change blob absent` (as today for chained goldens); after the first C point every change to
the package needs a record, and a call-site-only adapter edit there has no fitting reason.
Known writers (RP-6): A9's refactor and C6 precede C3 in the dependency chain; the D53
follow-up's A5 driver portability edits, if they land after C2, each carry a `determinism`
record naming an edited A5 path (M1/M5 support it). Writers beyond the current graph are
unchecked. Upgrade trigger: the first unsupported need; the owner raises a correction.

   first C point is `pre-change blob absent`.
3. *Later points:* C1, then a driver-only C2 point with a driver-path record, then a determinism
   point; each is regenerated at its own SHA and listed in the package line with its reason; a
   point whose reproduction differs, or which leaves a still-committed golden unproduced, fails.

   first C point (`change without record`); merge changing a driver (`merge changes oracle

6. *Scope:* a C record in an unselected package leaves selected packages on H1; a C record in
   `a3/control`-style nested package does not make its parent a C package; write-new writes
   nothing into a C package.
7. *Ledger:* driver and fixture paths accepted; still rejected: unknown golden kind, traversal,
   `PROVENANCE`, paths outside a package, whitespace; errors name the line.
8. *Real sample:* extend the clone pattern of `TestRegenNamesAlteredSampleGolden` in a new test:
