(environment isolation, manifests, path tokens, Git fixtures) and one entry-point run; split by
row, every task would edit or wait on the helper file and pay the full validation (~13 min, P16)

- **D-2 Environment isolation** (AC2, E2, E4, G1.4). `isolateEnv(t, withGit bool) envDirs`
  creates one `t.TempDir()` root with subdirectories `home`, `tmp`, `bin`, `work`; when `withGit`,
  resolves host `git` with `exec.LookPath` before isolating and symlinks it as `bin/git` (the only
  entry of `PATH`, AC2 "fixture-directory link to the host git"); then `t.Setenv` `HOME=home`,
  `TMPDIR=tmp`, `PATH=bin`, `GIT_CONFIG_NOSYSTEM=1`, and clears (`t.Setenv(k, "")` then
  `os.Unsetenv(k)`, so the test restores them) `SHELL`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME`,
  `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_COMMON_DIR`, `GIT_OBJECT_DIRECTORY`,
  `GIT_CONFIG`, `GIT_CONFIG_GLOBAL`. Every row calls it before any adapter, so no producer reads the
  host `HOME` (codex config, pi gate, `os.UserCacheDir`) or host Git config (in-process producers
  run Git through `gitenv`, which inherits the process environment). No test calls `t.Parallel`
  (`arch-a2-crosscut` Isolation). `gitRun(t, env, dir, args...)` runs host Git for fixture setup
  with exactly `oracle.ChildEnv(EnvBase{Home, Path: bin, Tmp}, "GIT_CONFIG_NOSYSTEM=1",
  author/committer name, e-mail and fixed `2026-01-01T00:00:00Z` dates)` (harness D-14); `initRepo`
  is `git init -q --template=<empty dir>` so no host template (sample hooks, `info/exclude`
  comments) enters a repository. Failure messages carry variable names, relative paths and Git exit
  codes, never environment values or command output containing them.
- **D-3 Manifest form.** Text, one line per file, sorted by path bytes, LF, final newline, no
  trailing whitespace (stable under the text pre-commit hooks): with content
  `<mode> <size> <sha256-hex> <path>`; path-set form `<mode> <path>`; `<mode>` four octal digits
  (`0644`); `<path>` slash-separated, relative to the row's root. Stored as kind `artifact`.
- **D-4 Mode determinism.** Writers' modes follow the process umask; `TestMain` fixes it to
  `0o022`, so live runs and entry-point runs record the same modes on any host (P4 shows host
  umask `002`). A-1/A-2 modes come from the source checkout (`RenderedFile.Mode`, stat of the
  tracked file), which Git creates under the checkout's umask (P4: `0664`/`0775` here); their
  manifests record the Git file class instead: `0755` when any execute bit is set, else `0644`.
  This is the only value a checkout preserves and the one `sync-embedded` carries (executable or
  not), so no asserted value is lost.
- **D-5 Path tokens.** `tokenise(b, pairs)` replaces each registered absolute directory, longest
  first, and its `filepath.EvalSymlinks` form, with a token: `<PROJECT>`, `<HOME>`, `<REPO>`.
  It does not apply the harness's system-temporary-directory rule (harness plan D-3): the Codex
  config carries a literal `"/tmp"` writable root (P6) that this rule would turn into `<TMP>` when
  `TMPDIR=/tmp` (live) but not under the entry point's own temporary root (harness plan D-11),
  so the golden would differ between the two runs. Byte goldens are tokenised before
  `oracle.Check(t, oracle.Artifact, …)`, which compares raw bytes (harness plan D-4). Assumption
  (DERIVED from `t.TempDir` name sanitising): disposable paths contain only `[A-Za-z0-9/._-]`, so
  shell quoting inside rendered scripts is the same in every run.
