## Proof Design (Task 1)

All new tests are named `TestC1…` in `_test.go` files of the package they exercise. Each P1-P5 has
a `lease_duration: 600` case and a default case using the existing default/unset configuration path
(`lease_duration` absent or 0 in the fixture state, not 1800 passed to an internal API). Expected
deltas are literals (`600*time.Second`, `1800*time.Second`), independent of the resolver. Bounded
before/after timestamps or a fixed projection time; no sleeping for expiry. Each test must fail if
its single caller is restored to the hard-coded default (the coder records this mutation check per
site in the manifest).

| Proof | Test boundary | Assertion |
|---|---|---|
| P1 Registration | production startup registration path (RunSupervisor's registration step or the extracted helper it calls) against a disposable state + named C6 registration op | agent row `lease_expires - registered_at` = 600 s / 1800 s; stored `terminal` = `"terminal-1"` |
| P2 Heartbeat | heartbeat built by the same startup wiring; publish one beat; read overlaid state | agent lease, owned task lease, and matching active review renewal expire beat-timestamp + 600 s / 1800 s; existing no-active-session and cleared-ownership tests stay green unmodified |
| P3 Reviewer claim | `reviewerStrategy.ClaimTask` through the real typed claim in a disposable project with a claimable submitted task (stub provider/session preflight) | task `review_lease_expires` within [before+D, after+D] |
| P4 Re-review | `AwaitResubmission` early-resubmission path and reservation-held path reaching `reclaimForReview`, with valid boundary/preflight fixtures | fresh `review_lease_expires` within bounds for D = 600 / 1800; existing ownership-loss and boundary-refusal tests unchanged |
| P5 Pool repair | `newReviewerStartPlanner` with fixed `now`, default and per-slot (`models.yaml` slot variants) | every projection row `LeaseExpires = now + D` exactly; input `state.Agents` unchanged (deep-equal before/after) |
| P6 Resolver / terminal | table test: 600 → 600; 0 and -5 → 1800; constant value `"terminal-1"` (also asserted by P1's stored row) | exact values |

Oracles: goldens normalise timestamps (`<TIME>`) and 799 of 804 oracle `lease_duration` fixture
values are 1800 (RP-4), so no golden change is expected. If an oracle asserts the old C1 duration,
change only that assertion/golden and record/reproduce the change point per `d24`; no blanket
regeneration. Existing white-box tests asserting the old hard-coded behaviour (e.g. a test pinning
1800 at a site under a 600 config) change only to the C1 value, listed in the manifest.
