# Architecture Plan: Candidate-Tree Artifact Guard

Status: draft

## Goal

Define the artifact-guard hook that validates protected artifact references against each candidate integration tree before the integration ref advances, while preserving the post-merge artifact validation backstop.

## Context

`MergeWorktree` currently advances the integration ref through `performCASMerge`, syncs files, then re-reads state and calls `statevalidate.ValidateArtifactRefs`. That protects state integrity by rolling back after the ref has already moved. The goal spec adds a pre-update guard over the candidate Git tree so bad candidates are rejected before `UpdateRef`.

This plan composes the two upstream architecture plans: `architecture-1` supplies deterministic artifact-ref collection and owner provenance, and `architecture-2` supplies the opaque `performCASMerge` pre-update hook boundary. This task plans only the artifact policy hook, fresh-state lifecycle, Git tree mode checks, actionable diagnostics, failure confirmation, and retention of the post-merge backstop.

### Constraints

- `performCASMerge` must stay artifact-policy agnostic. It receives only an opaque `func(candidateTreeish string) error` hook.
- The guard must read the latest available blackboard state for every hook invocation; refs must not be captured once before the CAS loop and reused across attempts.
- Candidate checks must require Git object modes `100644` or `100755`. Missing paths, directories, submodules, symlinks, and any non-regular modes are invalid.
- Candidate validation failure must trigger one fresh state re-read and revalidation against the same candidate treeish before returning an artifact error.
- If state cannot be re-read during failure confirmation, the hook fails closed and preserves both the original candidate failure and the state freshness failure.
- The existing post-merge `ValidateArtifactRefs` call remains after successful ref updates.
- `.pre-commit-config.yaml` exists at worktree `HEAD`; no `bootstrap-precommit` output entry is emitted.
- Project guardrail G1.2 applies: this change touches integration, concurrency, and artifact-reference protection invariants. The design preserves CAS ownership in `performCASMerge` and keeps rollback validation as a second line of defense.

## Components

### Candidate Tree Artifact Validator (`internal/statevalidate` plus `internal/git`)

**Responsibility:** Validate a deterministic collection of protected artifact refs against one Git treeish and return stable owner-aware diagnostics for missing or non-regular paths.

**Boundaries:**
- Exposes: a validation boundary that accepts a candidate treeish and collected artifact refs, or an equivalent guard-facing API.
- Depends on: the `statevalidate` collector from `architecture-1` and a narrow Git tree lookup operation.
- Does not depend on: blackboard state loading, CAS retry state, or task lifecycle transitions.

**Key decisions:**
- Put artifact policy with `statevalidate`, because it owns artifact-ref meaning and diagnostics. Put raw Git tree lookup in `internal/git`, because mode extraction is a Git concern.
- Add a narrow Git query such as `TreeEntryMode(treeish, path)` or an equivalent operation backed by `git ls-tree <treeish> -- <path>`. The operation reports missing separately from present-with-mode.
- Treat only `100644` and `100755` as valid artifact file modes. A blob mode of `120000` is rejected as a symlink, and tree/submodule/non-regular modes are rejected with mode-specific diagnostics.
- Validate unique normalized paths for Git lookup efficiency, but preserve all deterministic owners for diagnostics on the failing path.

### Artifact Guard Hook (`internal/ops/wt_merge.go`)

**Responsibility:** Bridge `MergeWorktree` to the candidate validator by creating the pre-update hook passed into `performCASMerge`.

**Boundaries:**
- Exposes: no public CLI or state API; this is `MergeWorktree` wiring.
- Depends on: blackboard read access, `statevalidate.CollectArtifactRefs`, candidate-tree validation, and the `performCASMerge` hook boundary from `architecture-2`.
- Does not depend on: implementation details of `performCASMerge` retries beyond receiving one treeish per hook invocation.

**Key decisions:**
- Construct the artifact guard in `MergeWorktree`, not inside `performCASMerge`, to satisfy NFR-000-4 and FR-001-19.
- The hook reads state inside the callback on every invocation, collects refs from that fresh snapshot, then validates the callback's candidate treeish.
- Hook success is local to that invocation. Any state changes after the hook passes remain covered by the existing post-merge `ValidateArtifactRefs` backstop.

### Failure Confirmation Loop (`internal/ops` or `internal/statevalidate`)

**Responsibility:** Avoid returning stale artifact failures when state no longer protects the failing path, while failing closed if freshness cannot be established.

**Boundaries:**
- Exposes: a small orchestration path used only by the artifact guard hook.
- Depends on: the first candidate validation error, a second blackboard read, a second collection, and revalidation of the same candidate treeish.
- Does not depend on: integration ref staleness detection. That remains `performCASMerge` behavior from `architecture-2`.

**Key decisions:**
- On first candidate failure, re-read state once and revalidate the same candidate treeish against the second snapshot.
- If the second snapshot no longer references the previously failing path and the candidate validates, the hook returns success for that invocation.
- If the second validation still fails, return the second validation failure with deterministic owners from the second snapshot. This reports current state, not stale first-snapshot owners.
- If the state re-read fails, return a composite fail-closed error preserving the first candidate failure and the state freshness error.

### Post-Merge Artifact Backstop (`internal/ops/wt_merge.go` plus `internal/statevalidate`)

**Responsibility:** Keep full-state artifact validation after successful ref update as protection for races outside the hook's snapshot.

**Boundaries:**
- Exposes: existing `ValidateArtifactRefs` behavior after `SyncMergedFiles`.
- Depends on: `bb.Read()` after the merge and statevalidate artifact validation.

**Key decisions:**
- Do not remove or weaken post-merge `ValidateArtifactRefs`.
- Candidate-tree rejection changes the primary protection path for invalid candidates; rollback remains the backstop when state changes after a hook pass or when another invariant fails after ref update.

## Interfaces

### Artifact Guard Hook -> Blackboard State

**Contract:** Each hook invocation reads the latest available state snapshot before collecting protected artifact refs.

**Direction:** The hook calls `bb.Read()` or an equivalent state read. The blackboard does not know about candidate Git trees.

**Invariants:**
- No protected refs are cached across hook invocations.
- State read errors are fail-closed when the guard needs refs to validate a candidate or confirm a failure.

### Artifact Guard Hook -> Artifact Ref Collector

**Contract:** The hook passes the fresh state snapshot and project root to the collector, receiving normalized repo-relative paths with deterministic owner provenance or a fail-closed invalid-ref error.

**Direction:** The hook calls `statevalidate`; the collector does not call back into ops.

**Invariants:**
- Invalid refs from the collector reject the candidate before ref advancement.
- Diagnostics include the invalid value or normalized path and deterministic owner provenance.

### Candidate Tree Artifact Validator -> Git Tree Query

**Contract:** For each protected normalized path, the validator asks Git whether the candidate treeish has that path and which object mode it has.

**Direction:** `statevalidate` or the validator calls `internal/git`; Git returns path presence and mode without artifact policy.

**Invariants:**
- Missing path is distinguishable from a present path with an invalid mode.
- Only modes `100644` and `100755` satisfy artifact liveness.
- Path values passed to Git are collector-normalized repo-relative paths.

### MergeWorktree -> performCASMerge

**Contract:** `MergeWorktree` passes the artifact guard hook into `performCASMerge`; `performCASMerge` invokes it with each candidate treeish before `UpdateRef`.

**Direction:** `MergeWorktree` assembles policy; `performCASMerge` owns CAS sequencing and treats hook errors opaquely.

**Invariants:**
- Already-merged no-op paths skip the hook per `architecture-2`.
- Fast-forward and true-merge attempts validate the candidate treeish for that attempt.
- Post-merge `ValidateArtifactRefs` remains after successful `performCASMerge`.

## Data Flow

```text
MergeWorktree
  -> create artifact guard hook with projectRoot, statePath/blackboard, and Git wrapper
  -> performCASMerge(..., artifactGuardHook)
     -> compute candidate treeish for current CAS attempt
     -> artifactGuardHook(candidateTreeish)
        -> read latest state snapshot
        -> CollectArtifactRefs(snapshot, projectRoot)
        -> ValidateCandidateArtifactRefs(candidateTreeish, refs)
           -> git ls-tree candidateTreeish -- normalizedPath
           -> accept mode 100644 or 100755
           -> reject missing, tree, submodule, symlink 120000, or any non-regular mode
        -> on failure:
           -> re-read state snapshot
           -> recollect refs
           -> revalidate same candidateTreeish
           -> return success only if second snapshot validates
           -> fail closed if re-read fails, preserving both errors
     -> UpdateRef only after hook success
  -> SyncMergedFiles
  -> read current state
  -> statevalidate.ValidateArtifactRefs(currentState, projectRoot)
  -> integration tests and final task transition
```

## Cross-Cutting Concerns

| Concern | Approach |
|---------|----------|
| Error handling | Candidate validation returns artifact-specific errors with path, mode or missing cause, and owners. State read failures while collecting or confirming failures are fail-closed. Composite freshness errors preserve the original candidate failure. |
| Observability | Error text and safe details are deterministic enough for tests: invalid path, cause, mode when present, and at least one owner including task ID and field when applicable. No new logging is required in `performCASMerge`. |
| Configuration | No new configuration. The guard uses the existing project root, state path, integration branch, and Git wrapper available to `MergeWorktree`. |
| Concurrency | `performCASMerge` continues to own integration ref staleness and CAS retries. The guard owns only state-snapshot freshness for artifact refs. Hook pass does not bypass CAS update checks. |
| Security | The guard checks only collector-normalized repo-relative paths. It does not read credential files directly and rejects unsafe refs through the collector. |
| Testing | Unit tests cover Git tree mode classification and owner diagnostics. Ops tests cover hook state loading, second-snapshot confirmation, fail-closed re-read errors, fast-forward and true-merge pre-update rejection, and post-merge backstop retention. |

## Structural Decisions

### Decision 1: Keep Artifact Policy Out Of `performCASMerge`

The guard is built by `MergeWorktree` and passed as the opaque pre-update hook planned by `architecture-2`.

**Rationale:** This satisfies NFR-000-4, FR-001-19, and NFR-001-2. `performCASMerge` keeps CAS and staleness ownership without importing statevalidate or blackboard semantics.

### Decision 2: Validate Git Tree Modes, Not Working Tree Paths

Candidate validation checks the candidate treeish with `git ls-tree` or an equivalent wrapper, requiring mode `100644` or `100755`.

**Rationale:** The guard must decide before integration ref advancement, and the candidate may not exist in the working tree. Git tree modes directly distinguish missing paths, directories, submodules, symlinks, and regular files.

### Decision 3: Read State Inside Every Hook Invocation

The artifact guard reads state after `performCASMerge` computes the current candidate treeish and invokes the hook.

**Rationale:** FR-001-12 requires the latest available state for each hook invocation. Capturing refs once before the CAS loop would validate retries against stale state.

### Decision 4: Confirm Candidate Failures With One Fresh Snapshot

On candidate validation failure, the hook re-reads state, recollects refs, and revalidates the same candidate before returning an artifact error.

**Rationale:** FR-001-14 and FR-001-15 avoid rejecting a candidate for a path no longer protected by current state, while still ensuring the candidate is valid against the second snapshot before proceeding.

### Decision 5: Fail Closed When Freshness Cannot Be Verified

If the second state read fails, the hook returns a composite error that preserves the candidate-tree failure and reports the failed freshness check.

**Rationale:** FR-001-16 requires state re-read errors to block the merge, because the system cannot prove the first artifact failure is stale.

### Decision 6: Retain Post-Merge Validation

The existing post-merge `ValidateArtifactRefs` call remains after successful `performCASMerge`.

**Rationale:** FR-001-13 and FR-001-28 require races after hook success to remain covered. The pre-update guard becomes the primary protection for candidate-invalidating commits, not the only protection.

- `internal/git`: focused tests for the new tree path mode query over missing paths, regular files, executable files, directories, symlinks, and submodules where feasible.
- `internal/statevalidate`: tests for candidate tree validation over collected refs, deterministic owner diagnostics, invalid collector errors, and regular-file mode enforcement.
- `internal/ops`: tests for artifact guard hook state loading, failure confirmation, fail-closed state read errors, and `MergeWorktree` wiring through `performCASMerge`.

### Scope 1: Candidate Tree Artifact Path Validator

**Component(s):** `internal/statevalidate`, `internal/git`, `internal/gitenv`, and focused tests in `internal/statevalidate` and `internal/git`.

**Boundary:** Plan the code changes that add a Git tree path query for candidate treeish validation, validate collected artifact refs against candidate Git object modes, require regular file modes `100644` or `100755`, reject missing paths and non-regular modes, and produce deterministic owner-aware diagnostics. Out of scope: `MergeWorktree` hook wiring, latest-state reads per invocation, second-snapshot confirmation, CAS retry behavior, and post-merge rollback behavior.

**Done when:** A code plan is ready for implementation that, when implemented, can validate protected artifact refs against a candidate Git treeish using a Git tree query; accepts only modes `100644` and `100755`; rejects missing paths, directories, submodules, symlinks with mode `120000`, and other non-regular modes; emits deterministic diagnostics naming the invalid path, cause, mode when present, and owner provenance; and includes tests for FR-001-8 through FR-001-11 and AC-001-1 through AC-001-8 plus AC-001-16 at the validator boundary.

**Depends on:** Existing task `architecture-1-code-planning-0`.

### Scope 2: MergeWorktree Artifact Guard Freshness And Backstop

**Component(s):** `internal/ops/wt_merge.go`, `internal/ops/wt_merge_test.go`, `internal/statevalidate` guard-facing API, and existing post-merge validation path.

**Boundary:** Plan the code changes that wire the candidate artifact validator into `MergeWorktree` through the `performCASMerge` pre-update hook, read the latest state for each hook invocation, collect refs from that snapshot, confirm candidate validation failures with one second state snapshot against the same candidate treeish, fail closed when confirmation state cannot be re-read, and retain the post-merge `ValidateArtifactRefs` backstop. Out of scope: collector normalization/provenance internals, the `performCASMerge` hook contract mechanics already covered by `architecture-2`, and submit-for-review diagnostics.

**Done when:** A code plan is ready for implementation that, when implemented, makes `MergeWorktree` pass an artifact guard hook into `performCASMerge`; the hook reads fresh state on every invocation, validates that snapshot's protected refs against the provided candidate treeish, re-reads state and revalidates the same candidate after any candidate-tree failure, returns success when the second snapshot no longer protects the failing path and validates, fails closed with a composite diagnostic when confirmation state cannot be read, and leaves the post-merge `ValidateArtifactRefs` rollback backstop in place; tests cover FR-001-12 through FR-001-16, FR-001-28, AC-001-9, AC-001-10, and AC-001-15, plus pre-update rejection before ref advancement for fast-forward and true-merge flows.
