# Architecture Plan: Artifact Ref Collection And Provenance

Status: draft

## Goal

Define the reusable statevalidate artifact-ref collection boundary so both existing state validation and the candidate-tree guard can use normalized repo-relative refs with deterministic owner provenance.

## Context

`statevalidate.ValidateArtifactRefs` currently traverses goal, task, and `output[]` artifact fields inline, strips fragments locally, accepts absolute paths for filesystem checks, and reports one field/task pair at a time. The goal spec requires that traversal to become reusable before candidate-tree validation can report stable, actionable diagnostics. This plan covers the collector, normalization rules, invalid-ref failures, provenance model, deterministic ordering, and reuse by `ValidateArtifactRefs`.

The CAS hook boundary is already planned separately by `architecture-2` in `specs/arch-plan/20260520-artifact-ref-protection/20260520-024522-architecture-2.md`. This plan intentionally does not move the integration ref, inspect Git tree object modes, or implement the `MergeWorktree` hook wiring.

### Constraints

- `ValidateArtifactRefs` must keep running after successful ref updates as the post-merge backstop.
- The collector must live in or be exposed by `internal/statevalidate`; consumers outside `statevalidate` should not duplicate the artifact field traversal.
- The collector must fail closed for refs that cannot be safely mapped to one repo-relative Git path.
- Candidate-tree mode validation belongs to a later guard scope; this scope supplies normalized paths and provenance, not Git tree object policy.
- `.pre-commit-config.yaml` exists at worktree `HEAD`; no `bootstrap-precommit` output entry is emitted.
- Project guardrail G1.2 applies: the change intersects race-condition and integration-branch protection invariants, so the design preserves CAS merge ownership and the post-merge rollback backstop.

## Components

### Artifact Ref Collector (`internal/statevalidate`)

**Responsibility:** Traverse every protected artifact field in a `models.State`, normalize each non-empty ref to a repo-relative file path, attach owner provenance, and return a deterministic collection or an invalid-ref error.

**Boundaries:**
- Exposes: a public collector such as `CollectArtifactRefs(state *models.State, projectRoot string) ([]ArtifactRef, error)` or equivalent.
- Depends on: `models.State`, existing artifact field names, and path helpers for fragment stripping and safe repo-relative normalization.

**Key decisions:**
- The collector takes `projectRoot` or equivalent repository context because FR-001-7 requires existing valid absolute refs to be converted to repo-relative paths when they point inside the repository.
- The collector returns one `ArtifactRef` per state field owner, rather than grouping by path, so duplicate references preserve full provenance without losing ordering.
- Empty artifact fields are ignored; non-empty refs that normalize to no safe path are errors.

### Artifact Ref Provenance Model (`internal/statevalidate`)

**Responsibility:** Represent the state owner of each artifact ref in a deterministic, diagnostic-friendly form.

**Boundaries:**
- Exposes: owner metadata containing field name, owning task ID when applicable, and output index when applicable.
- Depends on: no Git operations and no merge lifecycle state.

**Key decisions:**
- Owner field names are canonical strings from state shape: `goal.spec_ref`, `spec_ref`, `epic_ref`, `plan_ref`, `arch_ref`, and `output[N].<field>` or the equivalent structured field plus index.
- Goal-level refs have no task ID and no output index; task-level refs have task ID and no output index; output refs have task ID and output index.
- Sorting uses path first, then owner metadata in a stable order: task ID, output index presence/value, and field name. Goal owners sort predictably with empty task ID and absent output index.

### Artifact Ref Normalization (`internal/statevalidate` with `internal/paths`)

**Responsibility:** Convert a raw artifact ref string into the exact repo-relative file path that Git tree validation can check.

**Boundaries:**
- Exposes: normalized path and original ref value on collected refs; invalid inputs return actionable errors.
- Depends on: fragment stripping, repository root containment checks, and cross-platform absolute-path detection.

**Key decisions:**
- Fragment stripping happens before filesystem or Git tree checks: `specs/a.md#section` becomes `specs/a.md`.
- Semicolon-joined refs fail before path checks; scalar artifact fields do not accept delimiter-joined multi-refs.
- Fragment-only refs such as `#section`, empty strings after fragment stripping, `.` after cleaning, path traversal outside the repository, and absolute paths outside `projectRoot` fail closed.
- Absolute refs under `projectRoot` are converted to slash-separated repo-relative paths. Absolute refs outside `projectRoot`, including cross-platform absolute forms, are rejected with diagnostics that include the original value and owner.
- Existing `paths.SplitRefFile` should be reused for fragment stripping. `paths.NormalizeSpecRef` is not the authoritative collector normalizer because it deliberately preserves unsafe values for later validation.

### Artifact Ref Diagnostics (`internal/statevalidate`)

**Responsibility:** Produce stable errors for invalid refs and missing artifacts that include the normalized or invalid path plus deterministic owner provenance.

**Boundaries:**
- Exposes: error values compatible with current `ArtifactRefError` classification, with enough structured detail for JSON-safe diagnostics.
- Depends on: collected `ArtifactRef` and owner metadata.

**Key decisions:**
- Existing `ArtifactRefError` behavior should remain recognizable for current callers and tests, but it can be extended or paired with a new aggregate error when multiple owners share one failing path.
- Missing-file diagnostics from `ValidateArtifactRefs` should use the collected normalized path and owner metadata instead of the raw traversal field.
- Invalid-ref diagnostics should distinguish causes such as `multiple_refs_not_supported`, `empty_ref_path`, `path_traversal`, and `absolute_path_outside_repo` or equivalent stable cause strings.
- Error text remains deterministic and safe for test assertions; structured `SafeDetails` should include field, value, path when available, cause, task ID, and output index when available.

### Existing Artifact Ref Validator (`internal/statevalidate.ValidateArtifactRefs`)

**Responsibility:** Keep the post-merge backstop while reusing the collector as the single source of artifact traversal and normalization.

**Boundaries:**
- Exposes: same `ValidateArtifactRefs(state, projectRoot)` call shape unless code-planning finds a smaller compatible extension is necessary.
- Depends on: `CollectArtifactRefs`, filesystem `os.Stat`, and existing integration-branch Git fallback.

**Key decisions:**
- `ValidateArtifactRefs` calls the collector once, then checks each collected repo-relative path against the project working tree and, for missing disk paths, the configured integration branch.
- The integration-branch fallback uses the normalized repo-relative path only; raw absolute refs are never passed to Git pathspecs.
- The post-merge validator remains a backstop. It should not gain knowledge of `performCASMerge` or CAS retry behavior.

## Interfaces

### `statevalidate` Consumers -> Artifact Ref Collector

**Contract:** Consumers pass a state snapshot and repository root context, and receive a deterministic slice of normalized artifact refs or a fail-closed invalid-ref error.

**Direction:** `ValidateArtifactRefs` and the future candidate-tree guard call the collector; the collector does not call merge or blackboard operations.

**Invariants:**
- Every returned `ArtifactRef.Path` is repo-relative, fragment-free, non-empty, and safe to pass as a Git tree path.
- Every returned ref has owner provenance with field name and, when applicable, task ID and output index.
- Returned slice order is stable across Go map/slice iteration and independent of task insertion side effects except for explicit owner sort keys.

### Artifact Ref Collector -> Path Helpers

**Contract:** The collector uses path helper behavior for splitting fragments and determining whether a path is absolute or repo-contained.

**Direction:** The collector calls helper functions; helpers remain generic and do not know about state owners.

**Invariants:**
- Unsafe worktree-prefix normalization remains rejected downstream if it cannot produce a safe repo-relative path.
- Path cleaning must not turn an invalid escape into an accepted in-repo path.

### `ValidateArtifactRefs` -> Artifact Ref Collector

**Contract:** `ValidateArtifactRefs` obtains the full protected ref set from the collector and performs only existence checks over those normalized refs.

**Direction:** `ValidateArtifactRefs` calls the collector, then filesystem/Git fallback checks.

**Invariants:**
- Inline goal/task/output traversal is removed from `ValidateArtifactRefs`.
- Existing callers still get an error on the first invalid or missing artifact ref.
- Post-merge validation still runs from `MergeWorktree` after successful `performCASMerge`.

### Future Candidate-Tree Guard -> Artifact Ref Collector

**Contract:** The guard can consume collector output and report invalid candidate paths with the collector's owner metadata.

**Direction:** Future guard scope calls the collector for state snapshots and checks paths against a candidate treeish.

**Invariants:**
- The collector does not inspect Git tree modes.
- Candidate-tree guard errors can name both the invalid path and deterministic owner provenance without re-traversing state.

## Data Flow

```text
State snapshot
  -> CollectArtifactRefs(state, projectRoot)
     -> visit goal.spec_ref
     -> visit each task spec_ref, epic_ref, plan_ref, arch_ref
     -> visit each output[] spec_ref, epic_ref, plan_ref, arch_ref
     -> for each non-empty raw ref:
        -> reject semicolon-joined scalar values
        -> strip #fragment
        -> reject empty / traversal / unsafe absolute refs
        -> convert valid absolute in-repo refs to repo-relative paths
        -> attach owner metadata
     -> sort by normalized path and owner metadata
  -> ValidateArtifactRefs
     -> os.Stat(projectRoot/path)
     -> if missing on disk, git cat-file -e integration:path
     -> return stable owner-aware diagnostic on first failure

Future flow:
State snapshot -> CollectArtifactRefs -> candidate-tree guard -> git ls-tree treeish -- path -> owner-aware rejection
```

## Cross-Cutting Concerns

| Concern | Approach |
|---------|----------|
| Error handling | Invalid refs fail closed during collection. Missing artifacts fail during validation with the collected owner metadata. Existing `ArtifactRefError` compatibility is preserved where practical. |
| Observability | Diagnostics include path, cause, field, task ID, and output index in deterministic order; no new logs are required for this collector scope. |
| Configuration | No new configuration. The integration branch is still read by `ValidateArtifactRefs` from state config. |
| Determinism | Collector output and diagnostics sort by normalized path and owner metadata; tests should assert exact order. |
| Security | Paths are normalized to repo-relative Git paths before Git calls. Absolute paths outside the repo and traversal attempts are rejected rather than checked. No credential files are read. |
| Testing | Statevalidate unit tests cover collection, normalization, invalid refs, ordering, provenance, and `ValidateArtifactRefs` reuse. A narrow ops regression can verify post-merge artifact diagnostics still include task provenance. |

## Structural Decisions

### Decision 1: Make Collection A Statevalidate API

The reusable collector belongs in `internal/statevalidate` and is the only component that knows which state fields are protected artifact refs.

**Rationale:** The existing traversal already lives in `statevalidate`, and FR-001-1 plus FR-001-5 require reuse rather than duplicating traversal in the merge guard.

### Decision 2: Normalize To Repo-Relative Paths At Collection Time

The collector returns only repo-relative, fragment-free paths. Existing absolute refs are converted only when they are inside `projectRoot`; all other absolute refs are invalid.

**Rationale:** Candidate-tree validation can only check paths inside a Git tree. Returning normalized paths from the collector prevents each consumer from making its own path-safety decision.

### Decision 3: Preserve One Ref Per Owner

The collector returns one item per referenced state field instead of one item per unique path.

**Rationale:** FR-001-3 and FR-001-11 require owner provenance. Keeping per-owner entries makes diagnostics deterministic and lets downstream validation decide whether to report the first owner or all owners for a failing path.

### Decision 4: Treat Unsafe Normalization As A Collection Error

Semicolon-joined refs, fragment-only refs, traversal outside the repository, and absolute paths outside `projectRoot` are invalid collection results, not missing files.

**Rationale:** These values cannot be checked safely against a candidate Git tree, so FR-001-6 requires fail-closed behavior before tree validation.

### Decision 5: Keep `ValidateArtifactRefs` As A Consumer, Not A Second Traversal

`ValidateArtifactRefs` should call the collector and focus on existence checks over collected repo-relative paths.

**Rationale:** This directly satisfies FR-001-5 and keeps future changes to artifact-ref fields localized to one traversal.

## Validation And Test Strategy

### Unit Test Targets

- `internal/statevalidate/validate_specref_test.go` or a new focused statevalidate test file for collector behavior.
- `internal/statevalidate/validate.go` tests around `ValidateArtifactRefs` reuse and diagnostics.
- `internal/paths/normalize_test.go` only if code-planning chooses to expose or extend generic path helpers.
- Existing `internal/ops/wt_merge_test.go` post-merge rollback test remains as a non-regression for owner-aware diagnostics.

### Required Test Cases

| Requirement | Test strategy |
|-------------|---------------|
| FR-001-1 | Compile-time and unit-test use of `CollectArtifactRefs` from outside the collector implementation. |
| FR-001-2 | Collector strips `#fragment` from goal, task, and output refs and returns fragment-free repo-relative paths. |
| FR-001-3 | Collector returns field, task ID, and output index provenance for task and `output[]` refs; goal refs omit task and output metadata deterministically. |
| FR-001-4 | Table test with intentionally unordered paths/tasks/outputs asserts exact sorted collector output by path and owner metadata. |
| FR-001-5 | `ValidateArtifactRefs` test proves one collector call path covers goal, task, and output refs; no separate traversal remains in the validator. |
| FR-001-6 | Invalid-ref tests cover semicolon-joined refs, `#fragment` with empty path, path traversal outside the repo, and unsafe absolute paths; each returns a fail-closed diagnostic. |
| FR-001-7 | Absolute path inside `projectRoot` normalizes to repo-relative path; absolute path outside `projectRoot` is rejected with actionable owner diagnostics. |
| FR-001-11 | Missing or invalid artifact diagnostics include the invalid normalized path or original invalid value plus deterministic owner metadata, including task ID and field when applicable. |

### Non-Regression Checks

- Existing semicolon validation tests continue to pass with the new collector-backed error path.
- Existing worktree-prefix validation in `validate_task.go` remains intact.
- Existing `TestMergeWorktree_RejectsDeletingReferencedArtifact` still fails post-merge and rolls back until the candidate-tree guard scope changes it to a pre-update rejection.
- `go test ./internal/statevalidate ./internal/paths ./internal/ops` should exercise the directly affected packages once implementation exists.

## Decomposition

Each scope becomes a code-planning child task.

### Scope 1: Statevalidate Artifact Ref Collector And Provenance

**Component(s):** `internal/statevalidate`, `internal/paths`, `internal/models` artifact-ref field consumers, and existing post-merge validation call sites.

**Boundary:** Plan the code changes that expose a reusable statevalidate artifact-ref collector, normalize refs to safe repo-relative fragment-free paths, return deterministic owner provenance for goal/task/output artifact refs, fail closed for invalid refs that cannot be checked safely against a Git tree, and update `ValidateArtifactRefs` to consume the collector. Out of scope: `performCASMerge` hook mechanics, candidate Git tree mode checks, integration ref advancement, and state freshness retry semantics.

**Done when:** A code plan is ready for implementation that, when implemented, exposes a reusable collector from `internal/statevalidate`; returns normalized repo-relative fragment-free paths; includes owner provenance with field name, task ID when applicable, and output index when applicable; sorts output by path and owner metadata; rejects semicolon-joined refs, empty paths after fragment stripping, path traversal outside the repo, and unsafe absolute paths with actionable diagnostics; normalizes valid absolute in-repo refs or rejects unsupported absolute refs with owner diagnostics; and makes `ValidateArtifactRefs` use the collector. The plan includes tests for FR-001-1 through FR-001-7 and FR-001-11.

**Depends on:** None.
