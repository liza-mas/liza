## Goal

Freeze the observable behaviour of A6 (worktree create/delete/merge, external-merge reconciliation,
integration reconciliation and recovery, deferred validation, run-live, task-worktree index refresh)
in one oracle suite whose goldens come from the starting commit, before Scope 15 refactors A6.

## Design Decisions

- **D1 One package, one scope.** All cases live in `internal/oracle/a6` (tree convention,
  `s0-harness`): they share one fixture builder and one determinism layer, and the adapter rule
  confines non-stdlib imports to adapter files of the driver's own package. One code-planning scope;
  its planner may split coding units by surface group behind a first unit that lands the shared
  fixture builder.
- **D2 Zone-class timestamps (C5).** Children run under `TZ=Etc/GMT-2` (fixed `+02:00`, no DST,
  Probe A7). Goldens erase every instant but keep its zone class (`Z` or the numeric offset), so the
  C5 task changes exactly two zone tokens per merge state golden, and any other timestamp that
  changes zone fails. Rejected: running under UTC (local and UTC indistinguishable, C5 invisible).
- **D3 Unix only.** Drivers skip on Windows with a logged reason: Go ignores `TZ` there (A7), the
  deferred-validation runner refuses there (A11), and shell and path behaviour differ; the goldens
  record Unix behaviour, which E1 proof exercises. Windows A6 behaviour stays with existing tests and
  area-boundary CI. A Unix host where `Etc/GMT-2` does not load fails the suite naming the zone
  (never a silent UTC fallback).
- **D4 Committed fixtures, not `init`.** A fixture project is a disposable Git repository built by
  driver code plus committed `.liza` inputs (state and pipeline files) under `testdata/fixtures/`
  (E5). Rejected: driving `init` (A14: needs providers and a pre-commit config, and couples A6
  goldens to A7 and C4).
- **D5 Reconciliation through a helper process.** `ReconcileIntegrationAnalyses` has no CLI (A5); an
  adapter calls it in a re-executed test binary with the same explicit environment as CLI runs, so no
  host variable reaches it (E4, G1.4).
- **D6 Simulated runner.** `settle`, `abort` and `run_locked` cases hold the runner lock from the
  test through an adapter and write the batch record as fixture state (A12), so no concurrent batch
  and no sleep are needed (AC2, AC3).

#### CONTRACT

**Cases.** Exactly the Surface Inventory rows of this document, with the listed kinds and test
names; a row's principal refusal, where the inventory leaves it open, is the first precondition
refusal the operation reaches with well-formed flags at the starting commit, named in the plan.
Goldens are created only by the entry point's `write-new` mode from the starting commit (E5), never
by live tests.

**Invocation.** CLI cases run the CLI the harness builds from the tree under test; integration
reconciliation runs in a re-executed test binary through an adapter. Every run gets an explicitly
built environment: the harness environment plus `TZ=Etc/GMT-2`, `GIT_CONFIG_NOSYSTEM=1`, and per
case only the agent identity and index gates it needs. A CLI golden records the exit code with the
output: json mode as a wrapper object holding `exit_code` and the parsed stdout document; human mode
as a transcript of exit code, stdout and stderr with stdlib-log-formatted lines removed (log lines
are free, `goal-frozen`). Mutating cases run each mode on a fresh fixture copy.

**Fixtures.** A fixture project is a disposable Git repository (repo-local identity, integration
branch, task branches and worktrees built by driver code) plus committed `.liza` inputs valid at the
starting commit, with tokens for SHAs and paths filled at setup. Fixture timestamps are fixed
literals: history in the past, leases and expiries far in the future. Setup may call other
commands only to record inputs that have no file form (`provision --record --file` for R1).
Invariants checked by the driver: no effective deferred command in merge and reconcile fixtures,
no installed index script, and no deferred-validation runner directory after those cases (AC3).

**Determinism** (A6 layer, stdlib only, before the harness normalisers): instants replaced by a
token that keeps the zone class (`Z` or numeric offset, D2); 40-hex SHAs replaced by stable tokens
(fixture-known commits by name, others by first appearance); text that Git itself prints (merge
conflict and checkout messages) replaced by a placeholder; durations and process IDs replaced by
tokens. Where the harness already provides one of these, the harness's is used.

**Platforms** (D3). Each driver skips on Windows with a reason naming the platform gate; on Unix it
fails, naming `Etc/GMT-2`, if that zone does not load.
