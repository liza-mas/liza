## Foundation Decisions

- **Starting commit** = `96c9ad69aee983ce2b929dd681b6ba43bf920535` (D23: "the head after this
  commit", the commit that synced the embedded copy). Its production tree equals integration HEAD
  (Q3). It replaces master ASM-003's provisional `112ccec9c`, as that assumption foresaw.
- **E0 hold reading**: D23, a recorded human ruling, supersedes E0's branch name; the hold compares
  the configured `IntegrationBranch` with `global-refactoring` and is satisfied (Q1). E0's text is
  not edited (D23).
- **Data as Go declarations in a test-only package**: type-checked and gofmt-formatted with no
  parser to maintain (K5); test-only keeps FC1.
- **Start snapshot as ratchet ceiling**: without it a new or renamed offender could be added to
  ratchet data and pass; the snapshot makes "no new entry", "no ceiling above its starting value"
  and "not moved or renamed while over threshold" (`goal-success` S1) mechanical. It does not see
  history: a ceiling lowered and later raised again, still within its starting value, passes the
  guard, so monotonic shrink between lowered values stays a review check of ratchet-data diffs
  (SI-2 binds reviewers).
- **Parse-based import analysis**: every non-test file regardless of build constraints, so the
  union across GOOS is checked without a `go list` subprocess (Q6: same result at start).
- **Adapter pairs by build tag**: regeneration needs driver code that compiles against the
  starting tree while live suites follow moved APIs; tags keep both in the tree without history
  lookups, and splitting only at the first call-site-only edit avoids duplicating every adapter.
- **C-changed goldens (H1 with E5)**: settled by the human in D24 (`dec-d24`), option (a′),
  which is the authority for this reading of H1 and E5. A golden never changed by a C task is
  reproduced as H1 states. A golden changed by a C task is proven by a chain: its pre-change blob
  is reproduced from the starting baseline, and every later commit that changes its blob is a
  change point reproduced at that commit in a temporary detached worktree; the current blob must
  equal the last reproduced one. Every value is reproduced from a named commit. Two local
  refinements, both needed for D24's "current blob equals the last reproduced one" to hold:
  - change points after the first C change also include determinism-only and urgent-fix commits
    that change that golden (each reproduced at its commit like a C change), so neither needs a
    separate rule or a block;
  - the pre-change blob is reproduced with the oracle tree of the commit just before the first C
    change, so it is byte-exact under the normaliser that produced it.
  Ledger records name a golden and a reason, never a commit; the change point is the commit that
  adds the record and changes the golden, found from Git history (Q14), so a record never names
  its own commit and survives the rebase of its task branch (closes review R3). Rejected per D24:
  chaining without reproduction at the change point; starting-tree backports.

**Boundary:** In: everything listed; the E0 and OQ-003 hold checks. Out: K4 rules and layer data

**Done when:** `go test ./internal/testguard/archguard/` and `make lint` pass at integration HEAD

**Depends on:** none. **Priority:** Must.

#### CONTRACT

**Holds.** The run's first coding task. Before submission it confirms that the configured
`IntegrationBranch` is `global-refactoring` with D23 present at integration HEAD (D23 supersedes
E0's branch name) and that `make sync-embedded` leaves the tree clean; if either fails it marks
BLOCKED with `--human-action` naming the options of `arch-e0`.

**Package.** `internal/testguard/archguard/`, test-only (all `_test.go`), stdlib only. It locates
the repository from its own source file and reads the module path from `go.mod`. It provides to
later guard files of the package: enumeration of production Go files under `cmd/` and `internal/`
with the S1 exclusions applied and `testdata` skipped, parsed files, and the per-area data. A lint
target running the whole package with `-count=1` is added to `lint-nosync` (CI's lint lane), so
`make lint` runs it and later guards need no `Makefile` edit; `make test` runs it via `./...`.

**Data.** One file per area, `A1`…`A9`, each declaring one area value with four sections: layer
entries and allowlist entries (left empty here; Scope 2 fills them), ratchet entries and S2
exceptions. One guard-owned file lists the nine values; written here, never edited later. Keys:
file = repo-relative slash path; function = file + receiver-qualified name (`Type.Method`, type
parameters dropped), with a declaration ordinal when a name repeats in a file. Ratchet entry = key
+ ceiling lines. S2 entry = key + category (`table`, `registration`, `generated`, or a reference to
the human ruling for any other) + rationale; S2 data starts empty. A start snapshot (key → lines,
all S1 offenders at the starting commit `96c9ad69aee983ce2b929dd681b6ba43bf920535`) is written here
and never edited; it is part of the run baseline record (`arch-files`). Initial ratchet data equals
the snapshot, each entry in the file of the area owning it (`arch-areas`).

**S1 invariants.** Measurement and thresholds per S1 (`goal-success`), thresholds as named
constants. Every current offender is ratchet-listed with measured ≤ ceiling, or S2-listed; every
ratchet key is in the snapshot with ceiling ≤ its snapshot value and is still over threshold (else
stale: remove it); every S2 key is still over threshold; no key appears twice across lists or
areas. The guard does not see history: a ceiling raised back up within its snapshot value passes,
so the ADR names review of ratchet-data diffs as the remaining shrink check. All violations are reported in one run, naming key, measured value, limit and the area file
to change; never environment values.

**ADR.** One ADR, next free number, with its index row: the guard package, the per-area data seam
and its writers (`arch-files`), the snapshot ceiling, and the SI-1 layer rule and allowlist
discipline that Scope 2 enforces.

#### CONTRACT

Uses Scope 1's package helpers and area data shape. Imports are read by parsing every non-test
`.go` file regardless of build constraints (union across GOOS); a directory with no non-test file
has no production package. Only module-internal imports are classified.

**Layer data.** Every production package under `cmd/` and `internal/` gets exactly one layer of
`arch-layers`, in the file of the area containing it (`arch-areas`); `internal/ops` in A3's file,
`internal/agent` in A9's, `internal/prompts/rolebudget` (test-support) in A8's. A fixed exempt set
in the guard covers `internal/testhelpers/**`, `internal/testguard/**`, `internal/integration`,
`internal/prompts/promptbench`. New packages are added later by the creating area.

**K4 invariants.** R1–R7 of `arch-layers` are evaluated; each violating edge must match an
allowlist entry carrying importer, imported, owner scope and rationale (all non-empty); R8: an
unmapped production package fails; an allowlist entry whose edge no longer exists or no longer
violates, and a layer entry for a package that no longer exists, fail as stale; a package mapped
twice fails. All violations are reported in one run with the rule ID and the area file to change.

`Makefile`, production Go.
**Done when:** the entry point run at integration HEAD materialises starting commit `96c9ad69a`,
reproduces both sample goldens and exits 0, and exits non-zero naming the file when a sample golden
is altered; its tests run on a disposable Git repository whose history is made by the recording
workflow (each golden change committed with its own `changed` record, task branches merged with
`--no-ff`, one rebased before merge) and pass an unchanged golden, a one-change and a two-change C

from the starting baseline; no ledger record names a commit SHA other than `start` and `fix`;
`make test` runs the sample green.
**Depends on:** Scope 1. **Priority:** Must.

#### CONTRACT

**Harness** (`internal/testhelpers/oracle/`): stdlib only and no import from this module (FC2), so
it compiles against the starting tree. Provides normalisers (timestamps including local offsets,
temporary paths, ordering, volatile identifiers), comparators per surface kind, golden read and
compare, a write mode, and a helper that builds the CLI from the tree under test once per test
binary into a temporary directory and runs it in a disposable project directory with an explicitly
built environment (no host inheritance; G1.4, E4).

**Tree convention (H2).** Oracle suites are test-only packages `internal/oracle/a<N>/**` for the
area owning the surface (`arch-oracle-template`), plus `internal/oracle/sample/` owned here.
Goldens under each package's `testdata/golden/<kind>/`, inputs under `testdata/fixtures/`; `<kind>`
∈ `prompt`, `artifact`, `json`, `human`, `state`; oracle tests are named `TestOracle…`. Discovery is
the path `./internal/oracle/...`; no registry. In live mode `go test` compares the current tree
with committed goldens; a missing golden fails; live tests never create goldens. Golden paths are
never renamed.

**Golden form (H3, H4).** Goldens are stored normalised by the same normaliser the comparison uses,
so regeneration compares bytes: `prompt` and `artifact` raw bytes (artifacts as the starting
commit's build renders them, H5); `json` canonical (sorted keys, volatile values normalised, codes
kept); `human` content-normalised (ANSI and layout whitespace removed, row and token order kept);
`state` a before/after pair of normalised `state.yaml`.

**Adapter rule (H1).** Drivers import only stdlib, the harness, and adapter functions of their own
package; every other import sits in adapter files. An adapter starts untagged. The first
call-site-only edit (`goal-tests`) splits it: the pre-edit content moves verbatim into a twin
constrained to build tag `oraclestart`, and the edit lands in the original, now constrained to
`!oraclestart`. An oracle added after refactors began ships adapters that compile against the
starting tree under `oraclestart`. Twins are never edited.

**Provenance ledger** (`internal/oracle/PROVENANCE`, append-only, line-oriented): `start <sha>`,
written here with `96c9ad69aee983ce2b929dd681b6ba43bf920535`; `fix <sha>`, appended by the task
absorbing an urgent fix and naming the fix commit (X5, `arch-moves`); `changed <golden-path>
<reason>`, with `<reason>` a C-id (`C1`…`C6`, by the C task), `determinism` or `fix`. A `changed`
record names no commit: the commit that changes a golden's blob appends exactly one record for it,
so a golden changed in two commits gets two records. `determinism` and `fix` records are required
only for a golden that already has a C record; before that, H1 reproduction covers such edits.
Reviewers verify each record against its `goal-tests` exception.

**Change points (D24).** A golden `G` with a C record is a chained golden. Its change points
`c1…ck` are the commits listed by `git log --reverse --format=%H -- G` from HEAD, starting at the
first one whose diff adds a C record for `G` (Q14). Each must be a non-merge commit whose diff to
its first parent adds exactly one `changed G` record.

**Comparison rule.** For each committed golden `G`:
- not chained: the value regenerated from the reproduction baseline (starting commit plus `fix`
  commits, current oracle tree) equals the working-tree `G` byte for byte (H1);
- chained: (1) regenerated from the reproduction baseline with the oracle tree and `fix` records of
  `c1`'s first parent, it equals `G`'s blob there; (2) for each `ci` in order, regenerated at `ci`
  itself (temporary detached worktree, untagged build: the tree its drivers were written for), it
  equals `G`'s blob at `ci`; (3) the working-tree `G` equals its blob at `ck`. Each link is
  reported with its reason and SHA;
- anything else is an unexplained difference, including a change of a chained golden by a commit
  without its record, a record added by a commit that does not change its golden, a merge commit
  changing a golden, and any failed regeneration.

**Entry point** (`go run ./internal/testhelpers/oracle/cmd/regen`): read the ledger at HEAD →
resolve chained goldens and their change points → for each needed tree (the reproduction baseline
with the current oracle tree; the baseline with the oracle tree of each distinct `c1` parent; each
change point) create a temporary detached worktree of this repository at the commit named
(D24, D22-A3), in the system temporary directory, removed with `git worktree remove --force` on
exit, failure included; never a branch, a ref or `.liza/` access (E2, E4) → for baseline trees,
check out `start`, apply the diff of each `fix` commit listed by the ledger at the oracle-tree
commit, in ledger order, excluding `internal/oracle/**`, and overlay `internal/oracle/**` and `internal/testhelpers/oracle/**` from the oracle-tree commit
(working tree or `c1` parent) → run the tree's own `sync-embedded` (embedded copies are untracked,
Q8, Q15) → run `go test -count=1` on the oracle packages concerned in write mode, with
`-tags oraclestart` for baseline trees only, under `GOFLAGS=-buildvcs=false` (Q15) and an
explicitly built `HOME`/`PATH`/`TMPDIR` environment → apply the comparison rule. Modes: `check`
(default; exit non-zero listing unexplained, missing and extra golden paths, and listing chain
links) and `write-new` (copy goldens absent from the working tree into it, never overwriting one),
which is how oracle tasks create goldens from the starting commit (E5). An optional package filter
bounds cost.

**ADR.** One ADR, next free number after Scope 1's, with its index row: tree convention, golden
form, adapter rule, ledger kinds and recording workflow, change points and comparison rule (citing
D24), and entry-point modes, so later scopes find them (ASM-002). The sample goldens are harness
proof, not part of any area's surface inventory.
