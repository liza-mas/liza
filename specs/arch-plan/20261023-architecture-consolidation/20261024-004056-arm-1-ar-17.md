## Goal

Separate A7's command definitions, init and setup, inspection, agent-pool repair, watch, TUI and
envelope classification concerns inside their existing packages, with unchanged observable
behaviour, remove the `jsonout → ops` crossing through a leaf classification contract, and leave
A7 closable with only `ops.InitProject` in its ratchet for C4.

## Context and Decisions

Based on the pinned references above, source reads and the probes in Reality Probes, at
integration `38d4ea70cd2521eef253ba69b0202b4892f2290a` (branch `task/arm-1-ar-17`, clean). The A7
production tree there equals the starting commit `96c9ad69a` (RP1). The A7 ratchet holds 9 files
and 17 functions, including `InitProject`, and one allowlist entry, `jsonout → ops` (RP2). The A6
refactor and C5 coding, the A7 installation oracle and the A1, A3 vocabulary types are PROSPECTIVE
(RP9); this plan does not claim them delivered.

**D-1 Package layout.** A7 keeps its five packages and adds none. Offenders are reduced by moving
concerns into new files of the same package. Rationale: `commands → agent` and `tui → agent` are
package-level allowlist entries owned by Scope 20 in A9's data (RP6, `crossings`); a new A7 package
that needed `agent` would require an entry A7 may not write. `tui` and `interactive` import
`commands`, and `commands` files share private helpers (RP6), so sub-packages would export
helpers without an S1 or S3 need. A7 layer data therefore stays as is.

**D-2 Concerns, not engines.** Each offender is reduced by separating phases or families it already
has (Components and Data Flow). Rejected: a command-registration framework for `cmd/liza` (cobra
already is one; one file per command family with its own `init` is the existing convention of the
114-file package, RP7); a generic check-runner abstraction over watch checks, whose inputs,
alert identities and repair side effects differ; consolidating init's Git subprocesses into one
runner, which pre-empts C4's design (`c4-scope`).

**D-3 SI-5: leaf classification capabilities.** `jsonout` stops importing `ops`. The classification
contract lives in leaf `errors` as one capability per `ops`-typed branch of `ClassifyError`; each
capability exposes exactly the facts that branch reads today, and only the `ops` type the branch
matches implements it. `jsonout` evaluates the capabilities with `errors.As` in the frozen branch
order and composes every code and message itself. Rationale: `crossings` gives this direction;
one capability per slot keeps the branch precedence by construction (RP8: slot order wins over
chain order, also through `errors.Join`), whereas a single "classify yourself" interface would let
an outer `OperationalError` win over a wrapped `LifecycleError`, a frozen-surface change. Keeping
codes in `jsonout` leaves one owner for the `--json` code table (`review-errors`). The existing
`interface{ LifecycleResult() any }` and `SafeDetails` probes in `jsonout` are precedents (RP8).
Rejected: an allowlist entry (permitted by `crossings`, but keeps presentation coupled to `ops`
type identity for no saving); capability declarations inside `jsonout` only (works structurally,
but `ops` could not assert conformance, so a rename would silently drop a branch). This is an X3
addition to A1's `errors` and additive methods on A3 and A6 error types, authorised by `crossings`;
those areas' oracles stay green and their ratchet data unchanged (`moves`).

**D-4 One code plan, ordered coding units.** The A6 boundary unit and the concern units form one
code-planning Scope, for the reasons recorded in `a6-proof`: every unit writes the non-commuting A7
guard literal (`internal/testguard/archguard/area_a7_test.go`), the shared `commands` namespace and
the chain-serialized documents, and an order between coding units of sibling code plans can be
declared today only as planning-order edges, which the run waived for Scope 13 only.

**D-5 Plan from contract, resolve at coding.** As in `c5-plan`, planning may precede A6 coding
(`sequence`). The code plan names A6 and C5 boundary evidence and the post-A6 home of
`IntegrationFailedError` behaviourally; the coding unit resolves them at its own integration HEAD.

**D-6 Gap coverage.** A unit that changes code on a path whose frozen surface has no oracle adds the
oracle case first, with starting-tree provenance (`goal-tests`, `oracle`). Known gaps and their
