leaving its prerequisites, profile lifecycle, report step and every other target untouched.

## Components

### Coverage target (`Makefile`, target `coverage`)

**Responsibility:** Run the full Go suite with coverage instrumentation into a per-invocation
profile and render it as HTML.

**Boundaries:**
- Exposes: `make coverage` to developers and agents; local, non-gating.
- Depends on: `sync-embedded`, `check-testhelpers` (unchanged); Go toolchain `go test`/`go tool cover`.

**Key decisions:**
- **Basis = whole module.** The `go test` invocation gains `-coverpkg=./...`, the same basis the
  architecture review's pass-20 figures used, so its total and per-package figures are comparable.
  Rationale: `goal-scope` Should; P4 shows the under-reporting it removes.
- **Merging is the toolchain's.** `go test` writes one profile across all test binaries and
  `go tool cover` merges duplicate blocks (P3, P5); no deduplication step is added.
- **Everything else unchanged:** prerequisites, `mktemp`/`trap` lifecycle, `-html` report and the
  package selection `./...`. Rationale: `arch-scope26` boundary; the profile stays transient, so
  no retention or summary is introduced (OQ-002).

### Coverage documentation (`docs/TESTING.md`)

**Responsibility:** Tell readers what `make coverage` measures.

**Key decisions:**
- The Quick Reference row ("per-package coverage") and the Coverage subsection (lines 37–45:
  "Coverage remains package-local because the target does not use `-coverpkg=./...`") state the
  opposite of the new behaviour, so this scope updates them in the same change. Rationale: Doc
  Impact; leaving them would make the change self-contradicting. No merged or pending architecture
  plan or code plan names `docs/TESTING.md` (searched `specs/arch-plan`, `specs/plans`), so this
  scope is its sole writer; a later scope claiming it orders after this one.
- Other mentions stay accurate and are not edited: `CONTRIBUTING.md:45`, `REPOSITORY.md:135`,
  `docs/PERFORMANCE.md:164`. Stale text in files this scope does not own is OQ-001 and OQ-002.

## Interfaces

### Developer/agent → `make coverage`

**Contract:** Same invocation, prerequisites, exit semantics and HTML report; the profile and
report now cover every package of the module from every test binary.
**Direction:** Caller runs the target; output is the HTML report (or its path when no browser opens).
**Invariants:** `make test`, `make lint` and every other target are byte-identical in the
`Makefile`; coverage gates nothing (`goal-wont`).

## Data Flow

```
make coverage → sync-embedded, check-testhelpers → mktemp profile
  → go test -coverpkg=./... -coverprofile=<profile> ./...   (one profile, all binaries, whole-module blocks)
  → go tool cover -html=<profile>                            (merges duplicate blocks; renders)
  → trap removes <profile>
```

#### CONTRACT

`make coverage` keeps its invocation, prerequisites, profile lifecycle, exit semantics and HTML
report; its measurement basis becomes the whole module (`-coverpkg=./...`), credited across all
test binaries and merged by the Go toolchain. It remains a local, non-gating measurement
(`arch-scope26`). No other target's recipe changes.
