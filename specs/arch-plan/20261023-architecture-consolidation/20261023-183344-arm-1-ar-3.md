## Goal

Pin every A3-produced frozen surface — the CLI output and `state.yaml` effects of the task-lifecycle
and operator-control commands whose `ops` entry lies in an A3 file — with black-box goldens created
from the starting commit through the SI-3 entry point, in two independent oracle packages.

## Context

Based on: the carrier `arch-scope3` and its direct references, the merged SI-3 refinement
`arch-harness`, the A3 file list (`arch-areas`), the `cmd/liza` and `internal/commands` callers of
every exported function of those files, and the probes below.

This document owns: the A3 surface inventory, its split into two oracle packages, the A3 fixture,
caller-identity and determinism conventions, and the recorded gaps. SI-3 (tree convention, golden
form, adapter rule, ledger, entry point) stays at `arch-harness`; this plan refines inside it and
edits nothing it owns.

### Constraints

Inherited by reference: frozen-surface rules (`goal-frozen`), oracle immutability (`goal-tests`),
E2–E5 (`goal-proof`), G1.3/G1.4 (`guard-tier1`), assignment and depth (`arch-oracle-template`),
SI-3 H1–H7 (`arch-oracle`, `arch-harness`), additive oracle files (`arch-files`).

New, local:
- **OC1** Test-only additions under `internal/oracle/a3/**`; no production file, existing test,
  harness file, ledger or `Makefile` changes (`arch-scope3` boundary).
- **OC2** Binary-driven only: every A3 surface is reachable through a CLI invocation (P2), so
  drivers import only the standard library and the harness and need no adapter.
- **OC3** Linux only: each test skips on other systems, naming the reason. Goldens are generated on
  Linux; A3 has build-constrained process files (`exec_*`, `shell_runner_*`,
  `delete_agent_process_*`) whose other-platform behaviour stays with the existing suites N2 runs.
- **OC4** No oracle case signals, waits on or outlives a process: no `--force` against a live PID,
  no `recover-agent --cli` (it spawns a provider, E2).

### Assumptions
- **ASM-001**: Phase-gate inheritance (ADR-0048) makes each coding task generated by these outputs
  wait for the coding descendants of `arm-1-ar-0` outputs 0 (size guard, E0 hold) and 2 (harness),

- **ASM-002**: The harness delivers the `arch-harness` CONTRACT (tree convention, golden kinds,

## Components

| Component | Path | Responsibility |
|---|---|---|
| Lifecycle oracle | `internal/oracle/a3/lifecycle/` | Goldens for task-lifecycle commands over a task, agent and Git fixture: output, `state.yaml` before/after, Git effects, lifecycle outcome counts |
| Control oracle | `internal/oracle/a3/control/` | Goldens for mode, config, admission and agent-administration commands over agent and config fixtures |

Both are test-only packages under the SI-3 tree convention (`arch-harness`), each owning its own
`testdata/fixtures/` and `testdata/golden/<kind>/`; they share no file. Key decisions:
- **Two packages, split by fixture shape**: lifecycle cases need a task in a chosen status, live and
  dead caller agents, a Git repository with task worktrees and lifecycle receipts; control cases need
  only mode, config and agent rows. The split keeps fixtures local, lets the two code plans proceed
  in parallel and bounds each review.
- **Conventions duplicated, not shared**: the A3 environment and determinism layer (CONTRACTs) is
  stdlib code in each package. Sharing it would make one scope wait on the other. Ceiling: a third
  A3 oracle package extracts it into `internal/oracle/a3/internal/` in that task.

## Interfaces

**Harness → A3 packages** (`arch-harness` CONTRACT, consumed as is): CLI build helper, golden read
and compare per kind, normalisers, `write-new`. **A3 packages → entry point**: discovered by path;
the filter `./internal/oracle/a3/...` bounds a run. **A3 oracle → consumers**: Scope 12 (A3
refactor), the A4–A6 and A9 refactors and C6, which touch the kernel A3 owns (`arch-areas`); each
runs the packages live and changes no golden.
