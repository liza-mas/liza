## Goal

Connect provider-unavailable policy to C2's identity query through A9's signal boundary,
keeping operational signal identity distinct from presentation identity.

## Context

Based on resolved parent authority, the pinned C2 and A9 contracts, and source probes at
`92b705f2165e1869b9ea434bbff3ed1b3c1bf760` (initial clean worktree HEAD).
The tree still has the pre-extraction implementation in agent. A9's `providersignal` and
`agentlaunch` packages, and C2's exported canonical query, are **PROSPECTIVE**, supplied by
their coding descendants through the inherited phase chain. That chain holds C3 coding, not C3
code planning: the planner waits only on the C2 code plan, so it plans against the pinned A9/C2
contracts and whatever tree its integration HEAD has, and requires no delivered A9/C2 code.
Current paths below are discovery anchors; they do not authorize restoring code to pre-refactor
locations.

Built-in Codex aliases already share a signal filename through `acpxAgentNameFromTool`.
That is insufficient evidence for C3's C2-based rule: it does not consume current project
provider-key overrides. The crash path also passes the classifier's display provider into
the writer, losing the actual launch-tool identity. Conversely, CLI and TUI currently derive
their reported provider from the filename. Merely changing a suffix to an effective key would
therefore change a frozen value. These are the two boundaries this scope must separate.
ADR-0096 and ADR-0121 retain catalog ownership and independently addressable runtimes. The dated
issue registry's suggestion to canonicalize registration and quota is superseded by the explicit
`changes`/`parent` boundaries; its claim that unavailable aliases never match is stale at this HEAD.

**Components:** A9 providersignal unavailable-signal policy and records; agent crash/stop and

**Boundary:** every unavailable-signal raise/match change, its caller plumbing, tests, attributable

**Done when:** `parent` acceptance is proven through real raise/stop paths in both directions,

#### CONTRACT

**Owner and inputs.** A9's `providersignal` remains the owner of unavailable-signal records,
file access and matching. It consumes the C2 pure key query from `agentlaunch`; no new provider
registry, suffix table or parallel canonicalization belongs here. Pass the actual launch tool
identity separately from the existing classified provider/message. A classifier's `codex`
diagnostic label is not evidence that the failed tool was `codex` rather than `codex-acp`.
Diagnostic recognition and bounded-evidence rules remain unchanged; this is a stop-policy change,
not a broader startup-failure detector.

**Raise and match data flow.** Failed tool plus existing diagnostic -> unavailable record;
recorded originating tool plus candidate supervisor/spawn tool and the same current catalog/config
view -> C2 canonical keys -> equality -> existing stop/refusal decision. Keying is logical policy
identity; the physical file name need not be the policy key. Derive keys at evaluation time, without
rewriting `agents[].provider` or caching a derived key as durable policy truth. Do not call the
launch renderer or execute a provider to derive identity. Use C2's existing loading/fallback
owner, acquire inputs outside blackboard mutation callbacks, and share the loaded base across an
evaluation. Snapshot configuration must be the one used for the decision; no per-record network
refresh or new refresh policy.

All unavailable consumers must use that boundary: supervisor stop checks, classified-crash signal
creation, process spawn refusal and the orchestrator's final wake revalidation. Retain each caller's
existing order, cancellation, release/cleanup and error behavior. The process gate currently reads
runtime config after the signal checks; plumbing that existing config into this check must retain
quota-first refusal precedence and all launch/validation semantics. No quota helper is converted
to C2 comparison as a side effect of sharing infrastructure.

**Record and presentation separation.** Keep enough original tool information to evaluate C2
without substituting the classifier label. Preserve the existing display provider as a separate
projection of a signal record. CLI/TUI enumerate that projection and clear the corresponding
physical signal handle, not a file reconstructed from a newly canonicalized display string.
This allows internal storage/API changes without changing provider values, row order, labels,
duplicate/collapsed reporting behavior, or error attribution for the same pre-existing fixtures.
Spawn-blocked alerts continue to name the requested tool, as today. A custom shared canonical key
must never leak into those values solely because matching now uses it.

Existing signal files remain usable: interpret the available legacy provider identity through the
same C2 query; do not require an unavailable historical originating tool to be guessed. New records
retain the information needed for unambiguous policy evaluation. The coder chooses the concrete
record/filename encoding on the delivered A9 tree, within these constraints, which the code
planner carries into acceptance without choosing it: legacy listing/clearing is preserved and
distinct effective keys are not conflated by the old alias filename normalization.
Treat filesystem addressing separately from arbitrary configured provider-key text; it must not
permit path traversal or place files outside the existing project signal directory. Clear handles
must refer to enumerated signals. No state-schema migration or new user-facing storage mode.

**Failure handling.** Keep existing missing-signal, unreadable-path, write-failure and clear-failure
behavior and CLI/TUI differences. Do not introduce a new refusal code, silently swallow an existing
error, or convert unavailable into quota/crash behavior. Preserve current global-catalog fallback
semantics via C2. Resume still clears unavailable signals in its existing sequence relative to state
changes, and quota expiry/reset handling is untouched.

**Provider answers.** The functional-spec entry has no epic stage or Provider Ask Inventory
(tracked-path and merged-spec probes below). Source-backed asks are reconciled here:

| Interface / consumer | Operations and fields | Answer |
|---|---|---|
| C2 canonical query / C3 | Actual tool, loaded catalog, config -> equality key; no status | Consume `c2` unchanged; planning uses the pinned contract, coding receives fixtures and implementation through coding inheritance. |
| Unavailable signals / runtime | Raise with tool and diagnostic; match current tool | Signal owner applies the shared query; preserve classified label separately. |
| Unavailable signals / process and orchestrator wake | Read stop decision before start | Same match operation, caller-specific precedence unchanged. |
| Unavailable signals / CLI and TUI | Enumerate display provider and clear physical record; existing failures | Preserve projection and clear-by-handle correspondence, including legacy files. |
| SI-3 / oracle consumers | Stable quota, state, display and alert evidence | Only attributable C3 comparison outcomes may change; D24 applies to changed goldens. |

No ask is deferred. This contract refines the already approved A9/C2 boundaries, without a new
package or speculative service abstraction. It does not freeze an invented implementation API.

#### Allocation and ownership

One code-planning output allocates one C3 coding task (`change-template`); raising, matching and
preservation tests are one deliverable. No helper/wiring/test task chain. `rca_required: false`:
this is the explicitly authorized C3 behavior change, with both identity-loss sites located.

The coder owns unavailable portions of providersignal, agent/process consumers, and necessary
CLI/TUI adapter updates under X4 in `moves`; tests may accompany every changed package and include
disposable integration fixtures. Allocate its acceptance manifest and C3 oracle/provenance entries.
Quota implementations stay outside the behavior change; existing quota tests remain runnable.
No ownership restriction may prevent the presentation adaptations needed by this contract.

Expected relevant boundary writers: A9 extraction, C2 identity query, C3 signal consumer: three,
ordered by the inherited chain. C3 writes signal-focused files and adds its own focused tests and
provenance entries; it consumes rather than edits the shared identity definition. This additive
separation avoids another shared registry writer. One local output means no sibling file conflicts
or optional-output waits. Preserve default inheritance; there is no new whole-phase barrier.
This ordinary scheduled writer does not insert a correction into the shared-file chain.

Update directly affected signal documentation and code references under `files`/`docs`; document
the durable matching/display separation in an ADR and its index entry during implementation if the
delivered A9/C2 records do not already cover it. Do not rewrite historical ADRs or the final overview;
issue-registry closure remains with the boundary/final owner. Preserve S1/K4/C6 guard behavior; a
necessary A9 guard-data adjustment uses only its existing area data and cannot grow the ratchet.

#### Proof allocation and final holds

| Proof | Observable distinction |

| P5 presentation and recovery | CLI and TUI listing/clearing preserve provider values, ordering, labels and existing failure reporting, with codex-acp, custom-key and legacy-file fixtures. | P6 structure and provenance | S1/K4/C6 checks and frozen oracles pass except attributable C3 outcomes; any changed golden has D24 reproduction-chain evidence. State provider fields, launch/config lookups and rendered prompts remain unchanged. |

Use deterministic tests at the real signal-policy boundary plus disposable filesystem/state
fixtures for caller and presentation behavior. G1.4/E2/E4 govern environments, temporary repos and
provider stubs. Shared catalog fixtures use injection or existing serialized cache conventions;
do not mutate global catalogs concurrently. Inspect TUI content in review as S4 requires.

After touched-file pre-commit, run focused tests and scoped race tests for changed packages per E1.
The existing broader commands are `make test`, `make lint` and `make test-e2e` (setup/selection
dry-run verified below). A long regression-only command can be deferred through the coding
Acceptance Contract only if no P1-P6 proof maps to it; integration then owns that final hold.
Never substitute a deferred broad suite for C3 evidence.

**Delivered-tree adaptation.** Planning evidence and coding evidence are separate. The planner works
from the pinned A9/C2 contracts and probes of its own integration HEAD; it neither waits for, nor
probes, nor times A9/C2 code, and every allocation it makes stays valid whether or not that code
has landed at its HEAD. Its canonical validation therefore resolves on both the pre-extraction and
the delivered layouts: make targets, and focused runs that select C3 tests by name over package
trees that exist in both (for example `-run` over `./internal/...`), never a path that exists only
after extraction (`./internal/providersignal/...` does not resolve at the probed HEAD, RP10). The
planner fixes a test-name convention selecting every new P1-P5 test, probes that selection on the
existing signal tests, and carries the encoding constraints above into acceptance. The coder, whose
claim waits on C2, C6, C1 and A9 coding through inheritance, adapts to the delivered seams: it
chooses the record encoding, places tests in the packages A9 delivered, names each new test under
the convention, records exact per-package focused and scoped race commands in its acceptance
manifest, and measures the focused batch. Delivered code that contradicts a pinned A9/C2 contract
consumed here is marked BLOCKED for a contract correction, never absorbed by changing that contract.

Runtime basis: pure comparisons/filesystem cases estimated seconds; disposable supervisor/spawn
cases estimated minutes. These are planning estimates, not measurements. The planner sets the
admission timeout from these estimates and from timing the existing signal tests at its HEAD,
with headroom under the 600-second foreground cap and shared slots. The coder reports the measured
focused batch; one exceeding the admitted timeout is marked BLOCKED for a reviewed validation
correction and is never fitted by dropping a P1-P6 test. Broad regression cost uses Scope 0's
baseline and existing integration batching; N3/N4 comparison and cross-platform CI remain with the
inherited area/final gates. No stronger performance threshold or credential-dependent test is
introduced.
