#### CONTRACT

**Components and data flow.** Delivered code, per-area guard data, merged task commits and
boundary records are evidence inputs. The A9 boundary consumes them and emits a record tied to
an immutable integration SHA. The close-out documentation consumes that passed record plus the
final tree. `overview.md` owns the explanation of structure and code placement;
`architectural-issues.md` alone owns finding lifecycle. The final record links evidence and
dispositions; it does not become a second issue registry or a replacement specification.

**Post-run guard form.** Keep `area_a1_test.go` through `area_a9_test.go` as permanent component
groups, and explain them in the overview with the groups' current responsibilities and package
membership. Use the final layer map and `areas` as the inputs, accounting for packages introduced
by the run rather than copying the initial path list. A new production package is assigned to
one group and entered in its layer map; a cross-group import is governed by `layers`, not by the
historical area sequence. Where the ops groups share a package, explain their capability/file
ownership separately from the single package layer entry. New code joins the group owning its
responsibility, not a new numbered run area.

Retain empty active `Ratchet` slices. Do not remove the nine area values, rewrite their aggregate
list, or erase `s1_snapshot_test.go`: the immutable start snapshot is historical evidence, not
active ratchet debt. Retain the S1/K4/C6 guards. S2 entries and allowlist entries keep their existing
schema and rationale; no new exception or crossing is authorized here. This chooses the
documentation option permitted by `parent` and is compatible with `guard-decision`. Merging
the data would touch the immutable aggregate list for no required benefit.

**Overview interface.** Document the delivered layers, import-direction rule, composition root,
named mutation boundary, and a concrete answer to where each kind of new code belongs. Link the
guard entry point and permanent component groups. Give the S2 list exact file/function keys,
category and rationale, with the recorded ruling for non-data exceptions; state explicitly when
the list is empty. Reconcile the list against all nine S2 slices, not against ratchets or obsolete
assessment sizes. Explain any retained K4 allowlist crossing with its actual rationale; an allowed
read/liveness dependency must not be described as a mutation exemption. Link current ADRs and
authoritative lifecycle/schema documents instead of duplicating them. Preserve useful existing
navigation anchors or update their live inbound references within the permitted documentation
scope. Do not invent a new public API, layer, configuration field or architectural exception.

**Registry interface.** Reconcile findings against merged implementation and acceptance evidence,
using `issues-policy`. Each closure names the fixing commit(s), proof and resulting owner/path;
update the active section, summary/counts, Completed Fixes and Fixed (Traceability) together.
Keep original issue anchors and historical sizes where they are link identities. A smaller file
is not proof that its cohesion concern is resolved. Partial fixes remain open with the residual
concern named. In particular, distinguish canonical-provider policy from hard diversity at
verdict time, and the C1 unchanged terminal literal from the registry's older recommendation to
derive it. C1-C3 do not authorize quota changes or canonicalizing stored provider values.
Never close the explicit `wont` findings merely because adjacent code was consolidated.

**Current-reference interface.** Reconcile `INVARIANTS.md`, `state-machines.md`,
`blackboard-schema.md`, `supervision-model.md`, `specs/protocols/` and `lessons/` against the
delivered enforcement owners. Audit moved/renamed code references and references whose file still
exists but no longer owns the claim. Verify symbols and semantics, not only path existence.
Use area move/shim records, the starting-to-final diff and actual source as discovery aids.
Record which documents were reviewed, changes made and any intentionally historical references.
Preserve normative invariants, schema semantics and protocol behavior; an unresolved conflict
goes to the owning area/human instead of being rewritten into agreement. Historical ADRs and
skill/contract/support-doc content remain untouched.

**Failures and close status.** Apply `boundary` literally: failed G1-G4 becomes A9 closure debt,
with the failing command/result named in a BLOCKED task; this scope never repairs area production
code or weakens guards. Missing final implementation evidence holds closure even when a
ratchet-aware guard is green. G8 is maintainer-owned final acceptance: the boundary coder records
local evidence, marks BLOCKED with `--human-action`, and waits for the integration-to-main PR's
Linux/Windows results and the subsequent main-push macOS result. No agent push, install or live
state manipulation substitutes for that evidence. A red CI result follows the repair routing

N3/N4 out-of-bound or non-comparable results receive recorded Should dispositions and do not
block. The baseline timed run failed: retain its 523 s/exit 2 and the green 444 s warm-up as

**Provider asks.** No epic inventory exists: this run enters at functional-spec/architecture,
