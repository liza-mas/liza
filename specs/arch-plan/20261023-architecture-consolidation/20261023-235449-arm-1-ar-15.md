## Context and Decisions

Based on the pinned references above, source reads and the probes in Reality Probes, at
integration `31cd77b250685afeb23f840422731e37ba63b641` (branch `task/arm-1-ar-15`, clean).
The `internal/ops` production tree there equals the starting commit `96c9ad69a` (RP1). The A6
ratchet holds 3 files and 6 functions (RP2). SI-3 regeneration is delivered (RP10). The A5
refactor, the A6 oracle suite, the A1 V-types and the A3 kernel types are PROSPECTIVE (RP9); this
plan does not claim them delivered.

**D-1 Package layout.** A6 stays in `internal/ops`, keeps its exported operations, result and error
types, and extracts private concern files and functions. Rationale: `adr-0021`; A6 code calls A3
kernel helpers (`modifyLifecycleState`, `lifecycleMutation`, `RequireWorkAdmitted`, lifecycle
request and receipt functions), A4 helpers (`cleanupPredecessorBranches`, `UpdateSprintMetrics`,
`RecordObligationContentDrift`, archive operations) and A5 helpers (`requireReconciledVerdicts`,
`validateIntegrationLifecycleCandidate`), and A3–A5 call A6's integration locks (RP7). Rejected:
an `ops/integration` sub-package, which would export those helpers or create cycles without an S1
or S3 need. SI-5 assigns no crossing to A6 (`crossings`), so A6 layer and allowlist data stay empty.

**D-2 Concerns, not engines.** Each offender is reduced by separating phases it already has
(Components and Data Flow). Two shared private helpers are admitted under K6, each absorbing named
duplication: the guarded integration-ref publication repeated in `performCASMerge`'s fast-forward
and true-merge branches, and the merged-task worktree and branch retirement repeated with identical
warning text in `mergeWorktree` and `reconcileMergedWithOptionalAuthority`. A third absorbs the
eight-step provisioning sequence repeated in `createWorktree`'s reuse and fresh paths (RP4).
Rejected: a generic lifecycle-step framework over merge, reconcile and recover, whose locks,
transactions and failure projections differ; and resolving `issue-intel-refresh`, whose coordinator
spans A3, A5 and A9 paths with differing warning text and failure tolerance (a frozen-surface
change). That issue stays open.

**D-3 One code plan, ordered coding units.** The A5 boundary unit and the four concern units form
one code-planning Scope, for the reasons recorded in `a5-proof`: every unit writes the non-commuting
A6 guard literal, the chain-serialized documents and the shared `ops` namespace, and an order
between coding units of sibling code plans can be declared today only as a planning-order edge
(`planning-order-ruling`, which waives it for Scope 13 only).

**D-4 K1 is non-regression** (`k1-ruling`). A6's inherited Git call inside a transaction is listed
in K1 Inherited Exceptions. The merge's integration lock discipline (`inv-worktree`,
`inv-concurrency`) is preserved as stated in Scope 1's CONTRACT.

**D-5 Gap coverage.** A unit that changes code on a gap path recorded in `a6-surfaces` adds that
oracle case first (`goal-tests`). A gap whose case needs what the proof environment excludes (an
external indexer, a Windows host) is not built: the unit then leaves that gap path's own functions
unchanged, may change only their call site with arguments and warning order unchanged, keeps the
white-box tests over the path, and records the gap in its acceptance evidence. Windows A6 behaviour
stays with existing tests and area-boundary CI (G8), as the A6 oracle already decided.

Rules for every concern:
- A private helper that runs inside a transaction receives the state, task and context it needs.
  It never opens a blackboard, task, integration, completion or file lock. The operation keeps its
  lock order, transaction boundaries, error identity and effect order.
- Merge phases share one private per-invocation carrier for the values they pass on (blackboard,
  task, request, preparation, effect class, publication flags). The entry function keeps the
  deferred error wrapping and preparation retirement, so their trigger conditions are unchanged.
- Warnings are collected in the order the current code produces them; `--json` and human output
  render that order (`goal-frozen`).
- Extracted validation adds no check, does not change which refusal comes first, and swallows no
  error. Generation fencing, request identity and receipt replay come from the A3 kernel
  (`a3-kernel`, `adr-0130`).
- Test seams that are package variables today (hooks, `startIndexRefresh`,
  `startDeferredValidationProcess`, poll intervals, `DefaultIntegrationTestTimeout`) stay
  replaceable variables.
