## Goal

Freeze the observable behaviour of A4 (transitions, replanning, task creation and output, task
replace/supersede/cancel/delete, dependency repair and narrowing, provider reservations, plan check
and amendment, sprint operations and archival) in one oracle suite whose goldens come from the
starting commit, before Scope 13 refactors A4.

Based on: the carrier `arch-scope4` and its direct references, the Scope 0 harness contract
(`s0-harness`), the 41 A4 `ops` files and their callers in `cmd/liza`, `internal/commands` and
`internal/agent`, `internal/testguard`, and the probes below at integration HEAD `3168b4e6d`.

### Assumptions
- **ASM-001**: The code-planning child inherits waits on `arm-1-ar-0-cp-0` … `cp-3`, so it is
  planned and coded after the harness lands — *Why*: phase-gate inheritance (Probe A14) —
  Confidence: HIGH.
- **ASM-002**: The harness API is settled by `arm-1-ar-0-cp-2`, not this plan; a capability this
  suite needs that the harness contract does not promise is supplied inside `internal/oracle/a4/`
  with stdlib-only code (Provider asks) — Confidence: HIGH.
- **ASM-003**: Report files the CLI writes for humans (`sprint_summary.md`,
  `circuit_breaker_report.md`) are human-readable CLI output whose content is frozen
  (`goal-frozen`), so they are captured; log files are free and are not — *Why*: they are produced
  by the command for a human reader; capturing them costs one normalised file per case —
  Confidence: MEDIUM.

## Design Decisions

- **D1 One package, one scope.** All cases live in `internal/oracle/a4` (tree convention,
  `s0-harness`): they share one fixture builder, one invocation runner and one determinism layer,
  and the adapter rule confines non-stdlib imports to adapter files of the driver's own package.
  One code-planning scope; its planner may split coding units by row group (T/G, D/L, S/O) behind a
  first unit that lands the shared fixture builder, runner and determinism layer. Rejected: one
  scope per group, which would duplicate the shared layer or serialize the scopes on it anyway.
- **D2 Zone-class timestamps.** Children run under `TZ=Etc/GMT-2` (fixed `+02:00`, no DST, A8).
  Goldens erase every instant but keep its zone class (`Z` or the numeric offset), so a refactor
  turning a local timestamp (A7) into UTC, or the reverse, fails (`goal-frozen` "other local-time
  timestamps stay local"). Rejected: running under UTC, which makes the two classes identical.
- **D3 Unix only.** Drivers skip on Windows with a logged reason: Go ignores `TZ` there (A8) and
  path forms differ; goldens record Unix behaviour, which E1 proof exercises. Windows A4 behaviour
  stays with existing tests and area-boundary CI. A Unix host where `Etc/GMT-2` does not load fails
  the suite naming the zone, never a silent UTC fallback.
- **D4 Committed fixtures, not `init`** (AC3). A fixture project is a disposable Git repository
  built by driver code plus committed `.liza` inputs (state, pipeline, models files) and committed
  planning documents under `testdata/fixtures/` (E5). The pipeline input is a committed copy, not a
  read of `internal/embedded/pipeline.yaml`, so a later pipeline change cannot move A4 goldens.
- **D5 Supervisor-only operations through a helper process.** T2 and S2 have no CLI (A11); an adapter
  calls the operation in a re-executed test binary with the same explicit environment as CLI runs,
  so no host variable reaches it (E4, G1.4).
- **D6 Identity per operation.** Each case runs with the primary identity of its operation:
  operator (no agent variables) for operator-only operations, otherwise the fixture's registered
  orchestrator row and its generation passed as identity variables (A5). O1 is the only place an
  identity is deliberately wrong.
- **D7 Written-file manifest.** An operation's state effect includes the non-log files it writes
  under the project (archive objects, report files; A9, ASM-003), so the state golden records them.

#### CONTRACT

**Cases.** Exactly the Surface Inventory rows of this document, with the listed kinds and test
names; each principal refusal the inventory leaves open is the first precondition refusal the
operation reaches with well-formed flags at the starting commit, named in the plan. Every state
golden records the starting commit's actual before/after delta, whatever it is (a precondition
refusal is expected to show none). Goldens are created only by the entry point's `write-new` mode
from the starting commit (E5), never by live tests.

**Invocation.** CLI cases run the CLI the harness builds from the tree under test; T2 and S2 run in
a re-executed test binary through an adapter (D5). Every run gets an explicitly built environment:
the harness environment plus `TZ=Etc/GMT-2`, `GIT_CONFIG_NOSYSTEM=1`, and per case only the identity
variables of D6, subject to the G3 correction below. Stdin is empty unless the case supplies it (`delete task`, A16). A CLI golden
records the exit code with the output: json mode as a wrapper object holding `exit_code` and the
parsed stdout document; human mode as a transcript of exit code, stdout and stderr with
stdlib-log-formatted lines removed (log lines are free, `goal-frozen`). Mutating cases run each mode
on a fresh fixture copy.

**State and written files.** The state golden is the before/after pair of `state.yaml` plus a
manifest of files the case created or changed under the project root other than `log.yaml`,
`*.log`, lock and lock-owner files: each entry is the project-relative path (content-addressed
object paths tokenised as below) and its content normalised by form (JSON by the json normaliser,
YAML by the state normaliser, Markdown and text by the human normaliser).

**Fixtures.** A fixture project is a disposable Git repository (repo-local identity, `main` and the
configured integration branch, committed spec and planning documents where an operation resolves
references, task branches only where a case needs them) plus committed `.liza` inputs valid at the
starting commit, with tokens for SHAs and paths filled at setup. Fixture timestamps are fixed
literals: history in the past, leases and expiries far in the future. Tasks that a case archives are
terminal in the fixture with literal timestamps, so archive object content is stable. Setup calls no
other command. Every fixture carries one orchestrator agent row with a literal generation.

**G3 identity correction (supersedes D6 for G3 only).** `set-task-output` uses a registered
planning doer, not the orchestrator: the unchanged starting pipeline permits `architect` to invoke
it. Retain the orchestrator row and add `architect-1` with role `architect`, status `WORKING`,
literal nonempty generation, matching `current_task`, and valid owner metadata and future leases.
The target is an `architecture` task in `architecture-pair`, status `ARCHITECTING`, assigned to
`architect-1`, with matching task ownership metadata. Invoke
`set-task-output <task-id> --output <fixture-output.json> --agent-id architect-1` with only that
fixture agent's ID and generation as identity variables; run both output modes on fresh fixtures.
The nonempty, valid fixture output names committed fixture spec and architecture references.
G3 `/refused` uses the same permitted identity and the inventory's principal-precondition rule;
neither case substitutes an RBAC denial for the required success. This exception changes no
pipeline capability, production RBAC, other case identity, inventory case, or golden assertion.

the worktree-built CLI accepted this recipe in disposable repositories using a byte-for-byte copy

**Determinism** (A4 layer, stdlib only, before the harness normalisers): instants replaced by a token

**Platforms** (D3). Each driver skips on Windows with a reason naming the platform gate; on Unix it
fails, naming `Etc/GMT-2`, if that zone does not load.
