## Goal

Make the two merge timestamps written by the final MERGED transaction persist in UTC, keep every
existing state that holds local-offset values loadable as the same instants, and change nothing
else.

## Context and Decisions

Based on the pinned references, source reads and the probes below at integration
`11880dcfecf30587d8327dfce6c556bbf5fb70ac`.

The two sites (RP1) are, today, `HandoffEvent.Timestamp: time.Now()` (completion handoff event)
and `TaskHistoryEntry.Time: time.Now()` (`merged` history entry), both inside the final MERGED
transaction of the merge operation. The same transaction already records deferrals with
`time.Now().UTC()`, and the external-merge reconciliation path writes its own completion handoff
and `merged` history entry with a UTC `now` (RP2). After Scope 15 these sites live "in one findable
function inside the final MERGED transaction" (`a6-scope` CONTRACT, `a6-provider` C5 row); that
function's name and file are PROSPECTIVE, produced by the K-MRG unit of `arm-1-ar-15`'s code plan.
Sites are identified by this behaviour, not by line or file (D-6).

**D-6 Plan from contract, resolve at coding.** Planning may run before A6 coding lands
(`sequence`: only coding is sequential). The code plan is written against the reviewed A6 code plan
and the contract above, naming the sites behaviourally (the completion handoff timestamp and the
`merged` history time appended in the final MERGED transaction of the merge operation) and their
pre-refactor location as orientation only; it fixes no post-refactor function or file. The coding
unit, which inherits the wait on every A6 coding unit (ASM-001), resolves the actual function and
file at its own integration HEAD and records them in its acceptance evidence. If at coding time
the two readings are not in one function inside the final MERGED transaction, the `a6-scope`
contract is unmet: the coder marks BLOCKED naming the A6 contract, rather than reshaping A6 code.
Rejected: a planning wait on A6 coding (adds an implementation prerequisite planning does not need
and delays the plan for nothing; the inherited coding barrier already orders the writers).

**D-1 Minimum mechanism.** Each site reads the clock in UTC (`time.Now().UTC()` or the equivalent
in the refactored function). Each keeps its own reading, its field, its position in the
transaction and its entry content. Rejected: a clock abstraction or a shared `now` for both sites
(not needed by C5; Rule 6), and normalising times on load or on write in `db` or `models` (would
change every other timestamp and existing persisted values, against `goal-frozen`).

**D-2 Load compatibility needs no code.** Both fields are `time.Time` decoded by `gopkg.in/yaml.v3`
with no custom unmarshaler (RP3); a value with a `+02:00` offset decodes to the same instant (RP4).
State validation checks only non-zero handoff timestamps, never zones (RP5), and consumers compare
merge times by instant (`After`, `Before`), not by string (RP6). C5 therefore adds no migration and
no load-path code: pre-C5 entries keep their stored offset, including across later rewrites of the
state, and are proved by tests, not by changing the reader.

**D-3 Proof needs a non-UTC local zone.** On a host whose local zone is UTC, local and UTC readings
serialise to identical bytes (RP4), so a persisted-form test passes on the old code there. The
focused tests therefore (a) assert the in-memory location of each written value is `time.UTC`,
which distinguishes on every host, and (b) prove the persisted form under a forced non-UTC local
zone set for that test process only. Go fixes `time.Local` at first use, so `t.Setenv("TZ", …)`
mid-process is ineffective; reassigning `time.Local` while other goroutines run is a data race
under `go test -race` (`ops` tests start background work). Recommended: re-run the test binary as
a child process with an explicitly built environment carrying `TZ` (`guards` G1.4). The code plan
may pick another mechanism only if it is race-free and does not depend on the runner's zone.

**D-4 Goldens.** The A6 oracle is PROSPECTIVE (`arm-1-ar-6-cp-0-code-0`); SI-3 normalisation
replaces timestamps, including their `Z` or offset suffix, with `<TIME>` (RP7). The expected golden
delta is therefore empty. Any golden that changes must assert one of the two values; any other
golden change is a defect of this task (`goal-tests`). No white-box test asserts the zone of either
value today; the merge test checks only instant ordering (RP8).

**D-5 Out of the change.** Every other `time.Now()` keeps its zone, notably the local completion
handoff written by the agent runtime when it finalises a clean-terminal task (RP9), which is not a
merge timestamp and is not on the C5 list. Derived displays (`--json` history values, the usage
report's RFC3339 diagnostic) show the new zone for new merge entries only, as a direct consequence
of C5's persisted value; no rendering code changes.

**Doc Impact.** None. `schema-time` already states that state timestamps are UTC with a `Z`
suffix; C5 brings the two sites into line with it. No ADR: C5 is a goal-ruled behaviour change, not
a structural decision. The chain-serialized documents (`shared-files`) are not edited.

#### CONTRACT

Each of the two values is the merge invocation's own clock reading converted to UTC; field,
entry content, order and transaction position are unchanged (D-1). Readers are unchanged: a
`timestamp` or `time` with any RFC3339 offset loads as the same instant, through both the live
state read and the terminal-archive task read, and passes state validation; no code rewrites a
stored offset (D-2). Proof distinguishes UTC from local on any runner host, is race-free under
`go test -race`, and builds child environments explicitly (D-3, `guards` G1.4). Expected golden
delta is empty (D-4). Every other persisted timestamp keeps its zone (D-5). The sites are identified
by behaviour; their function and file are resolved by the coding unit after the A6 coding barrier
(D-6).
