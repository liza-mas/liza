## Data Flow

```
base-<name>/ + case deltas ─► temp case root (EvalSymlinks): HOME/, project/
   repo commits ─► git init, fixed identity and dates, integration branch, task worktrees
   state template ─► resolve root token and commit labels ─► project/<runtime dir>/state.yaml
   adapter: embedded pipeline ─► project/<runtime dir>/pipeline.yaml
preparation steps (CLI or adapter; each must exit 0 / succeed) ─► snapshot state (before)
step under test: CLI binary in project/ with explicit env  |  adapter call
   ─► exit code, stdout, stderr, state (after)
driver: commit SHAs ─► labels; changed lease fields ─► <lease:+Nm>; elapsed ─► <elapsed>; root ─► token
harness: normalise ─► live compare | write mode (regen at start)
```

## Determinism Rules

- **Root and labels.** One temp root per case (via `filepath.EvalSymlinks`), holding project and
  HOME, replaced by the harness temp-path normaliser. Every fixture commit carries a label; its SHA
  is replaced by `<commit:label>` wherever it appears, so goldens assert which commit; other hex
  identifiers (transition and request IDs) go to the volatile-identifier normaliser.
- **Environment.** CLI steps get exactly: `HOME` (case root), `PATH` (host, for `git` and `sh`;
  never written to output by these commands), `TMPDIR`, the Git identity and date variables, the
  agent generation variable for the acting agent; the agent ID only through `--agent-id` (lesson
  `agent-env-leaks-into-cli-tests`). Validation sessions (VP, and claims that reach preflight) use
  a fixed literal environment containing no temp path (`PATH=/usr/bin:/bin`, `HOME=/nonexistent`),
  since the readiness fingerprint hashes it (R11).
- **Time.** Fixture timestamps are fixed literals: history in the past, live leases in 2099,
  expired leases in the past. Timestamps the step writes go to the harness normaliser, except
  lease fields it changed: each becomes `<lease:+Nm>`, N = whole minutes from step start, so the
  1800 s default stays asserted (`arch-scope5`, R9). Elapsed durations in progress lines become
  `<elapsed>` (R8).
- **Selection.** Every claim case has exactly one eligible candidate, or (RC5) exactly one
  preferred one, so `pickRandom` never decides (R10).
- **Waiting.** Await cases start with the awaited state already present, so no step blocks (R7).
- **Brand and platform.** Default brand of a plain `go test` build; goldens contain default-brand
  literals (G1.3 test category). POSIX only (shell commands, paths): the test skips on Windows with
  that reason. Cases run sequentially.

adapter rule (`arch0-harness`). Adapter files start untagged and compile against the starting tree
(R1).

**Cases.** Exactly the 40 IDs of the Surface Inventory. A case names a base project, its state and
repository deltas, ordered preparation steps (any frozen CLI command, including other areas', or an
adapter call), one step under test, and its modes. A preparation step that fails fails the case
before comparison. Each mode of the step under test runs on a fresh materialisation of the case.
A case whose step under test cannot reach its declared outcome at the starting commit is a plan
defect: the unit marks BLOCKED naming the case, rather than substituting another entry or dropping
the case.

**Capture per step under test.** `json` mode: exit code and the stdout JSON document; if stderr is
non-empty, it is a `human` golden `<id>.json-stderr`. `human` mode: exit code, stdout and stderr,
content-normalised. `state`: the normalised `state.yaml` before and after the step, also for refusals
(asserting no effect). Adapter cases record `state` only: the `ops` result types are internal API,
not a frozen surface.

**Entry points.** CLI cases call the binary the harness builds, with the working directory at the
project root and the agent named by `--agent-id`. RC cases call the claim operation with the lease
unset; VP cases call the preflight preparation with an explicit session and a `local` execution
policy configured for the agent's tool; AE3 obtains its refusal from the claim entry and passes it to
the block operation. No private seam and no test-only production hook is used.

**Determinism.** As in Determinism Rules: root token, commit labels, explicit and pinned
environments, fixed fixture times, lease offsets, elapsed token, single-candidate claims,
non-blocking awaits, sequential cases, POSIX only.

**Goldens.** Created once by Scope 0's `write-new` run from the starting commit, never by live
tests. No ledger record is added (no C change in this task).
