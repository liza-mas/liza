## Goal

Complete the inherited ops mutation boundary with named operations and an executable guard,
without changing the state transitions those operations perform.

## Context

Based on source reads at integration/worktree HEAD `ce525e865a837857e2c0a8340d2f26785667c539`,
the supplied pinned authority, and the probes below. The current tree has five direct Blackboard
mutation sites outside ops/db and sixteen calls to `ops.ModifyWithAgentAuthority` in agent.
Ordinary log/file `Write` calls are not Blackboard writes. A9's merged architecture is available,
but its runtime consolidation is prospective; the downstream inheritance barrier supplies its
implementation before C6 coding. Paths below are discovery anchors, not a requirement to recreate
files that A9 splits.

This is completion of `ops-owner` and SI-4, not a new service framework or an ADR supersession.
No new package or third-party dependency is needed. Registration and recovery retain their distinct
operations because merging them into one generic patch API would move persistence while leaving
mutation policy with callers.

#### CONTRACT

**Responsibilities and direction.** Agent owns supervision, provider execution, in-memory trackers,
and decisions about when to request work. Commands and TUI own presentation and external setup.
Ops owns each named persistence operation, its locked state decision, and state/history updates.
Db retains locking, archive publication, encoding, liveness overlay and persistence mechanics.
Data flow is caller observations and typed intent -> named ops operation -> existing db transaction
-> typed result -> caller effects/output. Ops never imports agent, commands or tui.

**Inputs and results.** Pass task/agent identities, existing `models.AgentAuthority`, operation data,
and the observed transition/owner or pre-turn evidence actually used by the old path. Keep the
existing Blackboard handle where it carries patient/retry/cancellation configuration. Do not
replace it with a fresh default handle and lose its acquisition policy. Return values such as
registration authority, release witness, committed toggle value, claimed summary scope or recorded
observations explicitly. Callers supply no state-mutation callback, arbitrary patch map, or
function-valued ownership predicate. Read-only snapshot inputs are evidence, never replacement
runtime state to write. Whole-state initialization remains a specific construction operation;
migration remains a specific normalization operation, not a public generic Write adapter.
