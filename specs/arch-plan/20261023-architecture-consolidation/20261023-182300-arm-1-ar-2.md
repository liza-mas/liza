## Goal

Freeze every A2-produced surface behind two additive black-box oracle packages — one proving
artifact byte-identity at the producer, one proving command output and effects through the built
CLI — whose goldens the SI-3 entry point reproduces from the starting commit.

## Context

Based on: the carrier `arch-scope2` and its direct references, the Scope 0 harness contract
(`harness`), the A2 package sources and their importers at integration HEAD, and the probes below.

This document owns the A2 surface inventory, the A2/A7 artifact boundary reading, the split into
two oracle packages, and the fixture and environment rules those packages follow. Harness
behaviour (tree convention, golden form, adapter rule, normalisers, `write-new`/`check`, ledger)
stays at `harness`; this plan refines inside it.

### Constraints

Inherited by reference: frozen-surface rules (`goal-frozen`), oracle immutability (`goal-tests`),
E2–E5 (`goal-proof`), artifact byte-identity proof scope (`goal-success`), assignment rules and
depth (`arch-oracle-template`), H1–H7 (`arch-oracle`), harness CONTRACT (`harness`), oracle-file
ownership (`arch-files`), G1.1–G1.4 (`guard-tier1`).

New, local:
- **AC1** Additive only: every file this plan's children add lies under `internal/oracle/a2/**`.
  No production file, no existing test, no `Makefile`, no harness file, no ledger record.
- **AC2** No live host input: every CLI child process and every adapter call that reads the
  environment gets a disposable `HOME`, project directory and `TMPDIR`, no `SHELL`, and a `PATH`
  made of a per-test fixture directory of stubs. Rows whose output reflects `PATH` contents
  (`providers detect`, `toolchain doctor/install/configure`: tool and package-manager lookup is
  `PATH`-only, Q4) get exactly that directory; rows that need Git may add a fixture-directory link
  to the host `git`; stubs name their interpreter by absolute path. Any catalog
  URL points at an in-test loopback server or an unreachable loopback port. No network beyond
  loopback, no real provider or index CLI (E2), no installer execution (`toolchain install` only
  with `--dry-run`, E3), no `.liza/` of this repository (E4).
- **AC3** Linux-only: every A2 oracle test file carries a `linux` build constraint (combined with
  the harness's `oraclestart` tags where applicable). Rationale: goldens are written and
  regenerated on Linux (E1 local proof, the entry point runs on one host); six A2 producer sites
  branch on `runtime.GOOS` (Q11) and the fixtures use POSIX shell stubs and file modes; per-OS
  goldens could not be reproduced by the entry point. Cross-platform behaviour stays covered by the
  existing white-box tests in CI.
- **AC4** Default brand for the built CLI: the harness builds the CLI without brand ldflags, so CLI
  goldens assert default-brand output (G1.3 permitted category "tests intentionally asserting
  default-brand behaviour"). Non-default branding is asserted at the renderer (Scope 1, A-2).

## Decisions

- **Two packages by comparison class.** `internal/oracle/a2/artifact` (adapter-driven, kind
  `artifact`, byte identity at the producer) and `internal/oracle/a2/cli` (binary-driven, kinds
  `json`, `human`, plus `artifact` for files a command writes). Rationale: H4 compares the two
  classes differently; only the CLI package pays the harness's once-per-test-binary CLI build
  (H7); the packages share no file, so their tasks run in parallel.
- **A2/A7 artifact boundary** (rule 4 of `arch-oracle-template`, reconciled with `arch-a7`): A2
  owns the bytes an A2 producer writes or renders, captured by calling the producer directly in a
  disposable directory; A7 owns which artifacts init, setup and provider activation install,
  where, and the resulting `state.yaml`. `toolchain configure --project --agents` runs provider
  activation and is therefore A7's; `toolchain configure` without `--project` is A2's. Init
  diagnostics about index plans (rendered in `internal/commands/init.go`) are A7's; the planned
  index commands themselves become visible as the installed index script and hooks, which are A2's.
- **Large trees as manifests, small artifacts as bytes.** The rendered embedded tree and the
  global install set are snapshotted as a sorted manifest (path, mode, size, SHA-256) — a hash
  equality is byte identity (`goal-success`: "byte snapshots or hashes"), and a renderer change
  still fails it (H5). Every artifact written into a project, a hook directory or a global
  directory by a single writer is a byte golden, so a failure shows the diff.
- **One fixture brand.** The renderer is snapshotted for the default brand and for one fixed
  non-default fixture brand supplied as explicit values (never the host environment), because
  branded builds are distributed (Q13) and macro substitution is renderer behaviour.
- **Fixtures are committed inputs** under each package's `testdata/fixtures/` (fixture catalog,
  stub executables, hook payloads, fixture repository content); fixture Git repositories are
  created per test in temporary directories from those inputs (E2).

## Components

| Component | Path | Responsibility |
|---|---|---|
| A2 artifact oracle | `internal/oracle/a2/artifact/` | Byte identity of A2-produced artifacts, captured by adapters calling the producers |
| A2 command oracle | `internal/oracle/a2/cli/` | Output, exit code and file effects of A2-owned commands, run through the harness-built CLI |

Both depend only on the harness, stdlib and, in adapter files, the A2 producers (adapter rule,
`harness`). Neither is imported by anything.

## Interfaces

Harness → A2 oracles: `harness` CONTRACT, consumed unchanged. A2 oracles → reviewers and the entry
point: the per-scope inventories and goldens under the H2 tree. No interface between the two
packages.

## Data Flow

```
committed fixtures ─► adapter (producer call in temp dir) ─► normalise ─► compare / write-new ─► testdata/golden/artifact/
committed fixtures ─► harness-built CLI in temp HOME/project, explicit env ─► stdout, stderr, exit, written files
   ─► normalise (temp paths, timestamps, volatile ids, ordering) ─► compare / write-new ─► testdata/golden/{json,human,artifact}/
entry point: temp worktree @ start ─► sync-embedded ─► go test -tags oraclestart ./internal/oracle/a2/... (write) ─► check vs committed
```
