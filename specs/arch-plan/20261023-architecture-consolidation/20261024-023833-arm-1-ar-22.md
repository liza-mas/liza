## Goal

Connect the five C1 consumers to one effective duration derived from existing configuration,
without changing their ownership, persistence or presentation boundaries.

## Context

Based on pinned requirements and source inspection at worktree HEAD
`e37758ff6516026b62d2d4442717a292cfaccc30`, the integration merge of C6's architecture.
That architecture is delivered; its implementation is **PROSPECTIVE**, supplied by the inherited
C6 coding descendants. The current source still has pre-refactor paths and external mutation
closures. They are discovery anchors, not instructions to restore those paths after C6.

The existing `models.Config.LeaseDuration` is integer seconds and its existing named default is
`models.DefaultLeaseDurationSeconds`. Ops already reads that field with a non-positive fallback
in `renewLease`. Runtime registration and reviewer strategy instead supply literals; heartbeat
accepts a duration but supervisor does not supply one. Pool repair's site constructs a hypothetical
reviewer row, not a persisted registration. These differences determine the proof boundaries below.

The registry's older suggestion to derive a real terminal identity is not adopted: `changes` C1
explicitly preserves the stored value. No ADR supersession, new package, dependency or configuration
field is needed. This is a small completion of the existing ops service boundary, not a new policy
framework. No unresolved consequential assumption or design prerequisite remains.

#### CONTRACT

**Duration owner and representation.** Ops owns one pure resolver for effective lease duration,
consuming the existing config value and default from models. It returns the positive configured
seconds or the existing named default for a non-positive value, following the already-delivered
ops lease convention. Consumers convert seconds to `time.Duration` only at duration-taking APIs
or timestamp arithmetic. Keep unit meaning explicit; seconds must never be interpreted as
nanoseconds. Reuse an equivalent resolver if the preceding refactors deliver one; otherwise put
the minimal resolver beside the ops lease concern. Models remains the schema/default owner.

This chooses a shared ops seam over five repeated fallback expressions or a new configuration
service: agent and commands already depend on ops, and ops can consume models without importing
either caller. It avoids expanding the task into a models refactor. Do not migrate unrelated
timeouts or lease consumers merely to use the helper. Existing explicit-duration internal APIs
keep their override semantics; C1 fixes the runtime callers that currently pass hard-coded values.

**Agent startup.** Resolve existing project configuration during supervisor startup and pass the
same effective duration to registration and heartbeat construction. Registration remains the named
ops operation supplied by C6, with typed data and the existing authority result, lock policy,
collision/capacity checks, generation creation and cleanup. Runtime owns the terminal placeholder's
named constant, passing its unchanged string value into registration. It is not derived from a
TTY, agent ID or provider. A config-read error follows the existing error path; it is not treated
as absent configuration. Duration resolution creates no new persistent field.

**Heartbeat.** Retain the supervisor-lifetime heartbeat and its explicit duration input. The
configured value must reach the actual heartbeat object, not only a registration helper. Keep
standalone explicit-duration construction and existing heartbeat interval behavior intact.
Side-record publication, generation isolation, sequence ordering, overlay/folding, and the
active-provider-session condition on review renewal remain those of `liveness` and `authority`.
Assigned task and active review renewal therefore use the same duration as the agent heartbeat;
cleared ownership is not recreated. No lock-taking canonical heartbeat write is introduced.

**Reviewer claim.** The reviewer strategy reads the existing project configuration for its claim
and passes the resolved duration to the existing typed claim operation. All role strategies using
this generic reviewer path receive it; do not special-case the code reviewer. Keep candidate
selection, initial-task targeting, validation preflight, lease ownership, authority and failure
classification unchanged. Reading config does not authorize a claim; final transaction checks
remain authoritative.

**Re-review reclaim.** The existing ops reclaim path derives its fresh review duration from the
project state it already reads, rather than the fixed reclaim duration. Retain both early
resubmission and reservation-held reclaim paths. Preserve the existing clock instant/zone and
transaction placement apart from substituting the configured duration; maintain status/owner,
reservation and review-boundary revalidation. The inherited final `CheckCurrent` and review
boundary checks remain where they are under `d33`. No additional Git/exec under the lock.

**Pool repair.** Use the resolver against the supplied state when constructing hypothetical
reviewer registration rows in the start planner. All rows, including models.yaml slot variants,
receive the configured lease. This is a projection used for eligibility and ID allocation; do
not persist the hypothetical row or change capacity/provider/slot selection. Actual starts use
the supervisor startup flow above.

**Sampling and failures.** Resolve against the state each operation already consumes, with startup
providing the common registration/heartbeat value. C1 adds no subscription, timer or promise of
hot reconfiguration of an already-running heartbeat. Existing error codes/chains and refusal
paths stay intact. Do not turn unreadable state into a successful default-valued operation.
No new authority checks, weakened fences, migrations or output labels are part of this change.

**Provider asks and consumers.** This functional-spec run has no epic stage and the tracked tree
contains no `specs/epics` inventory. The source-backed consumer set is the five C1 sites in `parent`;
the merged master, A9 and C6 contracts reserve those sites for C1. The bounded SI-4 search found
the preservation scopes and subsequent C scopes, not another declared lease-policy API consumer.

| Interface / consumer | Operation, data and status needs | Provider answer |
|---|---|---|
| Configured duration / all five C1 sites | Existing config seconds to an effective duration; no new status | Shared pure ops resolver above; default remains model-owned. |
| C6 registration / supervisor | Existing registration inputs plus the effective duration and terminal; authority result | Consume C6's named operation; no mutation callback crosses into ops. |
| Liveness / heartbeat | Effective duration and current authority; existing record fields | Keep ADR-0177 publication and overlay, with only the duration input changed. |

| Pool projection / commands | Config and projection time to hypothetical reviewer lease | Same calculation, no runtime write or new dependency. |
