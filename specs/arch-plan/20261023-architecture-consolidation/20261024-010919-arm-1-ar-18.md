## Goal

Leave initialization with one implementation, the CLI path, by deleting `ops.InitProject` with its
tests and ratchet entry, and make every Git subprocess that path runs carry `gitenv`'s environment
and timeout and run against the project root, changing nothing else.

## Context and Decisions

Based on the pinned references, source reads and the probes below at integration
`a904301641f2688f6267b3886b5617985f365141`. At that SHA the init production files, `gitenv`,
`paths` and the `await` integration fixture equal the starting commit `96c9ad69a` (RP1); the A7
refactor (Scope 17 coding, `arm-1-ar-17`'s code plan) has not started, so function names and files
below are as of today and PROSPECTIVE after Scope 17 (D-6).

**Init Git census (RP2, RP3).** The CLI init path runs Git through two routes:

| Route | Sites | Environment | Timeout | Directory |
|---|---|---|---|---|
| `gitenv.Command` (untimed constructor) in the init branch helpers | `check-ref-format --branch <name>` (branch-name validation); `rev-parse --verify <name>`, `rev-parse --verify HEAD` (integration-branch existence and born-HEAD check); `branch <name> HEAD` (integration-branch creation) | `gitenv` (`LC_ALL=C`) | none | inherited process directory |
| `gitenv` timed runners (`Output`, `CombinedOutput`) in packages init calls | project-root discovery (`paths`), spec and pre-commit config checks (`initcheck`), `.git` path lookups for contract activation and repo excludes, SCIP init file listing, pairing index hook installation | `gitenv` | `gitenv.DefaultCommandTimeout` | explicit: the discovered project root (discovery: the process directory) |

Only the four helper subprocesses violate C4; the timed-runner sites already comply and are not
touched. Pairing init reaches none of the four helpers (RP3). Tools init launches that spawn Git
themselves (pre-commit, Semble, bash-policy) are not Liza Git subprocesses. `cmd/liza/cmd_launch.go`
`--cwd` is Won't (`goal-wont`).

**Observable effect (RP4).** Project-root discovery resolves a linked worktree or subdirectory to
the main project root, and the spec and pre-commit config checks already read that root's `HEAD`.
The helpers instead run in the process directory: from a linked worktree, `branch <name> HEAD`
creates the integration branch at the linked worktree's `HEAD`, not the root's. C4 removes this
divergence. When the process directory is the project root, as in every install oracle case
(RP6), nothing observable changes.

**D-1 Deletion.** `internal/ops/init_project.go` and `internal/ops/init_project_test.go` are deleted
whole: every declaration in them is private to them (RP5). Their tests are deleted outright, as the
goal rules (`goal-changes` C4); the one test not named after `InitProject`
(`TestGlobalIntegrationGenerationLimitDefaults`) drives `InitProject`, and its asserted value is
already asserted on the CLI path (RP5). The A7 ratchet entry for `InitProject` is removed in the
same commit, because the guard reports a stale entry once the file is gone; the start snapshot is
never edited (`size`). The only other caller is the integration fixture `setupIsolatedAwaitProject`
(test support, outside every area, `areas`), used by `TestAwaitResubmission_TerminalFlow`: it moves
to the reference CLI init entry, following the existing `full_sprint_test.go` precedent (global
setup fixture, process directory at the project, committed spec), with the test's lifecycle
assertions unchanged (X2 call-site update, `moves`). `scripts/ci/testshard/windows-weights.json`
keeps its `TestInitProject_*` keys: weights for absent tests are never looked up and the file is
refreshed from CI by the maintainer (RP5).

**D-2 Timed runners, same commands.** Each of the four helper subprocesses runs through `gitenv`'s
existing timed runners with an explicit directory, keeping its argument vector and the stream it
reads today: combined output for `check-ref-format` and `branch`, exit status only for the two
`rev-parse` checks. The timeout is `gitenv.DefaultCommandTimeout` (A2, unchanged). No new runner,
option or configuration field. Rejected: `internal/git.Git` methods, whose existence check reads
`refs/heads/` only (today's check accepts any ref name) and whose error text differs; a shared
init Git runner, rejected for A7 already (`a7-components`, D-2 of `arm-1-ar-17`) and unnecessary
because `gitenv` is that runner.

**D-3 Project root before the first helper, errors where they are.** The integration-branch checks
and creation run in the discovered project root. Branch-name validation precedes discovery today,
and several validations (agent env deny, providers, pipeline config, entry point, validation
execution) sit between them, so moving discovery's error earlier would change which error a
non-repository directory reports first (`goal-frozen`). Discovery therefore runs before branch-name
validation, its result is reused (one discovery, as today), and its failure is reported at today's
position with today's text; the legacy-root warning keeps its position. Validation runs in the
project root when discovery succeeded and in the process directory when it failed, which is
today's behaviour in the only case where no project root exists (init then fails at discovery's
position as today). Discovery itself runs from the process directory by definition: it is the
query that finds the root.

**D-4 Timeout is a failure, never an answer.** A subprocess killed by the timeout is reported as an
error wrapping `gitenv`'s timeout error. It is never read as a negative answer: not as an invalid
branch name, an absent branch or an unborn `HEAD`. Every non-timeout outcome keeps today's control
flow and error text, including `not a valid git branch name: …`, `repo has no commits (HEAD is
unborn)` and `git branch failed: …`, and the wrapping prefixes added by the init entry. The timeout
error's text is new in a case that could not occur before.

**D-5 K1 and placement.** No Git subprocess runs inside a blackboard transaction (init writes state
with `Write`, outside any `Modify`); C4 adds none. The helpers stay in the A7 init concern (Scope
17's K-INIT placement, `a7-components`); no Git code moves to `ops` or A2. Edits must not create an
S1 offender: the guard reports any new function over 100 or file over 800 lines (`size`).

**D-6 Plan from contract, resolve at coding.** Planning may precede Scope 17 coding (`sequence`:
only coding is sequential). The code plan names the sites by behaviour: the four helper
subprocesses above, the project-root discovery of MAS init, the `InitProject` ratchet key and the
`await` fixture. The coding unit resolves their functions and files at its integration HEAD,
where Scope 17 has preserved them unchanged (`a7-sites`, C4 rows), records them in its acceptance
evidence, and marks BLOCKED naming `a7-sites` if a helper was merged into a runner, rebuilt
differently, or `InitProject` or its ratchet entry is missing.

#### CONTRACT

The CLI init path (`internal/commands`) is the only initialization implementation; `ops` exposes no
initialization entry (`goal-changes` C4). The four init helper subprocesses (`check-ref-format
--branch <name>`, `rev-parse --verify <name>`, `rev-parse --verify HEAD`, `branch <name> HEAD`) keep
their argument vectors and run through `gitenv`'s timed runners with `gitenv.DefaultCommandTimeout`
and an explicit directory, the discovered project root (D-2). MAS init discovers the project root
once, before branch-name validation, reports a discovery failure at today's position with today's
text, and validates the branch name in the project root, or in the process directory only when
discovery failed (D-3). A timeout surfaces as an error wrapping `gitenv`'s timeout error and is never
read as an invalid name, an absent branch or an unborn `HEAD`; all other outcomes keep today's
control flow and error text (D-4). Every other init behaviour, output, state effect and Git site is
unchanged (`goal-frozen`, `change-template`). No Git subprocess runs inside a blackboard
transaction; no Git code moves out of the A7 init concern; no S1 offender is created (D-5).
