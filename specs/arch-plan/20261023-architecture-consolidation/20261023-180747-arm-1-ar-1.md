## Goal

Freeze A1's externally observable behaviour as two black-box oracle packages — one driving the
built CLI, one driving A1's persistence entry points through adapters — whose goldens are created
by and reproduced from starting commit `96c9ad69a`.

## Context

Based on: the carrier `arch-scope1` and its direct references, the Scope 0 harness contract
(`arch-harness`), direct reads of `cmd/liza/{cmd_init,cmd_usage,cmd_system,rbac,agent_generation}.go`,
`internal/commands/{validate,validate_payload,usage_report,analyze}.go`, `internal/ops/analyze.go`,
`internal/{alerts,usage,analysis,db,pipeline,statehygiene}`, an importer map of every A1 package,
and the probes below.

This document owns: the A1 surface inventory and its assignment rationale, the split of the A1
oracle into two packages, fixture classes, and per-surface golden sets. Harness, tree convention,
golden form, adapter rule, ledger and entry point stay at `arch-harness`; assignment rules and depth
at `arch-oracle-template`.

### Constraints

Inherited by reference: oracle immutability and black-box policy (`goal-tests`), E2/E4/E5
(`goal-proof`), oracle proof scope (`goal-success`), frozen-surface comparison rules
(`goal-frozen`), SI-3 H1–H7 (`arch-oracle`), tree convention, golden form, adapter rule and
`write-new` (`arch-harness`), assignment and depth (`arch-oracle-template`), additive oracle files
(`arch-files`), G1.3/G1.4 (`guard-tier1`).

New, local:
- **AC1** Files created only under `internal/oracle/a1/**`. No harness file, no `PROVENANCE`
  record, no production file and no existing test is touched. A capability missing from the
  delivered harness is supplied by stdlib-only code inside the A1 package, never by editing the
  harness.
- **AC2** Fixtures carry no value whose outcome depends on wall-clock time (no live lease or
  heartbeat, or one dated far beyond any run); every value a golden asserts comes from a fixture or
  from a normalised volatile field, so goldens are time- and host-independent.
- **AC3** Fixtures are committed inputs: authored by hand or generated once with the starting tree,
  then never regenerated (E5).

## Components

| Component | Path | Responsibility |
|---|---|---|
| A1 CLI oracle | `internal/oracle/a1/cli/` | Drive the CLI built from the tree under test against committed fixtures; golden V, VP, PR, U, AR |
| A1 persistence oracle | `internal/oracle/a1/persist/` | Drive A1 persistence entry points through adapter files; golden S, AL, UR |

**Why two packages:** the CLI package imports no production code, so it never needs adapter twins
when A1's API moves; the persistence package concentrates every call-site-only exception
(`goal-tests`) in its adapter files. A binary build happens once per test binary
(`arch-harness`), so binary-driven surfaces share one package. The two share no file and commute.

## Interfaces

**Harness → A1 oracles** (`arch-harness`, consumed as delivered):

| Need | Harness answer | If the delivered harness lacks it (AC1) |

| Build the CLI once per test binary; run it in a disposable project | CLI helper | — |
| Driver-supplied environment entries (PR's agent generation) on an explicitly built base | "explicitly built environment" | Driver runs the CLI with `os/exec` and its own explicit environment (building it with `go build` if the helper exposes no binary) |

## Data Flow

```
committed fixtures ──► temp project (.liza/state.yaml, pipeline.yaml, usage/, README, payloads)
  cli:     built CLI ─► stdout / stderr / exit ─► normalise volatile ─► json|human goldens
           analyze  ─► .liza/circuit_breaker_report.md ─► normalise Analyzed, paths ─► human golden
  persist: fixture ─► adapter(load) ─► adapter(persist) ─► bytes ─► state goldens (before/after)
           fixed alerts / records ─► adapter(write) ─► log, ledger, day files ─► state goldens
regen write-new @ 96c9ad69a ─► goldens committed;  live go test and regen check ─► compare
```

## Cross-Cutting Concerns

| Concern | Approach |
|---|---|
| Environment safety | Base environment built explicitly per run (temp `HOME`, `TMPDIR`, minimal `PATH`); no inherited agent identity; PR adds only the generation variable; messages name variables, never values (G1.4, E4) |
| Repository safety | Every run in its own temp project; no Git repository needed (fixtures carry no ref fragment, so `validate` never resolves the integration branch); never `.liza/` of this repository (E4) |
| Determinism | AC2; explicit usage window; `--skip-process-checks`; volatile values: the report's `Analyzed` stamp and absolute temp paths |
| Branding | Default-brand literals (`LIZA_AGENT_GENERATION`, `liza resume` in the report) are permitted test literals asserting default-brand behaviour (G1.3) |
| Platforms | Paths via `filepath`; temp-path normalisation covers separators; no host-specific scan |
| Proof budget | Estimate, unmeasured: `cli` one link of `cmd/liza` (seconds warm) plus ~20 CLI runs under 0.2 s each; `persist` under 2 s; both inside `make test`, cases parallel-safe (own temp dirs). Regeneration: one `go test` per package per tree, run by reviewers and gates. Well inside H7 |
