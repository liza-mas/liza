#### CONTRACT

**D1 — Launch capability below the runtime.** Create `internal/agentlaunch` as A9-owned
infrastructure in SI-1. It owns effective tool registry construction, CLI/profile/model selection,
role-model validation, launch-plan rendering, executable prerequisite lookup and default-role
validation policy. Move the corresponding responsibilities from launch_resolver.go,
launch_selection.go, role_models.go, validation_policy.go and the non-backend parts of cli.go.
Keep `internal/providers` as catalog owner and `internal/rolemodels` as file/schema owner; do not
merge them or create a parallel registry. This package is callable by agent, commands, tui, process
and later ops without importing runtime, application, prompts or presentation.

Inputs remain tool names, config, role types, role-model selections and request values; outputs
remain the selection and resolved launch description, including distinct ToolName, ProviderKey,
ContractKey, argv, prompt transport, profile/model, session identity and environment-file metadata.
Preserve defaults, copy semantics, ordering, optional versus explicit environment files, current
cache/load behavior, error text and error order. ResolveLaunchPlan must shrink under S1 in its
original location before it moves; split validation/default resolution from argument and session
template expansion. The helper that builds the default ACP session name moves with its pure
formatting dependencies, not with runtime execution. No provider process, registration, worktree
operation or environment-file loading is added to this resolution boundary.

Backend construction (`NewLLMAgentForCLI*`), actual execution, masking, environment preparation and
usage events remain in agent. The registry is the lower-layer input C2 needs; this scope does not
apply canonical identity to diversity, anomalies or stop policy. C2 owns its policy-time derivation
and may reuse the registry rather than launching or rendering a complete command. No new config.

**D2 — Provider signals as infrastructure.** Create `internal/providersignal`, A9 infrastructure,
for quota/unavailable detection, diagnostic-line extraction, reset-time interpretation, signal path
and record handling, quota sweep and corresponding alert-file writes. Move the relevant parts of
quota.go, quota_reset.go, provider_unavailable.go and provider_diagnostics.go together. Keep the
existing per-provider distinctions, matching order, timestamp representation, unreadable-file
handling, clear results and errors. Its API accepts project root/tool identity/output and returns
existing result records (including quota cleared/held/failures), without a blackboard handle.
It may use agentlaunch's existing alias derivation after extraction; that derivation is distinct
from the prospective C2 policy and retains today's values.

`commitQuotaTerminationWIP` and supervisor output-file discovery stay in agent: they involve task
ownership or runtime execution artifacts. They call providersignal for classification only. Signal
file I/O is not a license to move blackboard mutations. Resume and TUI keep their existing sequencing
of signal cleanup and state changes; consolidate the implementation of signal primitives, not the
different presentation error/reporting policies. Process spawn calls the extracted checks in the
same order and retains readiness protocol, reaping and platform behavior.

**D3 — Explicit residual SI-5 crossings.** All presentation uses of launch and signal capabilities
migrate in the same coding unit, including init's RoleCLI/DefaultRoleCLIs/ValidationExecutionLocal
and watch's LoadValidatedRoleModels/RoleTypesOf; do not stop at the older three-file issue inventory.
The source scan distinguishes local variables named agent from package symbols.

Two query uses may remain, with these per-symbol rationales in A9's allowlist entry:

- commands/status: `DetectOrchestratorWakeTriggersForProject` and `OrchestratorWakeResult` expose
  the runtime's read-only wake projection. Keeping this adapter avoids duplicating runtime wake
  precedence or dragging ops/prompts dependencies into infrastructure. It grants no mutation
  authority; it continues using the A8-delivered projection records.
- tui/view: `RolePauseReason` exposes the same snapshot-only pause reason the runtime displays;
  retaining this pure query avoids a second role/checkpoint predicate. No waiting, resume or
  mutation side effect crosses the interface.

No other presentation-to-agent capability is authorized by those rationales. Audit the final
production import sites and extend the symbol list only for an evidenced equivalent query with
reviewed rationale, or remove the edge. Remove stale allowlist entries when an edge disappears.
Keep the agent/db entry assigned to C6; this task neither declares C6 complete nor disguises that
edge behind a forwarding package. `cmd/liza` remains the composition root.

**D4 — Supervisor lifetime and turn responsibilities.** Keep the existing RoleStrategy and
LLMAgent boundaries, which absorb the real doer/reviewer/orchestrator and CLI/ACP variations.
Within agent, separate supervisor setup/lifetime cleanup, work admission/claim, prompt preparation,
provider session execution, and completed-turn/restart policy into cohesive files/helpers.
RunSupervisor remains the ordered coordinator; no event bus, generic state-machine framework,
additional service or third-party dependency is needed. A private supervisor lifetime record may
carry the existing context, authority, strategy, trackers and cleanup state; it is not persisted.

Setup owns identity/environment withholding, frozen pipeline strategy, pending-verdict replay,
registration and lifetime heartbeat/cleanup. A turn owns its claimed versus effective task IDs,
snapshot and output. Keep heartbeat lifetime across idle waits, initial-task spending on claim,
surplus retirement, the two role gates, heartbeat-error precedence and independent cleanup context.
Preparation retains selected-wake revalidation and prompt-failure blocking targets. Completed-turn
handling preserves verdict replay, quota WIP before release, release witness, provider audit,
background-job preservation and exit-specific tracker resets. Explicit local outcomes may replace
nested continue/return branches, but their values and control effects must remain the same.

`executeAgent` separates validation/session preparation, gated start, interactive execution,
watchdog lifetime and result classification. The gate still owns the same lifecycle -> admission
lock nesting, current-generation/review/validation checks and start boundary. A start-attempted
marker must not move later than the actual effect; only contention proven before start is retryable.
Keep gate failure distinct from backend failure even when a backend returns an exit code. No Git,
provider start or exec enters a new Modify callback; retain inherited final revalidation under D33.
ADR-0130 and ADR-0177 remain binding. Neither PID observation nor a snapshot alone becomes authority.

**D5 — Runtime concern helpers.** CLI and ACP backends retain their separate start/wait behavior
and LLMAgent result shape. Split command/prompt-file preparation, stream/event wiring, gated launch
and completion mapping, retaining mask boundaries, cleanup ownership and event order. Share only
existing common mechanics, not a generic backend algorithm that erases their differences.
Claiming separates resume selection, candidate attempts and merge-candidate processing while
preserving handoff -> owned -> fresh priority and nil-authority compatibility paths. Restart tracking
separates in-memory progress/backoff calculation from its existing fenced persistence; the closure
stays in agent. Worktree recovery separates eligibility/attachment, post-worktree/index preparation
and history recording, keeping failure classes and ordering. Waiting separates snapshot evaluation
from watcher/timer mechanics, keeping cancellation, stop/surplus precedence and polling fallback.
Orchestrator completion verification dispatches to concern helpers by existing trigger; it does not
reinterpret a trigger or turn a warning into a refusal. Use the A8 result types when delivered.

**D6 — Vocabulary owners.** Adopt delivered roles, pipeline, models and alerts constants instead
of creating parallel enums. Launch selection source, backend and transport vocabulary belongs to
agentlaunch; runtime-only turn outcomes, stream/event kinds and restart categories belong to agent.
Signal record vocabulary belongs to providersignal. Existing strings at YAML/JSON/command boundaries
retain their spelling and unknown-value behavior; explicit conversions do not add rejection paths.
Name local retry/delay/size/threshold literals at their concern owner, preserving values. Audit every
A9 production file and extracted package, not only S1 offenders. YAML role names, tool names,
profile names, role-pair identities and configured values stay dynamic. C1 owns the terminal-1
constant and lease-policy change; leave those reserved sites for C1, while retaining existing named
heartbeat constants. C2/C3 policy evaluation remains unchanged.
