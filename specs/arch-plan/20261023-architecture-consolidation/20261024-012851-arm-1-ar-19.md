#### CONTRACT

**Component boundary and data flow (D1).** Runtime assembly in `internal/agent` owns obtaining
read-only application results and frozen-pipeline entry-point metadata. `internal/prompts` owns
presentation records, formatting, template execution and block composition. `internal/models`
owns shared domain result records. `internal/ops` continues to own queries and mutations.

`state snapshot + project/pipeline context -> runtime resolution -> resolved prompt records ->
embedded templates -> prompt bytes`. For status: `commands -> ops result -> shared domain records
-> prompts integration projection -> existing status fields`. No new query framework, interface
with one implementation, dependency, service or configuration field is introduced (K5/K6).

Prompts must not obtain business context through callbacks that secretly call ops. Resolve data
before invoking the renderer. Keep ops queries in ops; do not copy their classifiers into prompts.
This chooses the caller-resolution option in `issue` and SI-5 rather than a broad shared query
package: the runtime already owns the production dashboard call, while the shared projection
needs only data. The read model absorbs the actual selected-wake and standalone-render paths.

**Resolved dashboard input (D2).** The runtime supplies the snapshot and the additional values the
dashboard currently derives from ops: cycle-blocked count, eligible planning tasks in planned-task
order, their classification/blocker/correction details and plan refs, ready many-to-one count,
actionable blocked IDs/count, actionable hypothesis-exhausted count, held-plan result and unseen
human notes. It resolves entry-point routes, display names, task types and prefixes from the frozen
pipeline before rendering. Prompts may calculate formatting-only totals from the supplied snapshot.
Keep raw displayed blocked/hypothesis counts distinct from actionable counts used to select a wake.

The selected-wake path supplies the revalidated trigger and integration projection together and
does not select a replacement wake. The standalone path retains its current selection precedence,
held-plan suppression and blocked-planning-handoff exception. Moving resolution must not turn
detection-context fallback into a fatal error, hide entry-point errors, read a different state
snapshot, or reorder integration evaluation and entry-point error handling. Nil blocked scope on
the stateless measurement path remains distinct from a computed empty actionable set.

**Shared result types (D3).** Move the data declarations `IntegrationProgressDecision`,
`IntegrationScopeCoverage`, `IntegrationAnalysisRequest`, `IntegrationProgressReason`, and
`ReconcileIntegrationAnalysesResult` from ops to models, with fields, tags and nil/zero semantics
unchanged. Move `PlanHandoffClass` and its constants to models; its classifier/domain/resolver
remain in ops. These are X3 moves of the types prompts reads, not a new persisted state schema.
Ops exposes the domain records through its existing operations; prompts' pure
`ProjectEffectiveIntegrationCompletion` consumes them. Preserve projection precedence, sorted
copies, reconciliation-reason override, created IDs and deferred-validation indication. Status,
runtime, tests and any other callers migrate in the same coding unit; no permanent aliases.
No mutation body or query implementation moves across the ops boundary.

**Template inputs and structure (D4).** Supply the test-file matcher display text from the runtime
using the existing ops matcher query. Carry it through task context, planning-wake context and
stateless wake-measurement inputs. Replace the ops-calling template function with resolved data;
test and benchmark callers supply equivalent explicit data. Do not duplicate matcher lists or
change the TDD gate. Preserve comma-space joining and current order.

Keep the two existing embedded template sets and their single loader. Separate the static
orchestrator command/instruction text currently inside builder.go into an embedded template,
leaving dynamic dashboard formatting separate. Existing block names, invocation order and
whitespace semantics remain the interface; do not reorganize unrelated templates for symmetry.
If a template path changes, the embed pattern and test-support readers follow together. Content,
including brand substitutions and final newlines, stays frozen; this is structure, not editing
instructions for brevity. No runtime filesystem template fallback or duplicate loader is allowed.

**Task and reference assembly (D5).** Keep orchestration in agent; separate identity/task values,
repository-intelligence discovery, recovery/review context, integration evidence, planner navigation
and reference provenance into cohesive helpers/files within that package. Reuse existing
prompt_planner_context and prompt_corrective_context boundaries rather than adding abstractions.
Keep error-returning stages ordered, and retain intentional ignored-error behavior where it exists.

Reference context retains one lazily captured integration HEAD per build. Separate scalar-carrier
collection, reviewed parent/review-range collection, assigned-section presentation selection, and
legacy filtering. Preserve scalar ranking, same-file fragment agreement, parent-range precedence,
proof-policy drift checking, mandatory validation before elision, reviewer attribution refusal and
the notice/fallback behavior for historical malformed read sets. Rendering is still delegated to
referencecontract. These are concern boundaries, not fixed-size function slices.

**Vocabulary (D6).** Adopt A1/A4-owned constants where already delivered; do not recreate them.
Prompts owns typed wake-rendering and integration-view status vocabulary (current string values
unchanged). Shared handoff classes have the D3 domain owner. Existing runtime wake types may use
explicit conversions at the rendering boundary; no A9 control policy is changed. Name local
digest/truncation/recovery limits and reference rank values where they determine control flow.
Examples observed in source: active task display limit 12, blocker truncation 220, parent
description truncation 500, prior-attempt branch 2. Preserve all values and any existing constants.
Role names, role-pair names, task prefixes, context-section configuration and other YAML-defined
identities stay open strings (ADR-0045). K7 does not authorize fixing custom-role behavior.
