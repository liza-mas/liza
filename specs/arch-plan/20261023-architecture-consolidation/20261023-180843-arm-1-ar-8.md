## Data Flow

```
fixtures/<id>/ ──► driver: temp case root (EvalSymlinks) ─► HOME + project/
   repo content ──► git init -b <integration branch>, commits with fixed identity and dates
   state.yaml template ──► resolve root token and commit labels ──► <runtime dir>/state.yaml
   adapter: embedded pipeline ──► <runtime dir>/pipeline.yaml
driver: pin gates and Git variables (t.Setenv), optional Semble stub on PATH
adapter: LoadFrozen ─► NewResolver ─► NewRoleStrategy(role) ─► ReadSnapshot ─► BuildPrompt
driver: replace case root with token ─► harness: live compare | write mode (regen at start)
```

## Determinism Rules

- **Root token.** Each case uses one temporary root, resolved through `filepath.EvalSymlinks`
  (macOS `/private`), holding both the project and HOME. The driver replaces that root, wherever it
  appears in the prompt, with one fixed token. The golden holds the token.
- **Environment.** For the test's duration the driver sets: the four gate variables (enabled only
  for T15), HOME, `GIT_CONFIG_GLOBAL` (an empty file under the root), `GIT_CONFIG_NOSYSTEM`, and
  the Git author and committer name, email and date. T15 prefixes PATH with a stub `semble`. Cases
  run sequentially (`t.Setenv` forbids `t.Parallel`). Brand: the default brand of a plain `go test`
  build (R12); goldens contain default-brand literals, a G1.3 test category.
- **State.** The case's `state.yaml` is written to disk and read back through the blackboard, so
  the state schema the supervisor parses is what the prompt sees. Timestamps in state are fixed
  literals. The state template may reference only the root token and the fixture repository's
  commit labels, which the driver resolves.
- **Config.** `SupervisorConfig` carries Role, AgentID, ProjectRoot, SpecsDir, StatePath, CLIName
  (`claude`) and, for T15 only, InitialTask; no provider is executed.
- **Wake path.** The orchestrator prompt is built with no prior wait, so the wake trigger is
  derived from state by the renderer (R7, R8). Wake selection and revalidation are A9 behaviour,
  not a prompt surface. Each W case's manifest names its expected trigger; the driver fails the
  case before comparing when the rendered `WAKE TRIGGER:` line differs.
- **Platforms.** Prompts embed native paths, so the goldens are POSIX renders. The test skips on
  Windows with that reason; Linux and macOS run it.

## Cross-Cutting Concerns

| Concern | Approach |
|---|---|
| Error handling | A render error, missing golden, wrong wake trigger or missing listed section fails the case naming its ID and golden path; a byte difference reports the first differing line number and the two lines (prompt text only) |
| Environment safety | No host value enters a fixture or a message; failures name variables, never values (G1.4); fixture repositories are disposable (E2); live project state is never read (E4) |
| Immutability | After merge, fixtures and goldens change only under the `goal-tests` exceptions |
| Prompt conciseness | No template text is added (`guard-g22`) |
| Proof budget | About 30 renders plus 30 small Git repositories, about 1–2 s per package run (estimate from R5: 42 renders and 42 repositories took 0.70 s), inside `make test`; regeneration adds one package run at start, inside H7 |

#### CONTRACT

**Package.** `internal/oracle/a8/`, test-only, following Scope 0's tree convention, golden form
(`prompt` kind, raw bytes) and adapter rule (`arch0-harness`). Adapter files hold every import from
this module; they start untagged and compile against the starting tree (R1).

**Cases.** Exactly the 30 IDs of the Surface Inventory, one golden each, named `<id>.txt`. A case's
fixture directory holds: a manifest (role, role pair or none, agent ID, task ID, expected wake
trigger for W cases, gates on or off, initial task, one marker line per "Reaches" branch);
the fixture repository's ordered commits as file trees with labels, and its integration branch;
the `state.yaml` template. The driver fails a case whose render lacks a manifest marker or, for W
cases, the declared `WAKE TRIGGER:` line, before comparing. A case whose state cannot reach its declared branches or trigger at the
starting commit is a plan defect: the unit marks BLOCKED naming the case rather than substituting
another render path or dropping the case.

**Render path.** Per case: materialise the root and fixture repository, freeze the embedded pipeline
into the project runtime directory as `init` does (R3), write and re-read state through the
blackboard, then `pipeline.LoadFrozen` → `pipeline.NewResolver` → `agent.NewRoleStrategy(role)` →
`BuildPrompt(snapshot, SupervisorConfig, taskID)` (R2). No other production entry point and no
private seam is used.

**Determinism.** As in Determinism Rules: root token, pinned environment, fixed Git identity and
dates, sequential cases, POSIX only.

**Goldens.** Created once by Scope 0's `write-new` run from the starting commit, never by live
tests; byte-identical comparison of the root-substituted render. No ledger record is added (no C
change).
