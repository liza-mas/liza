## Goal

Bring A1 under S1 by separating the concerns of its ten offenders inside their own packages, then
make A1's finite control-flow vocabulary typed and its magic values named, without changing any
frozen surface or any API outside A1 beyond call-site conversions.

### Constraints

Inherited by reference: frozen surfaces (`goal-frozen`), closed C list (`goal-changes`), K1–K7
(`goal-structure`), oracle immutability and white-box policy (`goal-tests`), N1 (`goal-nfr`), E1,

(`arch-layers`, `arch-size`, `arch-oracle`, `arch-mutation`), Refactor Scope Template
(`arch-refactor-template`), G1.1–G1.4 (`guard-tier1`), ADR-0045 (`adr-0045`).

New, local to A1:
- **AC1 Message text frozen.** No error, refusal or validation message text produced by A1 code
  changes, and violation/diagnostic emission order is unchanged. This is stricter than
  `goal-frozen` (which allows unclassified text to change) and is chosen because
  `statevalidate`, `payloadschema` and `referencecontract` messages reach `--json` envelopes whose
  substring classification makes the classified/unclassified split costly to audit per message.
- **AC2 No marshaling methods on vocabulary types.** A vocabulary type is a defined type over
  `string` with no `MarshalYAML`, `UnmarshalYAML`, `MarshalText`, `UnmarshalText`, `MarshalJSON`,
  `UnmarshalJSON` or `IsZero` method: the blackboard writer projects string-kinded values by kind
  and treats method-bearing types as opaque (`internal/db/yaml_write.go`), so such a method would
  change the persisted bytes path (RP6).
- **AC3 `any` boundary.** A value of a vocabulary type never reaches an `any`-typed container,
  parameter or template data where it is later asserted or switched as `string`; at such a boundary
  it is converted to `string` explicitly. A boxed defined type fails `.(string)` (RP6), which
  would silently change behaviour.
- **AC4 Outside-A1 edits are call-site conversions plus conformance updates.** Callers in A2–A9
  and oracle adapters adapt to A1 API changes by conversions or by naming the new constant at the
  call site. Where Go type identity requires more — a non-A1 interface whose method an A1 type
  implements, or a function-typed variable, field or parameter that receives an A1 function or
  method value — that declaration's affected positions take the V-type, together with every other
  implementation and test double of it (conformance update, RP11). Nothing else in a non-A1
  signature, field or control flow changes (X2); retyping other non-A1 APIs is adoption by their
  own area (X7).
- **AC5 `db` mutation API stable.** `db`'s exported blackboard API (read, modify, write and
  liveness entry points) keeps its signatures, so no C6 site (SI-4) is touched by A1.

## Interfaces

**A1 → later areas (V1–V12).** Exported defined types and constants of the A1 Typed Vocabulary (Scope 2 CONTRACT). Direction: A2–A9 import
them; nothing in A1 imports A2–A9 beyond today's infrastructure edges (RP3). Invariants: AC2, AC3;
YAML tags, JSON keys and field names unchanged (`goal-frozen`); every changed exported signature
is a V-type substitution, whose K6 justification is the consumer-side literal variation it removes
(RP4 counts).

**A1 → oracle adapters.** Persistence adapters (`a1-oracle`, `internal/oracle/a1/persist`) and any
other oracle adapter compiling against an A1 API adapt by call-site-only edits under the adapter
rule (`arch-harness`: first edit splits an `oraclestart` twin); no golden, fixture or `PROVENANCE`
change.

**Provider asks.** No epic stage and no merged consumer citing this interface (RP10); the master
names later areas as adopters (X7) and none has frozen a need. Later areas raise a missing set as a
correction to this area's owner, not by redefining it.
