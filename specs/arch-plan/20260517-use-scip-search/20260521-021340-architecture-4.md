# Architecture Plan: scip-search Operator Documentation

Status: review

## Goal

Define the operator-facing documentation plan for positioning `scip-search` as Liza's highly recommended opt-in MAS repository index tool while preserving `ast-grep` as the complementary structural search tool and documenting the explicit non-goals.

## Context

This slice covers the documentation portion of success criteria 4 and 12 from `specs/goals/20260517-use-scip-search.md`, plus setup guidance requested by task `architecture-4`. Earlier architecture slices define init configuration, runtime indexing lifecycle, prompt injection, and Claude permissions. This plan does not implement `scip-search`, run indexers, change prompts, or add CLI behavior; it tells downstream planners where operator documentation belongs and what must be said.

Liza has two documentation surfaces that matter here:

- `README.md` is the public first-read document. It already has Requirements, Installation, MAS quick start, and Recommended Tools sections.
- `support-docs/` is installed into `~/.liza/support-docs/` by `liza setup` and is the canonical source for operational guides such as `CONFIGURATION.md` and `CUSTOMIZING_AGENT_TOOLS.md`. Matching files under `docs/` are stubs that point to `support-docs/` and must not be edited for canonical content.

### Constraints

- Documentation must not imply `scip-search` is bundled, vendored, auto-installed, or active by default.
- `LIZA_ENABLE_SCIP_SEARCH` is the strict MAS activation gate. Documentation must say unset, empty, `0`, and `false` disable runtime indexing and prompt injection even when `config.scip_search` exists.
- The first milestone supported languages are exactly Go, TypeScript, and Python through `scip-go`, `scip-typescript`, and `scip-python`.
- Language indexers are separate prerequisites from `scip-search`. Installing `scip-search` does not install them.
- `ast-grep` remains the tool for pattern-based structural search and replacement. `scip-search` is for indexed symbol/package/reference/implementation navigation over generated SCIP files.
- Canonical support documentation belongs in `support-docs/`; `docs/CONFIGURATION.md` and `docs/CUSTOMIZING_AGENT_TOOLS.md` are stubs and should stay as stubs.
- If support docs are changed and embedded support-doc copies exist in the worktree, consistency must be preserved through the repository's existing sync mechanism. The plan must not hardcode Liza-specific runtime setup commands into product behavior.
- `.pre-commit-config.yaml` exists at integration `HEAD`; no `bootstrap-precommit` output entry is emitted.

## Components

### README Recommended Tool Positioning (`README.md`)

**Responsibility:** Make `scip-search` visible to new operators as a highly recommended MAS navigation tool and place it correctly among existing token-saving tools.

**Boundaries:**
- Exposes: public overview, requirements/setup hints, and the Recommended Tools table.
- Depends on: the goal spec's operator contract and the existing README organization.

**Key decisions:**
- Add `scip-search` to the Recommended Tools table near navigation/search tools, not as a hard runtime requirement for all Liza users.
- Use "highly recommended for MAS" language so users understand the value without reading it as mandatory for pairing mode or inactive MAS runs.
- State that Liza does not install `scip-search` or language indexers automatically.
- Preserve the existing `ast-grep` row and describe the complement: `scip-search` answers indexed symbol/reference/package questions; `ast-grep` answers pattern and rewrite questions that an index cannot express.

### README Setup and Quick-Start Guidance (`README.md`)

**Responsibility:** Give operators the minimum setup sequence needed to intentionally enable `scip-search` for MAS.

**Boundaries:**
- Exposes: setup prerequisites, opt-in environment variable, and repeated init flag examples.
- Depends on: init/config behavior from `architecture-1` and runtime lifecycle behavior from `architecture-2`.

**Key decisions:**
- Keep setup guidance compact in README and point detailed configuration to `support-docs/CONFIGURATION.md`.
- Show `LIZA_ENABLE_SCIP_SEARCH=1` or `true` as the activation gate, plus `liza init --spec ... --scip-search go --scip-search typescript` for explicit allowlists.
- Say that when the env gate is truthy and no explicit `--scip-search` values are supplied, Liza auto-detects supported languages from git-tracked code.
- Say generated indexes are task-worktree/project-root artifacts under `.liza/scip/` and are snapshots, not live-updating indexes.

### Configuration Reference (`support-docs/CONFIGURATION.md`)

**Responsibility:** Document durable `config.scip_search` and process-local `LIZA_ENABLE_SCIP_SEARCH` semantics for operators troubleshooting setup.

**Boundaries:**
- Exposes: environment variable table entry, config shape, truthy/false values, supported languages, and failure/degradation behavior.
- Depends on: `models.Config.ScipSearch` and runtime activation contract planned by `architecture-1`.

**Key decisions:**
- Document `LIZA_ENABLE_SCIP_SEARCH` in the environment-variable table because it is process-local activation, not durable state.
- Add a `config.scip_search` subsection explaining that it is a language allowlist written by init, not enough by itself to activate MAS indexing.
- Include the supported-language/indexer matrix from the goal spec at operator altitude: executable names and installation responsibility, not implementation internals.
- Document graceful degradation: missing indexers during init warn/drop languages; runtime indexing failures omit failed indexes from prompts and do not block agent spawn.

### Agent Tool Customization Guidance (`support-docs/CUSTOMIZING_AGENT_TOOLS.md`)

**Responsibility:** Explain how `scip-search` changes the recommended MAS tool stack without replacing existing fallback tools.

**Boundaries:**
- Exposes: tool-contract guidance for operators adapting `AGENT_TOOLS.md`.
- Depends on: existing warnings about stale IDE/LSP indexes and centralized indexes in multi-agent worktrees.

**Key decisions:**
- Add `scip-search` to the safer default direction for multi-agent use as a worktree-local, caller-supplied-index navigation tool when Liza has generated indexes.
- Keep `rg` and `ast-grep` in the safe defaults. `scip-search` should be framed as the preferred first stop for indexed symbols/references when an explicit index is present, with `rg` for text/path search and `ast-grep` for syntactic patterns.
- Warn that agents should use explicit `--index` paths supplied by Liza rather than searching for default indexes.

### MAS Usage Setup Notes (`support-docs/USAGE_MULTI_AGENTS.md`)

**Responsibility:** Place a concise pointer in the MAS setup flow so operators discover the opt-in path before running a fleet.

**Boundaries:**
- Exposes: optional setup step and link to the configuration reference.
- Depends on: existing MAS quick-start organization.

**Key decisions:**
- Keep this as a short pointer, not a second full reference, to avoid duplicated setup truth.
- Mention that `scip-search` is optional but highly recommended for repository-navigation-heavy sprints.

### Documentation Consistency Boundary (`docs/`, `support-docs/`, `internal/embedded`)

**Responsibility:** Preserve the repository's canonical support-doc layout and installation behavior.

**Boundaries:**
- Exposes: canonical docs in `support-docs/`, public stubs in `docs/`, and embedded copies generated by `make sync-embedded` when present.
- Depends on: `internal/embedded/consistency_test.go` and the `sync-embedded` Make target.

**Key decisions:**
- Do not edit `docs/CONFIGURATION.md` or `docs/CUSTOMIZING_AGENT_TOOLS.md`; they should continue pointing to `support-docs/`.
- If implementation changes support docs and embedded copies are materialized, update the embedded copies through the existing sync path instead of hand-editing generated copies.
- Validation should include documentation greps for `scip-search`, `LIZA_ENABLE_SCIP_SEARCH`, the three indexer names, and the `ast-grep` complement wording.

## Interfaces

### README -> Operator

**Contract:** README communicates that `scip-search` is highly recommended for MAS repository navigation, opt-in, external, not auto-installed, and complementary to `ast-grep`.

**Direction:** Operators read README before setup and follow links to support docs for details.

**Invariants:** README must not make `scip-search` a universal requirement for all modes, must not promise automatic installation, and must not remove or demote `ast-grep` from pattern-based structural search.

### Configuration Reference -> Operator

**Contract:** `support-docs/CONFIGURATION.md` defines the durable `config.scip_search` allowlist, `LIZA_ENABLE_SCIP_SEARCH` truth table, supported languages, external indexer prerequisites, and degradation semantics.

**Direction:** Operators use the reference during setup and troubleshooting.

**Invariants:** The env gate alone does not select languages; the allowlist alone does not activate runtime indexing. Both are required for MAS indexing and prompt injection.

### Agent Tool Customization -> `AGENT_TOOLS.md`

**Contract:** Tool guidance tells operators how to position `scip-search` relative to `rg`, `ast-grep`, LSP, IDE, and MCP tools in worktree-based MAS environments.

**Direction:** Operators adapt their installed `~/.liza/AGENT_TOOLS.md` based on the support doc.

**Invariants:** `scip-search` guidance assumes explicit index paths supplied by Liza and generated SCIP files; it does not tell agents to discover indexes or rely on a daemon/global cache.

### Support Docs -> Installed `~/.liza/support-docs/`

**Contract:** `liza setup` installs `support-docs/*.md`; any canonical operator setup guidance must live there if installed users need it after setup.

**Direction:** Repository support docs are copied to the installed support-doc directory by existing setup/sync mechanisms.

**Invariants:** Stubs in `docs/` remain stubs. Embedded/generated copies, if present, must match canonical `support-docs/` content.

## Data Flow

```text
Goal spec operator requirements
  -> README recommended-tool and quick-start placement
  -> support-docs/CONFIGURATION.md detailed activation/config/indexer reference
  -> support-docs/CUSTOMIZING_AGENT_TOOLS.md tool-stack positioning
  -> support-docs/USAGE_MULTI_AGENTS.md concise MAS setup pointer
  -> liza setup installs support-docs for operators
```

Operator setup flow documented by this slice:

```text
Install external scip-search
  -> install desired language indexers outside Liza
  -> export LIZA_ENABLE_SCIP_SEARCH=1 or true for MAS process
  -> run liza init --spec ... [--scip-search language]*
  -> state config records validated config.scip_search allowlist
  -> later MAS lifecycle generates explicit task/project index paths when activated
```

Tool-choice flow documented by this slice:

```text
Need symbol/package/reference navigation and Liza supplied an index path
  -> scip-search --index <explicit-path>
Need text/path search
  -> rg / rg --files
Need syntax pattern or structural rewrite
  -> ast-grep
```

## Cross-Cutting Concerns

| Concern | Approach |
|---------|----------|
| Error handling | Docs distinguish init-time fatal missing `scip-search --help`, init-time missing indexer warning/drop, and runtime best-effort indexing failures that omit prompt guidance without blocking agents. |
| Observability | Docs tell operators that indexing failures remain observable through logs/command output, while failed indexes are intentionally omitted from agent prompt budget. |
| Configuration | `LIZA_ENABLE_SCIP_SEARCH` is documented as process-local activation; `config.scip_search` is documented as durable language allowlist. |
| Testing | Downstream implementation should use focused documentation checks: README contains `scip-search` in Recommended Tools; configuration docs contain the env truth table, supported language/indexer matrix, and non-auto-install warning; tool docs preserve the `ast-grep` complement; stubs still point to `support-docs/`. |
| Security | Documentation must avoid encouraging shell interpolation or secrets. Installation examples should be external prerequisite examples only, not commands Liza runs automatically. |
| Concurrency | Documentation should state task-worktree indexes are independent and project-root indexes are separate, matching the runtime lifecycle architecture. |
| Prompt budget | Documentation should explain that failed or absent indexes omit the prompt section, so setup failures do not consume agent context. |
| Stack agnosticism | Docs may mention Go, TypeScript, and Python as the first supported SCIP languages, but must not assume a Liza/Go project or hardcode Liza-specific setup commands into runtime behavior. |
