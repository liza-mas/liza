# Architecture Plan: scip-search Agent Prompt Contract

Status: review

## Goal

Define how successful `scip-search` indexes become explicit, capability-aware agent prompt guidance and how Claude is allowed to run the resulting query commands.

## Context

This slice covers the agent-facing prompt and Claude settings contract for the `scip-search` goal. Earlier architecture slices define init-time configuration and runtime index generation. This plan consumes their outputs: the prompt layer must not generate indexes, infer paths from worktrees, or duplicate activation rules. It renders prompt guidance only from successful index metadata supplied by runtime indexing code.

The relevant current prompt path is:

```text
agent strategy
  -> internal/agent/prompt.go
  -> prompts.BuildBasePrompt
  -> internal/prompts/templates/base_prompt.tmpl
```

Task-based prompts then append role-context blocks. Orchestrator prompts use the same base prompt and append the orchestrator dashboard. The `scip-search` section belongs in the base prompt because it is role-independent navigation guidance and must be omitted uniformly when no index is available.

### Constraints

- `LIZA_ENABLE_SCIP_SEARCH` plus `config.scip_search` remain the activation contract from `architecture-1`; this slice must consume that contract, not redefine it.
- Runtime indexing and available-index discovery are owned by `architecture-2`; this slice must not run indexers or decide whether indexing should happen.
- Prompt guidance must include explicit absolute index paths supplied by Liza. Agents must not infer paths from the worktree or project root.
- If zero successful indexes are available, the `scip-search` prompt section is omitted entirely.
- Prompt text must state snapshot semantics: generated indexes do not update after subsequent agent edits.
- Prompt text must avoid unsupported language promises. Python implementations are unsupported; Python references are partial; TypeScript implementations are upstream-supported but not locally verified in the baseline evidence.
- Claude permission changes must edit the master file `internal/embedded/claude-settings.json`, not derived `.claude/settings.json`.
- `.pre-commit-config.yaml` exists at integration `HEAD`; no `bootstrap-precommit` output entry is emitted.

## Components

### Runtime Index Availability Source (`internal/scipsearch` from architecture-2)

**Responsibility:** Provide prompt consumers with successful index metadata for a specific target root.

**Boundaries:**
- Exposes: read-only available-index discovery for a target root, returning language, absolute index path, and capability metadata for generated indexes that exist and are usable.
- Depends on: runtime indexing service output under `<target>/.liza/scip/` and activation helper from the init/config slice.

**Key decisions:**
- The prompt layer treats this source as authoritative for prompt inclusion. Missing or failed language indexes are represented by absence from the returned list, not by prompt warnings.
- Capability metadata must distinguish `supported`, `partial`, `unverified`, and `unsupported` prompt wording so the renderer can avoid false promises.
- The service boundary returns absolute paths so prompt code never reconstructs index locations from task worktree strings.

### Agent Prompt Context Assembly (`internal/agent/prompt.go`)

**Responsibility:** Resolve the correct target root for the current agent and pass successful `scip-search` prompt data into the base prompt.

**Boundaries:**
- Exposes: populated base prompt config for task-based roles and orchestrator roles.
- Depends on: task worktree path for doers/reviewers, project root for orchestrators, and runtime index availability source.

**Key decisions:**
- Task-based roles query available indexes for the resolved absolute task worktree path already stored in `RoleContextData.Worktree`.
- Orchestrator roles query available indexes for `config.ProjectRoot`, matching the project-root refresh planned by `architecture-2`.
- Prompt assembly degrades to an empty index list on no available indexes. It should not block agent spawn because the goal requires indexing failures to preserve agent availability.
- Unexpected prompt-context errors that do not come from absent indexes should still propagate through the existing prompt-build error path.

### Base Prompt scip-search Section (`internal/prompts/builder.go`, `internal/prompts/templates/base_prompt.tmpl`)

**Responsibility:** Render a concise, role-independent `scip-search` guidance section when at least one index is available.

**Boundaries:**
- Exposes: conditional base-prompt content driven by structured index prompt data.
- Depends on: `BasePromptConfig` fields populated by agent prompt assembly.

**Key decisions:**
- Add structured index prompt data to `BasePromptConfig`, not to each role-specific block. This keeps the section in the base prompt and avoids duplicating text across role templates.
- Render nothing when the index slice is empty. This is the only acceptable no-index behavior because the spec says prompt budget should not be consumed by indexing failures.
- Sort rendered indexes by deterministic milestone language order: `go`, `typescript`, `python`.
- Render the supplied absolute path as the index label and in every `--index` command. Do not render placeholder paths such as `<worktree>/.liza/scip/go.scip`.
- The command loop must stay terse and include:
  - `scip-search symbols --index <absolute-path> --name ...`
  - `scip-search references --index <absolute-path> --symbol ... --location-only`
  - `nl -ba <result-path> | sed -n '<first-line>,<last-line>p'`
  - implementation lookup only when the language capability permits the wording.
- Snapshot wording must be present once in the section, not repeated per language.

### Language Capability Wording (`internal/prompts` or `internal/scipsearch`)

**Responsibility:** Convert language capability metadata into truthful prompt text.

**Boundaries:**
- Exposes: language-specific guidance strings or template fields.
- Depends on: first milestone capability baseline from the goal spec.

**Key decisions:**
- Go: state that symbols, references, and implementations are available.
- TypeScript: state that symbols and references are available; mention implementations as upstream-supported but not locally verified, so agents should verify results against files before relying on them.
- Python: state that symbols are available, references may be incomplete, and `scip-search implementations` is not supported for Python.
- Do not expose unsupported commands in examples for a language. In particular, Python must not render an implementations command example.

### Claude Settings Permission (`internal/embedded/claude-settings.json`)

**Responsibility:** Permit Claude agents to run the `scip-search` binary from Bash.

**Boundaries:**
- Exposes: master embedded settings that `liza init` copies/merges into project `.claude/settings.json`.
- Depends on: existing permissions merge logic in `internal/embedded/embedded.go`.

**Key decisions:**
- Add `Bash(scip-search:*)` to `permissions.allow` in the embedded master settings.
- Do not edit derived `.claude/settings.json`.
- Keep existing `Bash(rg:*)` and `Bash(ast-grep:*)` permissions because `scip-search` complements rather than replaces them.

## Interfaces

### Runtime Index Availability Source -> Agent Prompt Context Assembly

**Contract:** Given an absolute target root and state config, return a deterministic list of successful index records: language, absolute index path, and capability status for symbols, references, and implementations.

**Direction:** `internal/agent/prompt.go` calls the runtime index source while building prompts.

**Invariants:** Returned paths are absolute; failed language indexes are omitted; empty list means no prompt section.

### Agent Prompt Context Assembly -> Base Prompt Builder

**Contract:** `BasePromptConfig` carries the successful index prompt records into `prompts.BuildBasePrompt`.

**Direction:** `baseConfigFrom` or a nearby prompt assembly helper populates base prompt config before executing `base_prompt.tmpl`.

**Invariants:** Base prompt rendering must not inspect the filesystem; it renders only supplied data. All roles use the same base prompt section.

### Base Prompt Builder -> Agent

**Contract:** When records exist, the base prompt includes explicit absolute index paths, the supported command loop, snapshot semantics, and capability-specific language caveats.

**Direction:** Template rendering produces prompt text consumed by spawned agents.

**Invariants:** No records means no `scip-search` section and no `scip-search` token in the prompt. Python does not render an implementations command. Every command example uses `--index <absolute-path>`.

### Embedded Settings -> Claude Runtime

**Contract:** `internal/embedded/claude-settings.json` includes `Bash(scip-search:*)` in `permissions.allow`; generated or merged Claude settings inherit that permission.

**Direction:** `liza init` writes or merges embedded settings into project Claude configuration.

**Invariants:** JSON remains valid; permissions are additive; derived settings are not the source of truth.

## Data Flow

Task-based agent flow:

```text
ClaimTask / reviewer claim
  -> architecture-2 lifecycle indexing writes successful indexes under <worktree>/.liza/scip/
  -> supervisor reads stateBefore
  -> buildPromptWithContext resolves the task worktree absolute path
  -> available-index source returns successful index records with absolute paths
  -> BasePromptConfig.ScipSearchIndexes
  -> base_prompt.tmpl renders conditional scip-search section
  -> spawned agent receives explicit --index paths
```

Orchestrator flow:

```text
orchestrator wake
  -> architecture-2 PreExecution refreshes project-root indexes
  -> supervisor reads stateBefore
  -> buildOrchestratorPromptContext queries project-root available indexes
  -> BasePromptConfig.ScipSearchIndexes
  -> base_prompt.tmpl renders conditional scip-search section
  -> orchestrator receives explicit project-root --index paths
```

No-index flow:

```text
activation false OR config empty OR all indexers fail OR no index files found
  -> available-index source returns []
  -> BasePromptConfig.ScipSearchIndexes is empty
  -> base_prompt.tmpl omits the entire scip-search section
  -> agent prompt contains no scip-search guidance
```

## Cross-Cutting Concerns

| Concern | Approach |
|---------|----------|
| Error handling | Absence of successful indexes is non-fatal and renders no prompt section. Unexpected prompt assembly failures still use the existing prompt-build error handling path. |
| Observability | Indexing failures remain observable through lifecycle command warnings/logs from architecture-2, not through prompt text. Prompt tests verify omission rather than warning injection. |
| Configuration | The prompt consumes activation and language allowlist outcomes through runtime index availability. It does not parse `LIZA_ENABLE_SCIP_SEARCH` directly. |
| Testing | Add prompt/golden checks for no-index omission, explicit absolute paths, supported command loop, snapshot semantics, Python implementation warning, TypeScript caveat, and language capability promises. Add JSON/embedded settings checks for `Bash(scip-search:*)`. |
| Security | Prompt commands use caller-supplied absolute index paths and fixed `scip-search` subcommands. No shell command is built from untrusted agent text inside Liza. |
| Concurrency | Each task prompt uses its own worktree-local available indexes; orchestrator prompt uses project-root indexes. No shared mutable prompt state is introduced. |
| Prompt budget | The section is omitted unless useful. The rendered text is one concise loop plus compact per-language caveats. |
| Stack agnosticism | Language-specific text is driven by index metadata for Go, TypeScript, and Python, not by assuming the user project is Liza or Go-only. |

## Decomposition

Each scope becomes a code-planning child task. No bootstrap-precommit entry is emitted because `.pre-commit-config.yaml` exists on integration `HEAD`.

### Scope 1: Agent Prompt scip-search Contract and Claude Permission

**Component(s):** Runtime Index Availability Source; Agent Prompt Context Assembly; Base Prompt scip-search Section; Language Capability Wording; Claude Settings Permission

**Boundary:** In scope: consuming successful available-index metadata from the runtime `scip-search` service, adding structured scip-search prompt data to base prompt construction, rendering the conditional base prompt section with explicit absolute index paths, supported command loop, snapshot semantics, Go/TypeScript/Python capability-specific wording, prompt omission when no indexes are available, and adding `Bash(scip-search:*)` to `internal/embedded/claude-settings.json`. Out of scope: init-time validation, language allowlist persistence, SCIP index generation, lifecycle indexing call-site wiring, README/operator documentation, generated `.claude/settings.json`, and any wrapper or MCP abstraction for `scip-search`.

**Done when:** Prompt and settings tests prove that: (a) when no successful indexes are supplied, the rendered agent prompt contains no `scip-search` section; (b) when Go, TypeScript, or Python indexes are supplied, the rendered prompt includes each explicit absolute index path in `--index` examples and does not ask agents to infer index locations; (c) the prompt includes the supported `symbols`, `references`, file-open loop, and implementation guidance only where language capability wording permits it; (d) Python guidance says `scip-search implementations` is not supported for Python and does not render a Python implementations command; (e) TypeScript implementation wording is caveated as upstream-supported but not locally verified; (f) the prompt states indexes are snapshots that will not reflect subsequent agent edits; and (g) `internal/embedded/claude-settings.json` is valid JSON whose `permissions.allow` contains `Bash(scip-search:*)`.

**Depends on:** Existing concrete task `architecture-2-code-planning-0` for the runtime available-index service contract.

## Self-Review Notes

- The plan keeps generated index files out of the repository and out of prompt rendering; indexing remains an upstream lifecycle responsibility.
- The prompt section is conditional on successful index records, so failed indexing consumes no prompt budget.
- The plan explicitly rejects path inference by requiring absolute paths in structured prompt data and in every rendered command example.
- The plan covers all task-required golden checks: omission, explicit paths, snapshot semantics, Python implementation warning, and language capability promises.
- The plan follows the `settings-master-not-derived` lesson by editing only the embedded master Claude settings file.
