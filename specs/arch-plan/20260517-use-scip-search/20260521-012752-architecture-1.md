# Architecture Plan: scip-search Init Configuration

Status: review

## Goal

Define the init-time architecture for `scip-search` setup validation, language allowlist selection, diagnostics, and `state.yaml` config persistence.

## Context

This slice covers the first ten success criteria from the goal spec. It does not generate SCIP indexes, alter task worktree lifecycle, inject prompt guidance, update README content, or modify Claude settings. Those are later goal slices that consume the config and activation contract defined here.

Liza already routes full workspace initialization through `cmd/liza/cmd_init.go` into `internal/commands.InitCommandWithConfig`, writes initial state through `internal/db.Blackboard`, and stores runtime options on `internal/models.Config`. The plan keeps `scip-search` setup policy out of Cobra plumbing and out of raw YAML handling by adding a small package-level service that init and later runtime code can share.

### Constraints

- Success criterion 1 is unconditional for full `liza init --spec`: init must run `scip-search --help` and fail clearly when that command is unavailable or exits unsuccessfully. This setup validation is separate from MAS runtime activation.
- `LIZA_ENABLE_SCIP_SEARCH` remains the strict MAS activation gate for index generation and prompt injection. False or unset values do not bypass init-time `scip-search --help` validation.
- Liza is stack-agnostic. Detection may look for supported language evidence in the target project, but it must not assume the target is the Liza Go repository or run project build commands.
- `state.yaml` config must be written through typed `models.Config` and the existing initial state write path.
- Init validation must happen before durable state creation so setup failures do not leave a partially initialized workspace.
- `.pre-commit-config.yaml` exists at integration `HEAD`; no `bootstrap-precommit` output entry is emitted.

## Components

### Init CLI Surface (`cmd/liza/cmd_init.go`)

**Responsibility:** Expose repeated `--scip-search <language>` flags for full workspace init and pass all raw flag values to init business logic.

**Boundaries:**
- Exposes: Cobra flag parsing, help text, and workspace-flag classification.
- Depends on: `commands.InitParams` for transferring raw CLI values.

**Key decisions:**
- Model the flag as a repeatable string slice so duplicate inputs remain visible to the resolver.
- Classify `--scip-search` as a workspace flag. Using it without a description follows the same rejection path as `--spec`, `--config`, and `--post-worktree-cmd`.
- Do not perform language validation in Cobra. Cobra owns syntax and dispatch; the resolver owns policy.

### Init scip-search Setup Validator (new internal package, for example `internal/scipsearch`)

**Responsibility:** Own setup-time `scip-search` command probing and diagnostics.

**Boundaries:**
- Exposes: a validation function that returns fatal setup errors plus optional diagnostic text.
- Depends on: fixed argv subprocess execution for `scip-search --help` and best-effort `scip-search --version`.

**Key decisions:**
- Run `scip-search --help` for every full `liza init --spec` before state creation, regardless of `LIZA_ENABLE_SCIP_SEARCH` and regardless of whether `--scip-search` flags were provided.
- Treat missing or failing `scip-search --help` as a fatal setup error with a message that names the unavailable command.
- Run `scip-search --version` only after `--help` succeeds. Version output is diagnostic when available; version failure is non-fatal and must not mask a successful help probe.
- Invoke external commands without shell interpolation.

### Init Language Resolver and Indexer Validator (same new internal package)

**Responsibility:** Convert raw CLI languages and environment state into the persisted language allowlist.

**Boundaries:**
- Exposes: supported language constants, environment gate parsing, explicit language validation, duplicate de-duplication, git-tracked autodetection, and per-language indexer probing.
- Depends on: `git ls-files` in the target project root and fixed argv probes for `scip-go`, `scip-typescript`, and `scip-python`.

**Key decisions:**
- Supported language values are exactly `go`, `typescript`, and `python` for this milestone.
- Explicit languages are validated and de-duplicated even when `LIZA_ENABLE_SCIP_SEARCH` is false.
- If no explicit languages are provided and the env gate is truthy, autodetect supported languages from `git ls-files`; test files count.
- If no explicit languages are provided and the env gate is false or unset, persist no `config.scip_search` allowlist.
- Missing language indexers are warnings that drop only the affected language. If every selected or autodetected language is dropped, `config.scip_search` is omitted or empty.
- Preserve deterministic output ordering as `go`, `typescript`, `python` after selection and validation.

### Init State Writer (`internal/commands/init.go`, `internal/models/config.go`)

**Responsibility:** Persist the resolved language allowlist into the initial state config.

**Boundaries:**
- Exposes: `config.scip_search` through a typed `models.Config` field.
- Depends on: the resolver result produced before `models.State` construction.

**Key decisions:**
- Add `ScipSearch []string yaml:"scip_search,omitempty"` to `models.Config`.
- Populate the field only with languages that survived validation.
- Keep all state writes in the existing `db.Blackboard.Write` path.

### Runtime Activation Contract (same new internal package)

**Responsibility:** Provide a read-only predicate that later lifecycle scopes can call to decide whether scip-search indexing and prompt injection are active.

**Boundaries:**
- Exposes: activation decision based on `LIZA_ENABLE_SCIP_SEARCH` plus non-empty `models.Config.ScipSearch`.
- Depends on: process environment and the typed config field.

**Key decisions:**
- Runtime activation is true only when the env gate is truthy and the configured language allowlist is non-empty.
- Runtime activation does not validate tools, generate indexes, inspect worktrees, or render prompt text in this task.
- Later supervisor, reviewer, and orchestrator scopes must consume this predicate instead of duplicating env parsing.

## Interfaces

### Cobra Init Command -> `commands.InitCommandWithConfig`

**Contract:** Cobra passes `InitParams.ScipSearch []string` containing every provided `--scip-search` value.

**Direction:** `cmd/liza/cmd_init.go` collects flags and calls `commands.InitCommandWithConfig`.

**Invariants:** Repeated values are not joined into one string; `--scip-search` without a description is treated as a workspace flag error.

### `commands.InitCommandWithConfig` -> scip-search Setup Validator

**Contract:** Init asks the validator to prove `scip-search --help` succeeds and to collect best-effort `--version` diagnostics before state creation.

**Direction:** Init calls the validator after project/spec context is known and before `.liza/state.yaml` is written.

**Invariants:** Help failure is fatal for full `liza init --spec`; version failure is diagnostic-only after help succeeds.

### `commands.InitCommandWithConfig` -> Language Resolver and Indexer Validator

**Contract:** Init passes project root, raw CLI language values, and environment access. The resolver returns canonical languages plus warnings for dropped indexers.

**Direction:** Init calls the resolver before building `models.State`.

**Invariants:** Unsupported explicit languages fail; duplicates collapse; autodetection only runs when no explicit language was provided and the env gate is truthy; missing indexers drop languages with warnings.

### Language Resolver -> Git and Process Boundary

**Contract:** Autodetection reads `git ls-files`; validation probes fixed executable names with argv arrays.

**Direction:** Resolver invokes external processes and converts results into fatal errors or warnings.

**Invariants:** No shell command construction from user input; no project build or type-check commands run during init.

### State Config -> Later Runtime Lifecycle

**Contract:** Later code reads `state.Config.ScipSearch` as the language allowlist and combines it with the env gate through the runtime activation predicate.

**Direction:** Supervisor/worktree/reviewer/orchestrator prompt scopes consume the config.

**Invariants:** Empty or absent config disables runtime scip-search behavior; false env gate disables runtime scip-search behavior even when config exists.

## Data Flow

```text
liza init --spec ... [--scip-search L]*
  -> Cobra collects repeated values
  -> InitParams.ScipSearch
  -> InitCommandWithConfig resolves project/spec context
  -> scip-search setup validator runs scip-search --help
  -> setup validator optionally reports scip-search --version
  -> language resolver parses LIZA_ENABLE_SCIP_SEARCH
  -> explicit languages OR git ls-files autodetect OR empty selection
  -> supported-language validation and de-duplication
  -> per-language indexer probes
  -> warnings drop missing indexer languages
  -> models.Config.ScipSearch
  -> db.Blackboard.Write initial state.yaml
```

Runtime data flow for this slice:

```text
state.Config.ScipSearch + LIZA_ENABLE_SCIP_SEARCH
  -> runtime activation predicate
  -> later indexing and prompt-injection scopes
```

## Cross-Cutting Concerns

| Concern | Approach |
|---------|----------|
| Error handling | `scip-search --help` failure, unsupported languages, and git autodetection failures that prevent required detection return fatal init errors before state creation. Missing language indexers warn and drop only affected languages. |
| Observability | Init surfaces warnings for dropped languages and diagnostic version text when available. The version behavior is explicitly testable with a fake command runner. |
| Configuration | `config.scip_search` is a typed language allowlist. `LIZA_ENABLE_SCIP_SEARCH` is an environment activation gate and is not persisted. |
| Testing | Use pure unit tests for env parsing, language normalization, and activation; fake command runners for missing tools/version/indexers; command/init tests for flag parsing and YAML persistence; fake git output for autodetection. |
| Security | Do not read credential files. External probes use fixed executable names and argv arrays, not shell strings derived from user input. |
| Concurrency | Init is a single-writer setup path. Runtime activation is read-only and safe for later concurrent lifecycle calls. |
| Stack agnosticism | Language detection uses git-tracked file evidence for the supported languages only. No Liza-specific build, test, or module commands are introduced. |

## Decomposition

Each scope becomes a code-planning child task. No bootstrap-precommit entry is emitted because `.pre-commit-config.yaml` exists on integration `HEAD`.

### Scope 1: State Config and CLI Surface

**Component(s):** Init CLI Surface; Init State Writer

**Boundary:** In scope: repeated `--scip-search` flag plumbing, `InitParams.ScipSearch`, `models.Config.ScipSearch`, workspace-flag detection, init help text, and state persistence wiring. Out of scope: `scip-search --help` probing, `--version` diagnostics, language autodetection, indexer validation, lifecycle indexing, prompt injection, README, and Claude settings.

**Done when:** `liza init --spec ... --scip-search go --scip-search typescript` can carry both values into `InitCommandWithConfig` and successful init persists `config.scip_search` through the typed `models.Config` field; tests cover repeated flag parsing, `--scip-search` workspace-flag rejection without a description, and YAML persistence.

**Depends on:** None

### Scope 2: Init-Time Setup Validation and Language Resolution

**Component(s):** Init scip-search Setup Validator; Init Language Resolver and Indexer Validator; Init State Writer

**Boundary:** In scope: unconditional full-init `scip-search --help` validation, best-effort `scip-search --version` diagnostics, `LIZA_ENABLE_SCIP_SEARCH` parsing, supported-language validation, duplicate de-duplication, git-tracked autodetection, per-language indexer validation, warnings that drop missing indexers, and integration into init before state creation. Out of scope: generating SCIP index files and modifying agent prompts.

**Done when:** init-time tests prove every full `liza init --spec` path invokes `scip-search --help` and fails clearly when unavailable or unsuccessful, reports `scip-search --version` when available, treats version failure as non-fatal after help succeeds, parses truthy and false `LIZA_ENABLE_SCIP_SEARCH` values, rejects unsupported languages, de-duplicates duplicate languages, auto-detects Go/TypeScript/Python from git-tracked files when no explicit languages are provided and the env gate is truthy, warns and drops languages with missing indexers, and persists only validated languages to `config.scip_search`.

**Depends on:** Scope 1

### Scope 3: Runtime Activation Contract for Supervisors

**Component(s):** Runtime Activation Contract

**Boundary:** In scope: a read-only helper/interface that later supervisor, worktree, reviewer, and orchestrator prompt scopes can call to combine `LIZA_ENABLE_SCIP_SEARCH` with `config.scip_search`. Out of scope: actual indexing, index storage, prompt rendering, reviewer regeneration, orchestrator refresh, README, and Claude settings.

**Done when:** tests prove runtime activation is false when env is unset/empty/`0`/`false`, false when `config.scip_search` is absent or empty, true only for truthy env plus at least one configured language, and later callers have a documented package-level contract instead of duplicating env parsing.

**Depends on:** Scope 2

## Self-Review Notes

- The prior rejection is addressed by making `scip-search --help` unconditional for every full `liza init --spec`, not only for an active scip path.
- `scip-search --version` diagnostics are falsifiable in Scope 2 `done_when`.
- All required task test categories are named in Spec Coverage: flag parsing, env gating, autodetection, unsupported languages, duplicate languages, missing tools, and config persistence.
- No scope creates or edits runtime log files under `.liza/agent-outputs/`.
