# Architecture Plan: scip-search Init Configuration

Status: review

## Goal

Define the init-time architecture for opt-in `scip-search` configuration, validation, language selection, diagnostics, and `state.yaml` persistence.

## Context

Liza already centralizes workspace initialization in the Cobra `init` command, delegates business logic to `internal/commands.InitCommandWithConfig`, stores runtime configuration in `models.Config`, and uses `state.Config` from supervisor, claim, and prompt-building flows. This plan adds the `scip-search` init/config slice without implementing lifecycle indexing or prompt injection, which are later goal scopes.

### Constraints

- `LIZA_ENABLE_SCIP_SEARCH` is the strict MAS activation gate for indexing and prompt injection. Init may persist explicit configuration while runtime remains inactive.
- Liza is stack-agnostic. Language/indexer logic must be opt-in configuration and detected evidence, not assumed from Liza's own Go implementation.
- `state.yaml` is mutated only through existing blackboard/init flows, never by ad hoc YAML editing.
- Init runs before `.liza/state.yaml` exists, so validation must happen before state creation and before partial artifacts become durable.
- Worktree lifecycle indexing, reviewer prompt injection, orchestrator refresh, README updates, and Claude settings changes are outside this architecture task except for defining the config interface they will consume.
- `.pre-commit-config.yaml` exists at integration `HEAD`; no `bootstrap-precommit` output entry is emitted.

### Assumptions

- **ASM-001**: Init should only require `scip-search` when the scip-search init path is requested by repeated `--scip-search` flags or by truthy `LIZA_ENABLE_SCIP_SEARCH`. Why: the goal calls the feature strict opt-in and says false/unset disables MAS indexing and prompt injection. Confidence: MEDIUM.
- **ASM-002**: Persisted language order should be canonical `go`, `typescript`, `python` after de-duplication. Why: this keeps state deterministic and matches the first milestone language list. Confidence: HIGH.

### Open Questions

- None for this slice. If reviewers interpret success criterion 1 as requiring `scip-search --help` on every `liza init --spec` even with no env gate and no flags, Scope 2 must be tightened before code implementation.

## Components

### Init CLI Surface (`cmd/liza/cmd_init.go`)

**Responsibility:** Expose repeated `--scip-search <language>` flags and pass normalized raw values into init business logic.

**Boundaries:**
- Exposes: CLI flag parsing and help text.
- Depends on: `commands.InitParams` for business-logic inputs.

**Key decisions:**
- Add the flag as a repeatable string array on full workspace init only. Pairing mode remains contract setup only.
- Include `scip-search` in explicit workspace flag detection so `liza init --scip-search go` without a description follows the existing "workspace flags require description" behavior.

### Init Scip Configuration Service (`internal/scipsearch` or `internal/scipconfig`)

**Responsibility:** Own scip-search language constants, environment parsing, language validation, de-duplication, git-tracked autodetection, tool probing, and activation decisions.

**Boundaries:**
- Exposes: a small init resolver that returns selected languages, warnings, and fatal setup errors; a runtime activation predicate for later supervisor scopes.
- Depends on: `git ls-files` run in the target project root, `exec.Command` for `scip-search --help`, optional `scip-search --version`, and indexer `--help` probes.

**Key decisions:**
- Keep this out of `internal/commands/init.go` so command initialization remains orchestration and state construction, not language/tool policy.
- Use explicit language constants for `go`, `typescript`, and `python`; unsupported values fail before state artifacts are created.
- Parse `LIZA_ENABLE_SCIP_SEARCH` with trim and case-fold. Truthy: `1`, `true`. False: unset, empty, `0`, `false`. Any other value is a clear setup error because silent guessing would make activation ambiguous.
- Use `git ls-files` for autodetection. Test files count because the spec says git-tracked code, not production-only code.
- Treat missing language indexers as warnings that drop that language; treat missing or failing `scip-search --help` as fatal only when the scip-search init path is active.
- Report `scip-search --version` when available as diagnostics; version failure is non-fatal after `--help` succeeds.

### Init State Writer (`internal/commands/init.go`, `internal/models/config.go`)

**Responsibility:** Persist the resolved language allowlist into the initial `models.Config` written to `.liza/state.yaml`.

**Boundaries:**
- Exposes: `config.scip_search` in YAML through a typed `models.Config` field.
- Depends on: init scip configuration service result.

**Key decisions:**
- Add `ScipSearch []string yaml:"scip_search,omitempty"` to `models.Config`.
- Write only languages that survived validation. If none survive, omit or leave empty so runtime activation is disabled.
- Preserve explicit `--scip-search` values even when `LIZA_ENABLE_SCIP_SEARCH` is false, after validating supported language names and dropping missing indexers with warnings.

### Runtime Activation Contract (`internal/scipsearch`)

**Responsibility:** Provide one predicate later lifecycle code can use to decide whether indexing and prompt injection are active.

**Boundaries:**
- Exposes: activation based on `LIZA_ENABLE_SCIP_SEARCH` plus non-empty `Config.ScipSearch`.
- Depends on: `models.Config` and process environment.

**Key decisions:**
- The predicate returns false when the env gate is false or the language list is empty.
- It does not generate indexes, inspect worktrees, or build prompt text in this task's scope.
- Later worktree/reviewer/orchestrator scopes must call this predicate instead of re-parsing environment rules.

## Interfaces

### Cobra Init Command -> `commands.InitCommandWithConfig`

**Contract:** CLI supplies `InitParams.ScipSearch []string` containing each provided `--scip-search` value exactly as entered.

**Direction:** `cmd/liza/cmd_init.go` reads Cobra flags and calls `commands.InitCommandWithConfig`.

**Invariants:** Pairing-only init must reject workspace flags without a description; full init must pass all repeated values without lossy string joining.

### `commands.InitCommandWithConfig` -> Init Scip Configuration Service

**Contract:** Init passes project root and raw CLI languages; the service returns canonical languages, warnings, diagnostics, and a fatal error when setup is invalid.

**Direction:** Init calls the service after project root/spec checks are known and before `.liza/` directories/state files are written.

**Invariants:** Unsupported languages fail; duplicates collapse; autodetection happens only when no explicit languages were provided and env is truthy; missing indexers drop languages with warnings.

### Init Scip Configuration Service -> Git and Tool Process Boundary

**Contract:** Autodetection uses `git ls-files` in the project root. Tool validation probes command availability with bounded subprocesses.

**Direction:** Service invokes external commands and converts results into structured fatal errors or warnings.

**Invariants:** No language-specific build commands run during init; validation probes do not write project files; diagnostics redact no secrets because no env values beyond the gate are printed.

### State Config -> Later Runtime Lifecycle

**Contract:** Later lifecycle code reads `state.Config.ScipSearch` as the language allowlist and combines it with the environment gate. Empty or absent disables scip-search.

**Direction:** Supervisor/worktree/prompt scopes consume the config; they do not own init selection policy.

**Invariants:** Runtime activation requires both truthy env and at least one configured language.

## Data Flow

```text
liza init --spec ... [--scip-search L]*
  -> Cobra collects repeated values
  -> InitParams.ScipSearch
  -> scip config service parses LIZA_ENABLE_SCIP_SEARCH
  -> explicit languages OR git ls-files autodetect OR empty selection
  -> supported-language validation and de-duplication
  -> scip-search --help probe and optional --version diagnostics when active
  -> per-language indexer probes
  -> models.Config.ScipSearch
  -> db.Blackboard.WriteInitialState / state.yaml config.scip_search
```

Runtime data flow for this slice:

```text
state.Config.ScipSearch + LIZA_ENABLE_SCIP_SEARCH
  -> scip activation predicate
  -> later worktree indexing and prompt-injection scopes
```

## Cross-Cutting Concerns

| Concern | Approach |
|---------|----------|
| Error handling | Unsupported env values, unsupported languages, and missing/failing `scip-search --help` on the active path return fatal init errors before state creation. Missing indexers return warnings and drop only the affected language. |
| Observability | Init warnings go to the existing warning/output channel; `scip-search --version` is best-effort diagnostic text when available. Later runtime logs consume the same language allowlist. |
| Configuration | `config.scip_search` is a typed language allowlist. Environment remains the runtime activation gate and is not persisted. |
| Testing | Unit tests cover pure parsing/selection logic with fake command runners; command/init tests verify CLI flag plumbing and state persistence; runtime helper tests verify activation semantics. |
| Security | No credential files are read. External probes use fixed executable names and argv arrays, not shell interpolation. |
| Concurrency | Init is pre-runtime and single-writer. Runtime helper is read-only and safe for concurrent supervisor paths. |
| Stack agnosticism | Detection keys off git-tracked files for supported languages only; no Liza-specific build commands or project setup commands are introduced. |

## Decomposition

Each scope becomes a code-planning child task. No bootstrap-precommit entry is emitted because `.pre-commit-config.yaml` already exists on integration `HEAD`.

### Scope 1: State Config and CLI Surface

**Component(s):** Init CLI Surface; Init State Writer

**Boundary:** In scope: repeated `--scip-search` flag plumbing, `InitParams.ScipSearch`, `models.Config.ScipSearch`, workspace-flag detection, init help text, and state persistence wiring. Out of scope: command probing, autodetection, lifecycle indexing, prompt injection, README, and Claude settings.

**Done when:** `liza init --spec ... --scip-search go --scip-search typescript` can carry both values into `InitCommandWithConfig` and successful init persists `config.scip_search` through the typed `models.Config` field; tests cover repeated flag parsing, workspace-flag rejection without a description, and YAML persistence.

**Depends on:** None

### Scope 2: Init-Time Language Resolution and Tool Validation

**Component(s):** Init Scip Configuration Service; Init State Writer

**Boundary:** In scope: `LIZA_ENABLE_SCIP_SEARCH` parsing, supported-language validation, duplicate de-duplication, git-tracked autodetection, `scip-search --help` validation, best-effort `--version` diagnostics, per-language indexer validation, warnings that drop missing indexers, and integration into init before state creation. Out of scope: generating SCIP index files and modifying agent prompts.

**Done when:** init-time tests prove truthy and false env parsing, unsupported language failure, duplicate language de-duplication, autodetection from git-tracked Go/TypeScript/Python files, missing indexer warning/drop behavior, fatal missing `scip-search --help` on the active path, and persisted `config.scip_search` for validated languages.

**Depends on:** Scope 1

### Scope 3: Runtime Activation Contract for Supervisors

**Component(s):** Runtime Activation Contract

**Boundary:** In scope: a read-only helper/interface that later supervisor, worktree, reviewer, and orchestrator prompt scopes can call to combine `LIZA_ENABLE_SCIP_SEARCH` with `config.scip_search`. Out of scope: actual indexing, index storage, prompt rendering, reviewer regeneration, and orchestrator refresh.

**Done when:** tests prove runtime activation is false when env is unset/empty/`0`/`false`, false when `config.scip_search` is absent or empty, true only for truthy env plus at least one configured language, and later callers have a documented package-level contract instead of duplicating env parsing.

**Depends on:** Scope 2
