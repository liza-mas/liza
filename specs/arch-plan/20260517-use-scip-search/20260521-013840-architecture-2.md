# Architecture Plan: scip-search Index Lifecycle

Status: review

## Goal

Define how Liza generates and refreshes SCIP indexes at lifecycle boundaries while preserving worktree isolation, clean git status, graceful failure, and project-root orchestrator refresh semantics.

## Context

This slice covers success criteria 13-18 and 22-23 from the goal spec. It consumes the init-time `config.scip_search` allowlist and runtime activation predicate planned by `architecture-1`; it does not cover init validation, agent prompt rendering, README copy, Claude settings, or language capability wording. The lifecycle design places index generation at the same controlled boundaries where Liza already prepares worktrees and prompts: task claim/worktree creation, submit-for-review, and orchestrator execution before prompt construction.

The current system already has deterministic task worktree paths (`internal/git/worktree.go`), claim-time worktree provisioning (`internal/ops/claim_task.go`, `internal/ops/wt_create.go`), submit-time rebase and state transition (`internal/ops/submit_review.go`), reviewer worktree recovery (`internal/agent/worktree_check.go`), role strategies around prompt construction (`internal/agent/strategy_*.go`, `internal/agent/supervisor.go`), and typed config with extra inline YAML fields (`internal/models/config.go`). The plan adds one runtime indexing service and keeps lifecycle call sites small.

### Constraints

- `LIZA_ENABLE_SCIP_SEARCH` plus non-empty `config.scip_search` is the strict runtime activation gate. Lifecycle code must call the shared activation contract from the init/config slice rather than duplicate environment parsing.
- Liza must remain stack-agnostic. Runtime indexing may call configured milestone indexers for detected enabled languages, but must not run Liza-specific build commands or assume the target project has Go tooling.
- Index generation is best-effort. Failure for one enabled language never blocks task claim, submit-for-review, reviewer claim, or orchestrator prompt execution.
- Generated task indexes live under `<worktree>/.liza/scip/`; generated orchestrator indexes live under `<project_root>/.liza/scip/`.
- Task worktree index artifacts must not dirty `git status --porcelain` before review.
- Concurrent task worktrees must not share output directories, mutable temp files, or prompt-visible path state.
- Prompt rendering is out of this task, but lifecycle code must expose successful absolute index paths in a shape the prompt slice can consume without requiring agents to infer locations.
- `.pre-commit-config.yaml` exists on integration `HEAD`; no `bootstrap-precommit` output entry is emitted.

## Components

### Runtime SCIP Indexing Service (new internal package, for example `internal/scipsearch`)

**Responsibility:** Own runtime activation consumption, language detection for an arbitrary repository root, index command selection, index storage paths, ignore setup, command execution, and per-language success/failure results.

**Boundaries:**
- Exposes: `RefreshIndexes(input) result` for a target root, target kind, configured language allowlist, and command-runner seam; `AvailableIndexes(root, allowlist) []IndexRef` for prompt consumers.
- Depends on: the init slice's typed `models.Config.ScipSearch` and activation predicate, fixed argv subprocess execution, git-tracked file detection, filesystem writes under `.liza/scip/`, and a git helper for worktree-local excludes.

**Key decisions:**
- Treat `go`, `typescript`, and `python` as the only milestone runtime languages and preserve deterministic processing order.
- Detect languages in the target root using git-tracked file evidence, matching the goal spec: Go via `go.mod` or `*.go`; TypeScript via `tsconfig.json`, `*.ts`, or `*.tsx`; Python via `pyproject.toml` or `*.py`.
- Attempt only languages that are both detected in the target root and present in `config.scip_search`.
- Generate indexes to `<target>/.liza/scip/<language>.scip` and create parent directories as needed.
- For task worktrees, install a worktree-local ignore rule before or during refresh so `.liza/scip/` does not appear in `git status --porcelain`. The preferred mechanism is a helper that resolves the worktree gitdir with `git -C <worktree> rev-parse --git-path info/exclude` and idempotently appends `.liza/scip/` there; this avoids tracked `.gitignore` changes and avoids creating an untracked ignore file in the worktree.
- Keep project-root indexes under project-root `.liza/scip/`; project-root cleanliness is not the task-worktree review invariant, but the same generated `*.scip` ignore behavior remains compatible with the repository's existing `*.scip` ignore rule.
- Return structured results with absolute index paths for successes and diagnostic strings for failures. Lifecycle callers log failures and pass successes onward; they do not put failure details into agent prompts.
- Invoke indexers with argv arrays and `cmd.Dir`/cwd, not shell strings. Go uses `scip-go` from the module root or with `--module-root <target>`; TypeScript and Python use their milestone indexer commands with explicit output paths and cwd based on the target root unless the code-planner finds a safer package-root convention already supported by the indexer.

### Task Worktree Claim Indexing (`internal/ops/claim_task.go`, `internal/ops/wt_create.go`)

**Responsibility:** Refresh task-local SCIP indexes after worktree provisioning and post-worktree setup, before the supervisor builds the doer prompt.

**Boundaries:**
- Exposes: lifecycle warnings in the existing claim/create result warning channel and successful index files under the task worktree.
- Depends on: Runtime SCIP Indexing Service, existing worktree creation/health checks, and `state.Config`.

**Key decisions:**
- In `ClaimTask`, run index refresh after the worktree exists and after `PostWorktreeCmd` has run. This lets project-scoped setup generate dependencies or embedded files before indexing without hardcoding any stack-specific setup.
- For direct `CreateWorktree`, run the same refresh after Claude config, pre-commit hook setup, and `PostWorktreeCmd`. This preserves the explicit `wt-create` command as a complete worktree preparation operation.
- Existing worktree paths are idempotently refreshed when lifecycle code reuses a healthy worktree, matching the existing post-worktree command upgrade behavior.
- A failed language contributes a warning such as `scip-search <language>: <diagnostic>` and does not fail the claim/create operation.
- The prompt slice later determines what to render by asking for successful existing indexes; if all languages fail or activation is off, no scip-search prompt section is rendered.

### Submit-for-Review Regeneration (`internal/ops/submit_review.go`)

**Responsibility:** Regenerate task-local indexes from the final post-rebase worktree before the task becomes reviewable.

**Boundaries:**
- Exposes: refreshed index files in the same worktree path the reviewer will inspect.
- Depends on: Runtime SCIP Indexing Service, submit-time git validation/rebase flow, and existing state transition semantics.

**Key decisions:**
- Run refresh after the successful rebase and review-boundary validation, and before the atomic transition to the submitted status. This captures the doer's final code as reviewed, while still keeping state unchanged if earlier submit preconditions fail.
- Regeneration is best-effort. Indexer failure does not prevent transition to review; it logs an operator-visible warning and leaves failed languages absent from prompt-available indexes.
- The refresh must not modify tracked source files or change the worktree commit. Tests should assert `git status --porcelain` remains clean after regeneration when no source changes are pending.
- Rebase-conflict handling remains unchanged. If rebase fails, Liza does not refresh indexes because the review candidate is not established.

### Reviewer Worktree Recovery Indexing (`internal/agent/worktree_check.go`)

**Responsibility:** Ensure recovered reviewer worktrees receive the same task-local indexes before a reviewer prompt is built.

**Boundaries:**
- Exposes: regenerated indexes after `AttachWorktree` recovery.
- Depends on: Runtime SCIP Indexing Service and existing reviewer worktree recovery path.

**Key decisions:**
- If the reviewer worktree already exists, no extra reviewer-claim refresh is required because `submit-for-review` is the authoritative regeneration point.
- If the reviewer worktree is missing and successfully recovered from the task branch, run post-worktree setup and then refresh SCIP indexes before recording recovery.
- Recovery indexing failures follow the same warning-only behavior and never turn a recoverable worktree into BLOCKED.

### Orchestrator Project-Root Refresh (`internal/agent/strategy_orchestrator.go`)

**Responsibility:** Refresh project-root SCIP indexes on every orchestrator wakeup before the orchestrator prompt is built.

**Boundaries:**
- Exposes: project-root index files under `<project_root>/.liza/scip/` and successful index refs for prompt rendering.
- Depends on: Runtime SCIP Indexing Service, orchestrator wake detection, and role strategy pre-execution.

**Key decisions:**
- Run project-root refresh in orchestrator `PreExecution`, after wake detection has returned work and before `RunSupervisor` reads state for prompt construction. This places refresh exactly on orchestrator wakeup and keeps prompt building read-oriented.
- Keep existing `setAgentToOrchestratingStatus` behavior and add refresh as warning-only work in the same pre-execution phase.
- Refresh on every orchestrator wakeup, not only on planning-complete checkpoints, so blocked-task, discovery, sprint-complete, and many-to-one wakes all see a current project-root snapshot.
- Project-root indexing failures do not prevent orchestrator execution. If no language succeeds, prompt rendering omits the scip-search section.

### Prompt Index Availability Boundary (`internal/agent/prompt.go`, `internal/prompts`)

**Responsibility:** Provide prompt builders with explicit successful index paths without making agents infer index locations.

**Boundaries:**
- Exposes: an `[]IndexRef` or equivalent prompt data field populated from lifecycle-generated files.
- Depends on: Runtime SCIP Indexing Service's `AvailableIndexes` read-only helper.

**Key decisions:**
- This task defines the boundary but leaves prompt wording and capability-specific rendering to the prompt/documentation slice.
- For task roles, prompt data uses the task worktree root; for orchestrator, prompt data uses the project root.
- Prompt data includes only successful, existing absolute paths. It does not include failed languages or failure diagnostics.

## Interfaces

### Lifecycle Call Sites -> Runtime SCIP Indexing Service

**Contract:** Callers pass project root, target root, target kind (`task-worktree` or `project-root`), configured language allowlist, and activation state. The service returns successes with absolute paths and failures with diagnostics.

**Direction:** `ClaimTask`, `CreateWorktree`, `SubmitForReview`, reviewer recovery, and orchestrator `PreExecution` call the service.

**Invariants:** If activation is false or the allowlist is empty, the service is a no-op. If one language fails, other languages still run. No caller treats indexer failure as a lifecycle-blocking error.

### Runtime SCIP Indexing Service -> Git

**Contract:** The service asks git for tracked files in the target root and, for task worktrees, installs an idempotent ignore rule through the target worktree's gitdir.

**Direction:** Service invokes git helpers or fixed `git -C <target>` argv calls.

**Invariants:** Detection uses tracked files only. Ignore setup must not edit tracked source files and must leave `git status --porcelain` clean.

### Runtime SCIP Indexing Service -> Language Indexers

**Contract:** The service invokes the configured milestone indexer for each selected detected language with an explicit output path under `.liza/scip/`.

**Direction:** Service launches subprocesses with argv arrays and explicit working directory.

**Invariants:** Indexer output never goes to the main checkout for task worktrees. Command stderr/stdout diagnostics are truncated for logs/warnings and never injected into prompts.

### Runtime SCIP Indexing Service -> Prompt Data

**Contract:** Prompt builders can request existing successful index refs for a target root and receive absolute paths plus language identifiers.

**Direction:** Prompt data construction reads generated files after lifecycle refresh.

**Invariants:** Prompt refs are explicit absolute paths; absence means omit prompt section. Prompt consumers do not infer paths from worktree naming conventions.

## Data Flow

Task claim path:

```text

doer supervisor wake
  -> ops.ClaimTask()
  -> git worktree provisioned under <project_root>/.worktrees/<taskID>
  -> Claude config and pre-commit hook setup
  -> optional PostWorktreeCmd
  -> Runtime SCIP Indexing Service refreshes <worktree>/.liza/scip/<language>.scip
  -> ClaimTask returns warnings only for failures
  -> supervisor reads state and builds prompt
  -> prompt slice reads successful absolute task index paths
  -> doer agent spawned
```

Submit-for-review path:

```text

doer runs liza submit-for-review <task> HEAD
  -> submit preconditions and checkpoint/TDD checks
  -> rebase task worktree onto integration HEAD
  -> validate review boundary commit
  -> Runtime SCIP Indexing Service regenerates <worktree>/.liza/scip/<language>.scip
  -> failures logged/warned, not blocking
  -> task transitions to submitted status with review_commit
  -> reviewer supervisor claims task
  -> existing worktree is used, or recovery attaches branch and refreshes indexes
  -> reviewer prompt receives successful absolute task index paths
```

Orchestrator wake path:

```text

orchestrator supervisor detects wake trigger
  -> orchestrator PreExecution sets orchestrating status
  -> Runtime SCIP Indexing Service refreshes <project_root>/.liza/scip/<language>.scip
  -> failures logged/warned, not blocking
  -> supervisor reads state and builds orchestrator prompt
  -> prompt slice reads successful absolute project-root index paths
  -> orchestrator agent spawned
```

Concurrent task isolation:

```text

task-A worktree -> /project/.worktrees/task-A/.liza/scip/go.scip
task-B worktree -> /project/.worktrees/task-B/.liza/scip/go.scip

No shared index path, no shared mutable temp path, no dependency on main checkout indexes.
```

## Cross-Cutting Concerns

| Concern | Approach |
|---------|----------|
| Error handling | Indexing is warning-only after lifecycle preconditions succeed. Per-language failures are isolated; successful languages remain available. Rebase and worktree health errors keep their current blocking behavior. |
| Observability | Lifecycle callers log concise diagnostics and attach warnings to existing result structs where available. Prompt content includes only successes, preserving prompt budget. |
| Configuration | Runtime code consumes `config.scip_search` and the shared `LIZA_ENABLE_SCIP_SEARCH` activation predicate. No indexer commands are stored in task state for this milestone. |
| Testing | Use fake command runners for indexers, git-backed temp repos for cleanliness/isolation tests, and lifecycle unit tests for claim, submit, recovery, and orchestrator pre-execution paths. |
| Security | No credential files are read. External commands use fixed executable names and argv arrays, with user project paths passed as argv elements rather than shell-expanded strings. |
| Concurrency | Each task worktree writes only under its own `<worktree>/.liza/scip/`. Service functions do not use package-level mutable current-target state. Concurrent refreshes for different roots are independent. |
| Stack agnosticism | Detection is language evidence based and indexer-specific. Liza does not assume Makefiles, Go modules outside Go indexing, or Liza repository internals. |
| Git cleanliness | Task index directories are ignored via worktree-local git excludes before file generation. Tests assert `git status --porcelain` is empty after lifecycle refresh. |
