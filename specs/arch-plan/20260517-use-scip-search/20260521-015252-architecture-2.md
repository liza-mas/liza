# Architecture Plan: scip-search Index Lifecycle

Status: review

## Goal

Define the supervisor-side lifecycle architecture that generates task-worktree and project-root SCIP indexes at controlled boundaries while preserving opt-in behavior, worktree isolation, clean task status, graceful failure, and concurrent worktree safety.

## Context

This plan covers success criteria 13-18 and 22-23 from `specs/goals/20260517-use-scip-search.md`. It consumes the init-time config and runtime activation contract planned by `architecture-1`; it does not cover init validation, README copy, Claude settings, prompt wording, or language capability copy.

Liza already centralizes worktree mutations in `internal/ops`, supervisor role flow in `internal/agent`, prompt data assembly in `internal/prompts`, and linked-worktree operations in `internal/git`. The design adds one runtime indexing service and keeps lifecycle call sites thin: task claim/worktree creation, submit-for-review, reviewer worktree recovery, and orchestrator pre-execution.

### Constraints

- `LIZA_ENABLE_SCIP_SEARCH` plus non-empty `config.scip_search` is the strict runtime activation gate. Runtime lifecycle code must call the shared activation contract from `architecture-1` rather than duplicate environment parsing.
- Liza remains stack-agnostic. It may run the milestone language indexers for detected enabled languages, but it must not run Liza-specific build commands or assume Makefiles, Go modules, or project-specific setup outside each language indexer contract.
- Runtime indexing is best-effort after lifecycle preconditions succeed. A failed language must not block task claim, direct worktree creation, submit-for-review, reviewer worktree recovery, or orchestrator execution.
- Task indexes are generated under `<worktree>/.liza/scip/`; project-root orchestrator indexes are generated under `<project_root>/.liza/scip/`.
- Generated task indexes must not dirty `git status --porcelain`.
- Concurrent task worktrees must not share index output directories, mutable package-level target state, or prompt-visible index paths.
- Prompt wording is out of scope, but lifecycle and prompt-data boundaries must expose successful absolute index paths so later prompt rendering never requires agents to infer index locations.
- `.pre-commit-config.yaml` exists at integration `HEAD`; no `bootstrap-precommit` output entry is emitted.

## Components

### Runtime SCIP Indexing Service (`internal/scipsearch` or equivalent)

**Responsibility:** Own runtime activation consumption, target-root language detection, enabled-language filtering, index output paths, task-worktree ignore setup, language indexer execution, structured success/failure results, and read-only available-index discovery.

**Boundaries:**
- Exposes: a refresh interface for a target root and target kind (`task-worktree` or `project-root`), and a read-only available-index query that returns only successful existing absolute paths.
- Depends on: `models.Config.ScipSearch`, the shared activation predicate from the init slice, git-tracked file discovery, fixed argv subprocess execution, filesystem writes under `.liza/scip/`, and a git helper for linked-worktree private exclude files.

**Key decisions:**
- Process milestone languages in deterministic order: `go`, `typescript`, `python`.
- Detect language presence in the target root using `git ls-files` evidence matching the goal spec: Go via `go.mod` or `*.go`; TypeScript via `tsconfig.json`, `*.ts`, or `*.tsx`; Python via `pyproject.toml` or `*.py`.
- Attempt only languages that are both detected in the target root and present in `config.scip_search`, and only when runtime activation is true.
- Write successful outputs to `<target>/.liza/scip/<language>.scip` and create parent directories as needed.
- For task worktrees, install an idempotent ignore entry in the linked worktree's private gitdir exclude file before writing indexes. The service resolves the private gitdir with `git -C <worktree> rev-parse --git-dir`, appends `.liza/scip/` to `<resolved-git-dir>/info/exclude` only when absent, and never edits tracked `.gitignore` or the common repository `.git/info/exclude`.
- For project-root refresh, store indexes under project-root `.liza/scip/`. Project-root cleanliness is not the task review invariant, and the repository already ignores `*.scip`; the service still uses the same output layout for consistency.
- Return structured per-language results: successes include language plus absolute index path; failures include language plus bounded diagnostics for logs/warnings. Failure diagnostics are never prompt content.
- Invoke indexers with fixed argv arrays and explicit working directories, not shell strings. Milestone argv contracts are: `scip-go index --module-root <target-root> --skip-tests --output <index-path>` with `Dir=<target-root>`; `scip-typescript index --cwd <target-root> --output <index-path> <target-root>` with `Dir=<target-root>`; `scip-python index --cwd <target-root> --output <index-path>` with `Dir=<target-root>`.
- If an indexer cannot handle the target root shape, only that language fails for that refresh.

### Task Worktree Creation Indexing (`internal/ops/claim_task.go`, `internal/ops/wt_create.go`)

**Responsibility:** Refresh task-local SCIP indexes after worktree provisioning and setup, before a task doer prompt can be built.

**Boundaries:**
- Exposes: successful files under the task worktree and non-fatal warnings through existing claim/create result warning channels.
- Depends on: Runtime SCIP Indexing Service, existing worktree creation/reuse paths, Claude config provisioning, pre-commit hook setup, optional `PostWorktreeCmd`, and `state.Config`.

**Key decisions:**
- In `ClaimTask`, run refresh after the worktree exists and after optional `PostWorktreeCmd` has run. This lets project-scoped setup prepare dependencies or generated sources without hardcoding stack-specific commands.
- In direct `CreateWorktree`, run refresh after Claude config provisioning, pre-commit hook setup, and optional `PostWorktreeCmd` for both new and existing healthy worktrees.
- Existing worktrees are refreshed idempotently, matching current hook and post-worktree upgrade behavior.
- A failed language contributes a warning such as `scip-search <language>: <diagnostic>` and does not fail claim/create.
- The subsequent prompt data path uses available-index discovery to render only successful files. Disabled activation, empty allowlist, or all-language failure yields no prompt-visible index refs.

### Submit-for-Review Regeneration (`internal/ops/submit_review.go`, `cmd/liza/cmd_review.go`)

**Responsibility:** Regenerate task-local SCIP indexes from the final post-rebase review candidate before the task is made reviewable and reviewer agents can spawn.

**Boundaries:**
- Exposes: refreshed index files in the submitted task worktree and non-fatal warnings on the submit result/JSON response.
- Depends on: Runtime SCIP Indexing Service, submit-time worktree validation, rebase flow, review-boundary validation, and atomic submitted-state transition.

**Key decisions:**
- Run refresh after successful rebase and review-boundary validation, and before the atomic transition to the submitted status. This captures the final review candidate while leaving state unchanged when earlier submit preconditions fail.
- Extend the submit result path with warnings so CLI JSON can surface indexer failures without turning them into errors.
- Regeneration does not alter commits or tracked source. Tests assert the worktree remains `git status --porcelain` clean after regeneration.
- Rebase-conflict handling remains unchanged. If rebase fails, no refresh runs because no review candidate exists.
- Failed language indexes are absent from available-index discovery; successful languages remain available for reviewer prompts.

### Reviewer Worktree Recovery Indexing (`internal/agent/worktree_check.go`)

**Responsibility:** Ensure recovered reviewer worktrees receive task-local SCIP indexes before reviewer prompt construction.

**Boundaries:**
- Exposes: regenerated indexes after a missing reviewer worktree is reattached from the task branch.
- Depends on: Runtime SCIP Indexing Service, existing reviewer worktree recovery, optional `PostWorktreeCmd`, and reviewer claim flow.

**Key decisions:**
- If the reviewer worktree already exists, `submit-for-review` is the authoritative regeneration point and no extra reviewer-claim refresh is required.
- If recovery attaches a missing worktree from the existing task branch, run optional post-worktree setup and then refresh SCIP indexes before recovery is recorded as complete.
- Recovery indexing failures are warning-only and must not turn recoverable reviewer worktrees into BLOCKED tasks.

### Orchestrator Project-Root Refresh (`internal/agent/strategy_orchestrator.go`)

**Responsibility:** Refresh project-root SCIP indexes on every orchestrator wake before prompt construction.

**Boundaries:**
- Exposes: successful project-root index files under `<project_root>/.liza/scip/` and prompt-data refs for those paths.
- Depends on: Runtime SCIP Indexing Service, orchestrator `PreExecution`, and role strategy prompt flow.

**Key decisions:**
- Run project-root refresh in orchestrator `PreExecution` after wake detection has decided there is work and before `RunSupervisor` reads state for prompt construction.
- Keep `setAgentToOrchestratingStatus` as the authoritative status mutation; add refresh as warning-only side work in the same pre-execution phase.
- Refresh on every orchestrator wake, including blocked-task, discovery, sprint-complete, planning-complete, and many-to-one wakes.
- Project-root indexing failures do not prevent orchestrator execution. If no language succeeds, prompt rendering omits the scip-search section.

### Prompt Index Availability Boundary (`internal/agent/prompt.go`, `internal/prompts`)

**Responsibility:** Provide prompt builders with explicit successful index paths while keeping prompt wording and command guidance in the later prompt/documentation slice.

**Boundaries:**
- Exposes: an `[]IndexRef` or equivalent role-context data field containing language and absolute index path.
- Depends on: Runtime SCIP Indexing Service read-only available-index query.

**Key decisions:**
- Task-based roles query the task worktree root; orchestrator roles query the project root.
- Prompt data includes only existing successful absolute paths. It does not include failed languages or failure diagnostics.
- This plan defines the data boundary only; command-loop wording, Python caveat text, and capability-specific prompt rendering remain out of scope for this task.

## Interfaces

### Lifecycle Call Sites -> Runtime SCIP Indexing Service

**Contract:** Callers pass project root, target root, target kind, configured language allowlist, activation state, and a command-runner/logger boundary. The service returns per-language successes and failures.

**Direction:** `ClaimTask`, `CreateWorktree`, `SubmitForReview`, reviewer recovery, and orchestrator `PreExecution` call the service.

**Invariants:** Disabled activation and empty allowlist are no-ops. One language failure does not suppress other languages. No caller treats indexer failure as lifecycle-blocking.

### Runtime SCIP Indexing Service -> Git

**Contract:** The service uses git to enumerate tracked files and, for task worktrees, to resolve the linked worktree private gitdir used for ignore setup.

**Direction:** Service invokes git helpers or fixed `git -C <target>` argv calls.

**Invariants:** Detection uses tracked files only. Ignore setup must not edit tracked source files, tracked `.gitignore`, or the common repository `.git/info/exclude`.

### Runtime SCIP Indexing Service -> Language Indexers

**Contract:** The service invokes the milestone indexer for each selected detected language with an explicit output path under `.liza/scip/`.

**Direction:** Service launches subprocesses with fixed executable names, argv arrays, and explicit working directories.

**Invariants:** Indexer output for task worktrees never goes to the main checkout. Stdout/stderr are bounded in diagnostics and never injected into prompts.

### Runtime SCIP Indexing Service -> Prompt Data

**Contract:** Prompt data construction requests existing successful index refs for a target root and receives language identifiers plus absolute paths.

**Direction:** Prompt data construction reads generated files after lifecycle refresh.

**Invariants:** Prompt refs are explicit absolute paths. Absence means omit prompt section. Prompt consumers do not infer paths from task IDs, worktree names, or default index locations.

## Data Flow

Task claim and direct create path:

```text
doer supervisor wake or liza wt-create
  -> ops.ClaimTask() or ops.CreateWorktree()
  -> task worktree exists under <project_root>/.worktrees/<taskID>
  -> Claude config and pre-commit hook setup
  -> optional PostWorktreeCmd
  -> Runtime SCIP Indexing Service refreshes <worktree>/.liza/scip/<language>.scip
  -> lifecycle returns warnings for failed languages only
  -> supervisor reads state and builds prompt
  -> prompt data reads successful absolute task index paths
  -> doer agent spawned
```

Submit-for-review and reviewer path:

```text
doer runs liza submit-for-review <task> HEAD
  -> submit preconditions and checkpoint/TDD checks
  -> rebase task worktree onto integration HEAD
  -> validate post-rebase review boundary
  -> Runtime SCIP Indexing Service regenerates <worktree>/.liza/scip/<language>.scip
  -> task transitions to submitted status with review_commit
  -> reviewer supervisor claims task
  -> existing worktree is used, or recovery attaches branch and refreshes indexes
  -> reviewer prompt reads successful absolute task index paths
```

Orchestrator wake path:

```text
orchestrator supervisor detects wake trigger
  -> orchestrator PreExecution sets orchestrating status
  -> Runtime SCIP Indexing Service refreshes <project_root>/.liza/scip/<language>.scip
  -> failures logged/warned, not blocking
  -> supervisor reads state and builds orchestrator prompt
  -> prompt data reads successful absolute project-root index paths
  -> orchestrator agent spawned
```

Concurrent task isolation:

```text
task-A worktree -> /project/.worktrees/task-A/.liza/scip/go.scip
task-B worktree -> /project/.worktrees/task-B/.liza/scip/go.scip

No shared index path, no shared mutable target state, no main-checkout fallback.
```

## Cross-Cutting Concerns

| Concern | Approach |
|---------|----------|
| Error handling | Indexing is warning-only after lifecycle preconditions succeed. Per-language failures are isolated; rebase, worktree health, and state-transition errors keep their current blocking behavior. |
| Observability | Claim/create/submit/recovery/orchestrator paths log concise diagnostics and use existing warning channels where available. Prompt content includes only successful indexes. |
| Configuration | Runtime code consumes `config.scip_search` and the shared `LIZA_ENABLE_SCIP_SEARCH` activation predicate. Indexer command names are fixed for the milestone and are not stored in task state. |
| Testing | Use fake command runners for indexers, git-backed temp repos for cleanliness/isolation, and lifecycle tests for claim/create, submit/recovery, and orchestrator pre-execution. |
| Security | No credential files are read. External commands use fixed executable names and argv arrays with project paths as argv elements, not shell-expanded strings. |
| Concurrency | Each refresh writes only under its target root. Service functions do not use package-level mutable target state. Concurrent refreshes for different worktrees use independent output and exclude paths. |
| Stack agnosticism | Detection is git-tracked language evidence based. Liza does not assume Makefiles, Liza repository internals, or project build commands. |
| Git cleanliness | Task index directories are ignored via the private linked-worktree gitdir exclude before generation. Tests assert `git status --porcelain` is empty after refresh. |
