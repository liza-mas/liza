# Circuit Breaker

## Goal

Detect systemic failure patterns from anomalies and planning task review evidence, then escalate to human checkpoints before the system continues unsafe or unproductive execution.

## User Stories

- 1.5.1 (implemented) — As an operator, I want pattern-triggered checkpoint escalation so systemic problems pause normal execution quickly.
- 1.5.2 (planned) — As a maintainer, I want configurable pattern thresholds so sensitivity can be tuned without code changes.
- 1.5.3 (planned) — As a planner, I want trend-based early warnings before hard triggers trip the system.

## Success Criteria

- Circuit-breaker analysis applies deterministic pattern checks and severities to both evidence sources.
- `planning_review_churn` triggers at four or more durable planning rejection cycles with severity `PLANNING_CONVERGENCE_DEGRADED`; `MERGED` tasks remain eligible.
- `blocked_replacement_chain` triggers for a `BLOCKED` task at the agent blocked-recovery cap (two marked recoveries in its lineage), with severity `RECOVERY_CONVERGENCE_DEGRADED`. Its typed `subject` scopes the `resume` release to that task and blocked episode (ADR-0171).
- Triggered patterns generate a human-readable report and transition system mode to `CIRCUIT_BREAKER_TRIPPED`.
- `liza tui` continuously evaluates circuit-breaker evidence and auto-creates sprint `CHECKPOINT` when a trigger fires.
- Non-trigger analyses set circuit-breaker status to `OK`, append history, and clear `CIRCUIT_BREAKER_TRIPPED` mode to `RUNNING`; sprint `CHECKPOINT` (if set) still requires `liza resume`.
- Trigger history records timestamp, pattern, and severity for auditability.
- Aggregate sprint metrics support early warning interpretation (e.g., suspicious approval-rate signals).
